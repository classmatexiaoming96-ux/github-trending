▸enforce_wall_clock — wall-clock 单点守门

这是 runner 对时间预算的唯一硬检查：time.monotonic() - self.started > wall_clock_min * 60 一旦成立就把 status=failed + failure="wall_clock_budget_exceeded" 并 raise RunnerError。检查点在 gather_context / run_host / run_gate / run_reviewers 入口，所以 host 的某次长尾响应会触发，budget 判定也是这一处；host 自身的耗时并不计在内（取决于 wall_clock_min 的取值精度）。

▸no_progress_reached — 同 signature 致死的真正机制

这就是三件套的第三层守门。每次进 gate 都把 sorted(failures) 当 signature 与 state 中 no_progress.signature 比对：同 gate 同样 signature 就 count += 1，否则归零。count 累计到 max_stalled_iterations 默认 2 就停；如果 spec 里 action: human_checkpoint 则只问一次"Type 'continue' to allow one more revision"，问完归零。这个签名级别虽然可能误判（措辞微调就归零），但配合 max_revisions 与 max_iterations 已经足够把 budget 烧穿的两大原因堵住。

 178    def enforce_wall_clock(self) -> None:
 179        budget = self.spec.get("loop_control", {}).get("budget", {})
 180        wall_clock_min = budget.get("wall_clock_min")
 181        if wall_clock_min is None:
 182            return
 183        if time.monotonic() - self.started > float(wall_clock_min) * 60:
 184            self.save_state(status="failed", failure="wall_clock_budget_exceeded")

 188    def no_progress_reached(self, gate_name: str, failures: list[str]) -> bool:
 189        if not failures:
 190            self.save_state(no_progress={"count": 0, "signature": "", "gate": gate_name})
 191            return False
 192        config = self.spec.get("loop_control", {}).get("no_progress", {})
 193        threshold = int(config.get("max_stalled_iterations", 2))
 194        signature = "\n".join(sorted(failures))
 195        previous = self.state.get("no_progress", {})
 196        same_gate = previous.get("gate") == gate_name
 197        same_signature = previous.get("signature") == signature
 198        count = int(previous.get("count", 0)) + 1 if same_gate and same_signature else 1
 199        progress = {
 200            "gate": gate_name,
 201            "signature": signature,
 202            "count": count,
 203            "threshold": threshold,
 204            "updated_at": utc_now(),
 205        }
 206        self.save_state(no_progress=progress)
 207        if count < threshold:
 208            return False
 209        self.append_log("no_progress_detected", gate=gate_name, count=count, failures=failures)
 210        if config.get("action", "stop") == "human_checkpoint":
 211            answer = input("No-progress detected. Type 'continue' to allow one more revision: ").strip().lower()
 212            if answer == "continue":
 213                progress["count"] = 0
 214                self.save_state(no_progress=progress)
 215                self.append_log("no_progress_override", gate=gate_name)
 216                return False
 217        self.save_state(status="failed", failure="no_progress_detected", blocking_issues=failures)
 218        return True

▸redactions_for + redact_prompt_for_member — privacy 一票否决

转译 prompt 之前先 redact。redactions_for(member_id) sources/ksimback-looper/templates/run-loop.py:227-232 从 privacy.egress 里找该 member 的 redact globs；找不到就用 DEFAULT_REDACTIONS = [".env", ".env.*", "secrets/**", "**/*.key"] sources/ksimback-looper/scripts/looper.py:23。redact_prompt_for_member() 先按 glob 抓到 path 列表，再读每个文件内容做字面 .replace()；同时对每个文件按行切，长度 ≥ 8 的 stripped 行再做一遍替换——因为 .env 经常是 OPENAI_API_KEY=sk-... 整行值的形态。文件读失败（BinaryDecodeError）或内容大于 1MB 都跳过，避免秘密被序列化爆栈。

 227    def redactions_for(self, member_id: str) -> list[str]:
 228        redactions: list[str] = []
 229        for entry in self.spec.get("privacy", {}).get("egress", []):
 230            if entry.get("to") == member_id:
 231                redactions.extend(entry.get("redact", []))
 232        return redactions or [".env", ".env.*", "secrets/**", "**/*.key"]
 233
 234    def redact_prompt_for_member(self, member_id: str, prompt: str) -> str:
 235        redactions = self.redactions_for(member_id)
 236        redacted = prompt
 237        for pattern in redactions:
 238            paths = list(self.base_dir.glob(pattern))
 239            if pattern.endswith("/**"):
 240                root = self.base_dir / pattern[:-3]
 241                if root.exists():
 242                    paths.extend(root.rglob("*"))
 243            for path in paths:
 244                if not path.is_file():
 245                    continue
 246                try:
 247                    secret_text = path.read_text(encoding="utf-8")
 248                except UnicodeDecodeError:
 249                    continue
 250                if not secret_text.strip() or len(secret_text) > 1_000_000:
 251                    continue
 252                marker = f"[redacted:{path.relative_to(self.base_dir).as_posix()}]"
 253                redacted = redacted.replace(secret_text, marker)
 254                for line in secret_text.splitlines():
 255                    stripped = line.strip()
 256                    if len(stripped) >= 8:
 257                        redacted = redacted.replace(stripped, marker)
 258        return redacted

run() 是 25 行直白的状态机：save_state("running") → gather_context → 跑 plan → 跑 plan_gate → 进入迭代循环 → 任一交付过 delivery_gate 就 return 0 → 否则 max_iterations 触发就 return 1。注意"max_iterations reached" 是单独一类失败，不进 gate.revisions 也不进 no_progress，逻辑上等价于"用完预算就要停"。

§ 03 · EDGE CASES

边界 / 失败模式

  • judge 输出非 JSON — parse_judge_output 把非 JSON 降级为 REVISE + blocking_issues=["Judge output was not parseable JSON."]，让 no_progress 自然触发；但仍可能浪费预算。
  • no_progress 文本签名错位 — 同样一句 blocking 措辞微调就归零；同一 gate 连续两次 verdict=REVISE 但 blocking_issues 排序不同也会归零。现实里 verbose judge 又尤其容易命中此问题。
  • wall_clock 在 host 子进程退出后检查 — enforce_wall_clock 在调用 前 检查，返回时 host 自身耗时已计入 monotonic，所以下一次进 gate 才能感知超时。如果一次 host call 跨多分钟，会变成"完成后再下一次 gate 才发现"的延迟停机。
  • redact 走文件 glob 不做内容指纹 — 用户把 secret 复制到 process-notes.md，runner 不会拦；只能默认 glob 的 4 类文件。
  • argv list 注入无显式校验 — ensure_argv 只查 "list of str"，不会拦 ["bash", "-c", "..."]。如果 council 成员的 invocation 里塞了一段 shell 脚本，runner 会直接 spawn bash。
  • subprocess.DEVNULL 仅给 run_probe — run_argv 把 stdin 走 prompt 文本（line 87-92），但探测版本时已经埋掉了 stdin，避免误从父进程吃。
  • 缺命令行参数走默认 spec_path — main() 把 loop.resolved.json 默认放在 runner 旁边，是好默认但工作目录不固定时容易找不到文件。
  • fake_judge 用 state 文件计数 — 仅在 tests/ 下有效；真实 CLI 不会按调用次数切 verdict。CI 通过不等于生产可用。
