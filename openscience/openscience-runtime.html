§ 02 · KEY FLOW

关键流程

index.ts middleware → credential env → WebCommand → syncServices budget → Server.listen → openUrl

这个流程的工程价值在于避免首屏 race。backend/cli/src/cli/cmd/web.ts:92 的注释明确说 synced whitelist 被 Config.state 首次请求缓存；如果 backend/cli/src/cli/cmd/web.ts:147 先启动 server，浏览器可能看到上一轮模型目录。退出阶段也没有忘：backend/cli/src/cli/cmd/web.ts:164 等 SIGINT/SIGTERM，backend/cli/src/cli/cmd/web.ts:173 用 watchdog 防止 SSE 长连接卡死退出。

▸为什么这样拆

这个子模块的拆法不是按文件大小，而是按运行时责任边界来切。主页面已经把 backend/cli/src/index.ts:55、backend/cli/src/config/config.ts:75、backend/cli/src/provider/provider.ts:57、backend/cli/src/science/connectors/types.ts:76 和 tooling/plugin/src/index.ts:148 串成整体；子页面只展开其中一个闭环，避免把所有源码证据挤成行号清单。

§ 03 · EDGE CASES

边界 / 失败模式

  • 如果 syncServices 很慢，backend/cli/src/cli/cmd/web.ts:127 选择继续启动，风险是模型 picker 稍后刷新而不是阻断。
  • macOS TCC 检测在 backend/cli/src/cli/cmd/web.ts:17 使用 Desktop 读目录作为信号，空 Desktop 也被当成可能阻塞。
  • 顶层 finally 在 backend/cli/src/index.ts:198 到 backend/cli/src/index.ts:202 强制退出，避免 MCP 子进程挂住。
