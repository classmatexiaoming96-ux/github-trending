§ 02 · KEY FLOW

关键流程

Plugin package → Hooks → chat/tool/permission interception Science artifact → renderer registry → inline workspace view

扩展系统的优点是两端都很薄。插件只需要返回 Hooks，见 tooling/plugin/src/index.ts:35；renderer 只需要注册 kind 和 component，见 frontend/workspace/src/science/renderers/registry.ts:43。与此相对，配置层会从 `.openscience` 目录加载插件，证据在 backend/cli/src/config/config.ts:166、backend/cli/src/config/config.ts:178、backend/cli/src/config/config.ts:185，所以插件目录的信任边界必须清楚。

▸为什么这样拆

这个子模块的拆法不是按文件大小，而是按运行时责任边界来切。主页面已经把 backend/cli/src/index.ts:55、backend/cli/src/config/config.ts:75、backend/cli/src/provider/provider.ts:57、backend/cli/src/science/connectors/types.ts:76 和 tooling/plugin/src/index.ts:148 串成整体；子页面只展开其中一个闭环，避免把所有源码证据挤成行号清单。

§ 03 · EDGE CASES

边界 / 失败模式

  • Hooks 可改 tool args，tooling/plugin/src/index.ts:184 的能力很强，应该配合权限策略使用。
  • Renderer registry 接受 string 扩展 kind，frontend/workspace/src/science/renderers/registry.ts:23 灵活但也需要命名约定。
  • 配置加载会自动安装依赖，backend/cli/src/config/config.ts:272 和 backend/cli/src/config/config.ts:281 需要可信插件源。
