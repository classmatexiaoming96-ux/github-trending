§ 00 · Source-level Observatory

northcinder 买家侧 Agent 商务防线

NorthCinder 不是把购物流程交给一个会点击网页的模型，而是把搜索、排序、信任信号、人工确认、签名 mandate 与 checkout rail 拆成多个互相制衡的源码边界。本页只看代码：本地 MCP server 在 client/src/server.ts:339 建立搜索入口，远端 bridge 在 remote/src/mcp-server.ts:123 刻意保持只读，授权存储在 client/src/authorization.ts:299 生成一次性确认码，真正 checkout 则由 packages/checkout/src/orchestrator.ts:101 的 mandate 硬门控制。

§ 00 · OVERVIEW

它解决什么，凭什么值得拆

这个仓库的核心价值在于把“Agent 能买东西”改写成“Agent 只能请求、解释和执行被验证过的购买尝试”。搜索工具在 client/src/server.ts:339 后会把服务端排序结果重新校验，client/src/server.ts:426 记录 rankingVerified 与 coverage，浏览器观察结果从 client/src/server.ts:572 进入但在 client/src/server.ts:1323 被拒绝直接授权，人工授权工具从 client/src/server.ts:1244 开始，把 confirmation code 放到本地渠道而非 MCP 返回值。这让模型可以推荐和解释，但不能仅凭一次搜索结果绕过用户确认。

更值得拆的是它的失败语义：client/src/server.ts:1338 拒绝跨币种 shipping，client/src/server.ts:1351 校验 cap 与 offer total，client/src/server.ts:1541 拒绝 pending authorization，client/src/server.ts:1568 在 checkout 中标记执行中，而 packages/checkout/src/orchestrator.ts:123 对 mandate verification 失败只返回结构化错误。审计层在 client/src/audit-log.ts:57 以 append-only JSONL 落盘，订单图在 packages/orders/src/store.ts:136 保留无法解析邮件，整体设计偏向可追责而不是自动化炫技。

§ 01 · ARCHITECTURE

架构边界：本地可买，远端只读

源码把本地 server 与 remote bridge 分得很清楚。client/src/server.ts:1 的注释定义本地 MCP server 覆盖 search/ranking/auth/checkout/audit，而 remote/src/mcp-server.ts:1 明确 remote bridge 只有 search 和 trust 两个只读工具。服务端搜索返回后，本地在 client/src/server.ts:285 追加本地历史证据但不影响排序，在 client/src/server.ts:403 把 ranking tamper warning 写进 brief。这条边界避免了把购买权限暴露给远端 API key 持有人。

▸系统拓扑

local MCP host -> client/src/server.ts search_products -> service/src/orchestrator/orchestrator.ts rank/search -> client/src/server.ts verifies ranking + coverage -> request_purchase_authorization -> local code file -> approve_purchase -> signed PurchaseMandate -> complete_checkout -> checkout orchestrator -> rail remote MCP bridge -> remote/src/mcp-server.ts search_products / get_trust_signal only -> no authorization, no checkout, no watches, no profile, no orders

§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

风险主要不是“代码没有防线”，而是工程集成时容易误解这些防线。client/src/checkout-wiring.ts:57 只有配置 ACP merchants 才启用 ACP rail，client/src/checkout-wiring.ts:73 默认还会加入 cart-permalink handoff；client/src/server.ts:1512 说明一个 mandate 只授权一次尝试。如果宿主 Agent UI 没有清晰呈现 pending/approved/declined 状态，安全语义会被用户体验稀释。

体验依赖宿主
