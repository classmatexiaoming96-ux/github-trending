§ 00 · OVERVIEW

它解决什么，凭什么值得拆

Agentsmith 的核心抽象不是“提示词更长”，而是把 agent 工作方式拆成可装配的静态规则、按任务切换的 profile、项目本地 verify gate 和提交前 hook。比如软件开发 profile 在 profiles/software-dev.md:11、profiles/software-dev.md:15、profiles/software-dev.md:46 明确要求先读代码、再用完整 verify 命令收口；通用原则在 core/20-principle-rules.md:13、core/20-principle-rules.md:23、core/20-principle-rules.md:35 把证据、端到端验证和完成前检查写成硬规则。

这套仓库值得拆，是因为它没有把“agent 应该谨慎”停留在口号。安全面由 scripts/secret-scan.sh:21、scripts/leak-gate.sh:73、scripts/install-git-hooks.sh:56 变成可执行检查；协作面由 core/10-operating-model.md:9、core/10-operating-model.md:49、core/40-subagents-and-tools.md:14 约束什么时候自主推进、什么时候暂停、什么时候并行。换句话说，它把模型外部的 90% 工作纪律做成了仓库结构。

§ 01 · ARCHITECTURE

装配拓扑

源码拓扑可以分成三层：规则材料在 core/ 和 profiles/，装配器把它们写入项目，验证层再检查输出是否可信。core/10-operating-model.md:4、core/20-principle-rules.md:31、profiles/software-dev.md:8 负责定义“如何工作”，而 scripts/verify.sh:58、scripts/secret-scan.sh:65、scripts/leak-gate.sh:75 负责让这些要求可以被机器执行。

35write_hook() {  # <hookname> <body> — managed write w/ foreign-backup; empty body removes a stale managed hook
36  local name="$1" body="$2" f="$HOOKS_DIR/$1" marker="agentsmith $1"
37  # legacy pre-rebrand marker: still recognized as "ours" so old hooks migrate in place, never written
38  local legacy_marker="universal-claude-harness $1"
39  if [ -z "$body" ]; then
40    if [ -f "$f" ] && grep -q -e "$marker" -e "$legacy_marker" "$f"; then
41      rm -f "$f"; echo "  removed managed $name (not selected)"
42    fi
43    return 0   # bare 'return' would propagate the failed test above and kill the set -e script
44  fi
45  [ -f "$f" ] && ! grep -q -e "$marker" -e "$legacy_marker" "$f" && { cp "$f" "$f.bak.$$"; echo "  backed up foreign $name → $name.bak.$$"; }
46  {
47    echo "#!/usr/bin/env bash"
48    echo "# $marker — regenerate via scripts/install-git-hooks.sh. Bypass once: --no-verify"
49    echo "set -e"
50    echo 'ROOT="$(git rev-parse --show-toplevel)"'
51    printf '%s\n' "$body"
52  } > "$f"
53  chmod +x "$f"; echo "  installed $name"

▸secret-scan / leak-gate 双门禁覆盖凭据和环境泄漏

Agentsmith 把安全拆成两个不同问题：`secret-scan` 看密钥形状，`leak-gate` 看人员、IP、邮箱和 home path 等环境特征。scripts/secret-scan.sh:20、scripts/secret-scan.sh:37、scripts/secret-scan.sh:77、scripts/leak-gate.sh:73、scripts/leak-gate.sh:121 共同形成“可快速跑、可在 hook 里跑、可用测试证明”的安全网。

21PATTERNS=(
22  'BEGIN [A-Z ]*PRIVATE KEY'                            # PEM private keys (RSA/OPENSSH/EC/bare/ENCRYPTED)
23  'AKIA[0-9A-Z]{16}'                                    # AWS access key id
24  'ASIA[0-9A-Z]{16}'                                    # AWS temp key id
25  'gh[pousr]_[A-Za-z0-9]{20,}'                          # GitHub tokens
26  'xox[baprs]-[A-Za-z0-9-]{10,}'                        # Slack tokens
27  'sk-[A-Za-z0-9]{20,}'                                 # OpenAI-style keys
28  'sk-ant-[A-Za-z0-9_-]{20,}'                           # Anthropic-style keys
29  'AIza[0-9A-Za-z_-]{35}'                               # Google API key
30  '(password|passwd|pwd|secret|token|api[_-]?key)["'"'"' ]*[:=][[:space:]]*["'"'"'][^"'"'"' ]{8,}'  # assigned secret literal

32
33# Patterns go to a temp file so the whole scan is ONE grep pass (-f ORs every line of the file).
34# Matching per-line in a shell loop costs a subprocess per line per pattern — imperceptible on
35# Linux (~1ms spawns), minutes on Windows/Git Bash (~30ms). This script runs as a pre-commit
36# hook, and a hook slow enough to be disabled is a guardrail that isn't there (R8).
37PATTERN_FILE="$(mktemp)"
38trap 'rm -f "$PATTERN_FILE"' EXIT
39printf '%s\n' "${PATTERNS[@]}" > "$PATTERN_FILE"

74# Findings print as file:line:match, so <exempt-regex> can anchor on the match with $.
75check() {
76  local label="$1" ere="$2" exempt="$3" hint="$4" hits line
77  # -I skips binaries; -o prints just the match so exemptions test the match, not the whole
78  # line (a line holding both a safe and an unsafe value must still fail).
79  # `|| true` absorbs grep's exit-1-on-no-match, which pipefail would treat as a hard error.
80  hits="$(git grep -noIiE -- "$ere" -- . "${SCOPE[@]+"${SCOPE[@]}"}" 2>/dev/null || true)"
81  [ -n "$hits" ] || return 0
82  if [ -n "$exempt" ]; then
83    hits="$(printf '%s\n' "$hits" | grep -Evi "$exempt" || true)"
84    [ -n "$hits" ] || return 0
85  fi
86  hits="$(printf '%s\n' "$hits" | allow_filter || true)"
87  [ -n "$hits" ] || return 0
88  echo "  ✗ $label — $hint"
89  while IFS= read -r line; do
90    echo "      $line"
91  done <<<"$hits"
92  fail=1
93}

▸已知边界 / 失败模式

  • 如果 `.harness/verify.conf` 没有真实阶段，`scripts/verify.sh:52` 会直接提示缺配置；但配置里有占位阶段时，还需要 profile 约束和测试去防止“假绿色”。
  • `scripts/secret-scan.sh:30` 用正则匹配 secret 形状，低误报和漏报之间必须持续调参，测试脚本要覆盖真实开发语言中的安全样例。
  • `scripts/leak-gate.sh:31` 明确不做通用 hostname denylist，因为把内部域名写进公开仓库本身就是泄漏；这是安全模型里的有意识取舍。
  • `core/40-subagents-and-tools.md:50` 把重复失败定义为停止信号，但实际执行仍依赖 agent 读懂并遵守，所以 verify gate 不能替代运行时判断。

13**2. Prove it — evidence before assertion.** Never claim something works, is fixed, or is
14correct without *evidence you actually produced*. For a bug, that means a check that **failed
15before your change and passes after** (a failing test, a reproduced error, a before/after
16screenshot, a diffed output). "It works in my head" / "it should be fine" / "this looks right"
17are not evidence. Two kinds of proof, and most real work needs both: **tests** for the
18deterministic parts (this input produces that output) and **evaluation** for the parts that
19require judgment (did it take the right approach, is the quality bar met) — a rubric, a second
20independent reviewer (human or an adversarial AI pass), a real run observed. The profile defines
21what counts as proof for this kind of work.
22
23**3. Verify the whole chain, not just your layer.** Work usually flows across layers (code →
24API → UI; source → draft → rendered doc; raw data → transform → chart; list → message → send).
25A change that's correct in one layer can be wrong by the time it reaches the end. Before
26declaring done, **trace one concrete example end-to-end** and confirm it lands correctly at the
27last layer the user actually sees. When a change fans out to many consumers (several pages,
28recipients, locales, output formats), check *every* consumer — "one of them works" does not
29satisfy this rule.
§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

风险主要来自脚本化 harness 的双刃剑：它能统一行为，也可能把错误规则统一扩散。core/20-principle-rules.md:78、scripts/install-git-hooks.sh:45、scripts/verify.sh:87 都体现了这个取舍：表面积要小，外部 hook 要备份，执行命令要读输出。

root setup.sh 很大
安装器超过千行，wizard、global install、self-update、profile 装配和 plugin 安装全在一个文件里；长期最好拆出更细的库函数和测试边界。
bash -c 执行阶段需要信任配置
`scripts/verify.sh:87` 直接执行 verify.conf 里的命令，符合“项目自己定义 shippable”，但也意味着配置审查非常重要。
scanner 是高信号，不是形式化证明
scripts/secret-scan.sh:20、scripts/leak-gate.sh:31 说明扫描器选择高信号规则，不能替代 secret manager、历史清理和人工审查。
跨工具行为仍依赖 agent 遵守
core/40-subagents-and-tools.md:18、core/40-subagents-and-tools.md:50 写了 subagent 和失败恢复纪律，但不同 agent 对规则遵守程度不同，真实项目仍要靠验证命令兜底。
