一句话定位：当一个团队同时用 Claude Code、Cursor 和 Copilot 写前端，最大的问题是一致性——每个 agent 按自己的理解写代码，目录结构/naming/state 管理逐渐分化。AlignDev 把团队约定转成机器可读的文件，让每个 agent 都从同一份契约出发。

问题：AI coding 的碎片化

README 直白地描述了这个痛点：

"When teams use Claude Code, Cursor, Copilot, Windsurf, and other AI agents at the same time, the biggest pain point is consistency: each agent writes code based on its own interpretation, so directory structure, naming, state management, and UI style drift apart."

AlignDev 的解法不是"限制 agent"，而是给 agent 一份它能读懂并遵守的约定文档。

7 步可视化向导

用户通过 Next.js 前端填写 7 个配置维度，后端生成两份文件：

文档生成器：lib/document-generator.ts

lib/document-generator.ts 是核心——一个纯函数，把 WizardState 变成完整 Markdown 文档。分段函数设计非常清晰：

  • s1Overview()：技术栈总览表格（框架/语言/包管理器/构建工具/组件库/CSS/状态/Data fetching/i18n）
  • s2TechStack()：版本锁定策略（package.json engines + devDeps）、构建工具配置、依赖管理规则
  • s3Directory()：根据 framework + dirPattern 动态生成目录树（monorepo / SSR feature / SSR layer / SPA feature / SPA layer）
  • s4Naming()：命名规则对照表（文件/组件/Hook/工具函数/常量/TS 类型/Enum/CSS）
  • s5Components()：组件开发规范（含 Next.js Server/Client Component 决策表）
lib/document-generator.ts — WizardState → Markdown 文档
// WizardState 包含 7 个 step 的所有用户选择
interface WizardState {
  framework: 'nextjs' | 'react-spa' | 'vue' | 'nuxt' | 'svelte'
  language: 'typescript' | 'javascript'
  pkgMgr:       'npm' | 'yarn' | 'pnpm' | 'bun'
  buildTool:   'vite' | 'rollup' | 'webpack' | 'none'
  componentLib: 'shadcn' | 'antd' | 'mui' | 'chakra' | 'none' ...
  cssSolution: 'tailwind' | 'css-modules' | 'styled-components' | 'scss'
  globalState: 'zustand' | 'redux-toolkit' | 'jotai' | 'context-api' | 'pinia' ...
  serverState: 'tanstack-query' | 'swr' | 'nuxt-built-in' ...
  i18n:        'next-intl' | 'i18next' | 'vue-i18n' | 'none'
  dirPattern: 'feature-based' | 'layer-based' | 'monorepo'
  dirDepth:    3 | 4 | 5
  fileNaming: 'kebab-case' | 'camelCase'
  linter:     'eslint' | 'biome' | 'none'
  testing:   string[]   // 'vitest' | 'jest' | 'playwright' ...
}

SKILL.md 生成器：lib/skill-generator.ts

lib/skill-generator.ts 把同样的 WizardState 变成一份 agent 可读的 SKILL.md 文件：

  • description：从 stack 组合里生成 human-readable 描述
  • commands：基于 linter/toolchain 选择生成 lint/typecheck/test 命令
  • checklist：7–10 条合规检查项，根据用户选择的 stack 定制
  • 输出是标准 SKILL.md YAML frontmatter 格式，兼容 Claude Code 的 skill 加载机制
lib/skill-generator.ts — generateSkill 函数
export function generateSkill(s: WizardState, v: VersionMap = {}) : string {
  _v = { ...FALLBACK_VERSIONS, ...v }

  // 基于 stack 组合生成 lint 命令
  const lintCmd = s.linter === 'biome'
    ? `\${px} @biomejs/biome check --apply .`
    : `\${pm} lint`
  const typecheckCmd = isTS ? `\${px} tsc --noEmit` : null

  // 合规检查清单（根据 stack 动态生成）
  const checklist = [
    'Component naming follows the standard.',
    'Folder structure follows the standard.',
    isTS ? 'TypeScript types are explicit — no `any`.' : 'JSDoc types are documented.',
    `State management (\${stateLabel(s.globalState)}) follows the standard.`,
    `Styling (\${cssLabel(s.cssSolution)}) follows the standard.`,
    'Error / loading / empty states are handled.',
    'No unnecessary dependencies are added.',
    ...(s.i18n !== 'none' ? ['All user-facing strings go through the i18n layer.'] : []),
    ...(s.testing.length > 0 ? ['New logic has corresponding unit tests.'] : []),
  ]

  // 输出标准 SKILL.md YAML frontmatter 格式
  return `---\nname: \${fwShort(s.framework)}-frontend-align\ndescription: Frontend alignment skill for \${fwLabel(s.framework)} project\n...\n---\n\n# \${fwLabel(s.framework)} Frontend Alignment Skill\n\n## Compliance Checklist\n\${checklist.map(c => `- ${c}`).join('\n')}`
}

实时版本查询：lib/pkg-versions.ts

一个有意思的工程细节：lib/pkg-versions.ts 实现了实时从 npm registry API 获取最新主版本号的能力，而不是硬编码版本。这让生成的文档始终引用当前最新版本：

  • FALLBACK_VERSIONS：硬编码的 fallback，当 API 不可用时使用
  • Live query：从 registry.npmjs.org/<package>/latest 获取当前 latest 版本
  • 用于生成 "next": "^16.x" 这样的 semver 范围
两个输出物的协同：frontend-align.md（人读）+ SKILL.md（机器读）形成完整的约定体系。前者用于人类 code review，后者放入仓库根目录让 Claude Code 等 agent 自动加载。这种"人机双读"的设计是 AlignDev 区别于纯文档工具的关键。

对 coding agent 生态的意义

AlignDev 解决的是"多个 coding agent 在同一个代码库里产生不一致代码"的问题。这是 multi-agent 协作的第一个实际痛点——不是 agent 和 agent 之间打架，而是agent 和 agent 之间各自为政。

它的价值在于把团队共识转成一份 agent 能加载的契约——这不是一个全新的想法（CLAUDE.md 早就存在），但它把这个过程可视化、流程化了，让非技术团队成员也能参与生成这份契约。

与 guard-skills 的关系：guard-skills 是"代码写完后检查"，AlignDev 是"代码写之前约定"。两者结合是完整的前端质量方案：约定（AlignDev）→ 执行（Claude Code 等）→ 验证（guard-skills）。
