WizardState 数据模型

源码：types/wizard.ts。WizardState 是整个 align-dev 的核心数据类型，定义前端项目的完整配置选项——通过 7 个步骤填写，最终驱动两个生成器。

7 个步骤 · STEP_LABELS

Step 1 Core Stack — 框架 / 语言 / 包管理器 / 构建工具 Step 2 UI & Styles — 组件库 / CSS 方案 / 图标 Step 3 State Management — 全局状态 / 服务器状态 / i18n / 文字方向 Step 4 Toolchain — lint / format / pre-commit / 测试 / CI Step 5 Directory — 结构模式 / 深度 / 命名 case Step 6 Naming & Code — 文件命名 / 导入顺序 / 导出模式 Step 7 Design Tokens — 主题 / 颜色 / 间距 / 字体
一致性是核心痛点：当团队同时用 Claude Code、Cursor、Copilot、Windsurf 写前端，每个 agent 按自己的理解写代码，目录结构 / naming / state 管理逐渐分化。AlignDev 把团队约定固化成 WizardState 这一份机器可读契约，让每个 agent 都从同一起点出发。
02
generator · markdown for humans

document-generator.ts 分段函数

源码：lib/document-generator.ts。一个纯函数把 WizardState 变成完整 Markdown 规范文档，由 13 个分段函数（s1–s13）拼装而成。

核心机制 · 模块级版本状态

文件用模块级变量 _v: VersionMap 存储实时版本，通过 mv() / pd() 在生成文档时插入版本信息——避免在每个分段函数之间反复传参。

lib/document-generator.ts · 版本辅助
// 用常量避免在模板字符串里转义反引号
const B = '`'
const FENCE = B + B + B  // 代码块标记 ```

let _v: VersionMap = {}

// 获取包的实时版本，失败时回退
const mv = (pkg: string, fb: string): string => _v[pkg] ?? FALLBACK_VERSIONS[pkg] ?? fb

// 格式化为 package.json 依赖条目
const pd = (pkg: string, fb: string): string => `"${pkg}": "^${mv(pkg, fb)}.x"`

主入口 · generateDocument

lib/document-generator.ts · generateDocument
export function generateDocument(s: WizardState, v: VersionMap = {}): string {
  // 注入实时版本，使 mv()/pd()/标签辅助函数能取到最新版本
  _v = { ...FALLBACK_VERSIONS, ...v }

  const sections = [
    s1Overview(s),       s2TechStack(s),  s3Directory(s),
    s4Naming(s),         s5Components(s), s6StateManagement(s),
    s7Styles(s),         s8Toolchain(s),  s9Testing(s),
    s10DesignTokens(s),  s11Git(s),       s12CICD(s),
    s13I18n(s),
  ].filter((sec): sec is string => sec !== null)  // s13I18n 对 i18n='none' 返回 null

  _v = {}  // 生成后重置
  return sections.join('\n\n---\n\n')
}
纯函数 + 模块级状态：generateDocument 统一注入版本、跑完 13 段、再重置 _v——既享受模块级变量「不用层层传参」的便利，又用「用后即清」保持纯函数的可重入性。

fetchVersions · 实时获取

lib/pkg-versions.ts · fetchVersions
export async function fetchVersions(): Promise<VersionMap> {
  try {
    const res = await fetch('/api/versions', { cache: 'no-store' })
    if (!res.ok) return FALLBACK_VERSIONS
    const data = await res.json() as VersionMap
    // 合并：API 结果优先，回退版本填补空缺
    return { ...FALLBACK_VERSIONS, ...data }
  } catch {
    return FALLBACK_VERSIONS
  }
}

该函数从 Next.js API 路由 /api/versions 获取最新版本，任何失败都回退到 FALLBACK_VERSIONS。合并逻辑 { ...FALLBACK_VERSIONS, ...v } 确保：所有已知包都有合理回退、API 实时版本能覆盖、未返回的包仍用回退。

链式回退保护：所有版本查询走 _v[pkg] ?? FALLBACK_VERSIONS[pkg] ?? fb 三级回退——文档生成绝不因版本获取失败而中断。

07
patterns · the why

关键设计模式

AlignDev 的工程取舍，以及它在 coding agent 生态里的定位。

模块级状态

版本状态模块化

用模块级变量 _v 避免在每个分段函数间传递版本参数，generateDocument 统一注入、生成后重置。

条件生成

条件化内容生成

各分段函数按 WizardState 字段值有条件返回内容（如 i18n='none' 时整节跳过）。

回退机制

版本回退保护

所有版本查询走 ?? FALLBACK_VERSIONS[pkg] ?? fb 链式回退，确保生成不中断。

模板模式

分段函数模板

13 个 s*N 函数各负责一章，最后 filter + join 组合成完整文档。

生态定位：AlignDev 解决的不是「agent 和 agent 打架」，而是「agent 和 agent 各自为政」——多个 coding agent 在同一代码库产生不一致代码。它把团队共识转成 agent 能加载的契约：约定（AlignDev）→ 执行（Claude Code 等）→ 验证（guard-skills），三段合起来才是完整的前端质量方案。它的创新不在「想法」（CLAUDE.md 早就存在），而在把这个过程可视化、流程化，让非技术成员也能参与生成契约。
