§ 00 · OVERVIEW

它解决什么，为什么值得拆

book-to-skill 的定位很清楚：把 PDF、EPUB、DOCX、HTML、RTF、纯文本或一个目录里的多份资料合并成 agent 可消费的 skill 原料。入口不是一个复杂框架，而是 book_to_skill/cli.py:483 到 book_to_skill/cli.py:512 的薄 CLI 分发；真正的抽取和汇总落在 book_to_skill/utils.py:414 之后。源码里可以看到，命令先统一 argv，再把 install/list/ui/readme/help 和转换路径拆开，因此它更像一个带安装器的文档抽取器，而不是完整 skill authoring IDE。

最核心的设计是“多解析器 fallback + 单一结构化输出”。sources/book-to-skill/book_to_skill/utils.py:250 先判断文件是否存在，sources/book-to-skill/book_to_skill/utils.py:256 校验扩展名，sources/book-to-skill/book_to_skill/utils.py:281 触发依赖准备，随后各格式进入不同分支。这个分支最后都汇入 sources/book-to-skill/book_to_skill/utils.py:378 的 Unicode 清洗、sources/book-to-skill/book_to_skill/utils.py:383 的 token 估算和 sources/book-to-skill/book_to_skill/utils.py:384 的结构识别。

▸核心数据

架构模式
CLI façade + parser fallback chain + consolidated output writer。
核心抽象
每个 source 被规范化成包含 text、format、method、pages、tokens、chapters 的 dict。
质量信号
测试覆盖 EPUB OPF 路径、批处理韧性、Unicode 隐形字符、输出目录权限和生成 skill 扫描。
风险信号
CLI 启动阶段存在 beacon、运行时状态同步和 Windows UI 自动启动逻辑，需要用户显式审查。
跳过记录 — SaladDay/pi-from-scratch 已在上一期收录；airship、dsh-TUI、codex-bridge、moli 和 rakazo 今天不选，是因为本项目星数最高且源码里有完整解析、扫描和安全边界可拆。
