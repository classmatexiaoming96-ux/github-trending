▸pending job 如何避免半批次执行

§ 02 · KEY FLOW

关键流程

POST /api/scans -> Scan row -> build_pending_jobs -> claim metadata -> prepare workspace -> render prompt -> harness.run -> validate payload -> write step result

流程中的关键转折是没有 pending jobs 且 claimed==completed 时才进入 post_processing；这避免了并发 worker 把未完成分支当作完整结果。backend/src/routes/scans.js:204 暴露列表状态，backend/src/routes/scans.js:468 允许合法状态更新，frontend/src/pages/ScanDetail.jsx:103 触发状态变更，frontend/src/pages/ScanDetail.jsx:116 保存运行设置。

§ 03 · EDGE CASES

边界 / 失败模式

  • backend/src/routes/scans.js:300 会根据活跃扫描要求用户选择 queue，避免默认并发冲突。
  • frontend/src/pages/ScanDetail.jsx:31 到 frontend/src/pages/ScanDetail.jsx:38 只在合适状态开放 pause/resume/stop/delete。
  • backend/test/validation.test.js:97 覆盖不同 thinking effort 的模型选择，降低 harness 参数漂移。

▸调度证据补充

这条链路还可以从前后端交界验证：backend/src/routes/scans.js:204 提供 scan 列表状态，backend/src/routes/scans.js:468 接受运行时 PATCH，frontend/src/pages/ScanDetail.jsx:103 发起状态变更，frontend/src/pages/ScanDetail.jsx:116 保存模型与 harness 设置。它们共同说明 engine 不是孤立进程，而是受 API 状态机和 UI 操作约束。
