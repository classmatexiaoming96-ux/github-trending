一句话定位：为 Hermes Agent 量身定制的"记忆操作系统"——七层互补的记忆结构，加上一个关键补丁：Ground Truth 层级，确保注入的记忆被 agent 真正使用，而不是视若无睹地重复探索。

"你的 agent 终于不会再忘记了。" — 项目 README 的开场白，也是它解决的核心问题：每次新会话 agent 都像第一次见面，即使上一会话注入过记忆。

核心问题：为什么记忆注入会失效？

这是项目最重要的 insight（Layer 7 文档）。Memory OS 把上下文注入到了 prompt 里——[qdrant]、[fabric]、[sessions]、[facts] 都在，但 agent 仍然去重发现——因为 SOUL.md 和 rulebook.md 的 Ground Truth 层级里根本没有"注入记忆"的位置。记忆没有地位，所以被忽略。

Layer 7：Ground Truth 层级 — 最关键的一层

这是项目的核心贡献。大多数记忆系统只解决"记忆如何存储和检索"，从来不解决"agent 为什么不使用检索到的记忆"。Layer 7 用一个四层权威层级明确回答了这个问题：

layers/07-ground-truth.md — 四层权威层级
# 扩展后的 Ground Truth 层级（SOUL.md + rulebook.md）
# 1. Terminal output        → Ground Truth（系统状态）
# 2. Injected memory        → Ground Truth（文档化知识与历史决策）  ← 关键补丁
# 3. Official documentation → Authoritative（API、配置、版本细节）
# 4. Training knowledge      → Reference only（永远用 1-3 验证）

# 冲突解决规则：
# - Terminal vs Injected memory → Terminal 胜（系统状态）；Injected 胜（项目上下文）
# - Injected memory vs Assumptions → Injected memory 胜，不要把问题当新的
# - Training knowledge vs 任何 → Training knowledge 永远输

Layer 3：Structured Facts 与信任评分

memory_store.db 存储带实体解析和信任评分的结构化事实，支持 fact_store 工具的 6 种操作（add / search / probe / reason / contradict / update）和 fact_feedback 的 helpful/unhelpful 打分。信任分用贝叶斯先验（从 0.50 开始）计算，检索次数越多、helpful 标记越多，trust_score 越高。关键约束：每次引用 fact 后必须调用 fact_feedback，否则 trust_score 永远停在 0.50。

Layer 5：Qdrant 向量库与 4 级回退链

4096 维 Cosine + BM25 稀疏混合检索。embedding 用 Qwen3-Embedding-8B（通过 OpenRouter，$0.025/1M tokens）。关键设计：5 级回退链，任何一层失败都自动降到下一级：

  • Hybrid：dense + sparse → RRF 融合排序
  • Dense-only：sparse 失败时纯向量搜索
  • Lexical：Qdrant 离线时搜 vault 里 markdown 文件
  • SQLite：vault 也不可用时搜 lineage 表关键词
  • None：全部失败 → 返回空（fail-open）

每周还有 decay scanner 扫描低重要性、高年龄的 AI 生成内容并归档；semantic dedup 用 cosine > 0.92 阈值合并语义重复的点。

Layer 4：Icarus Fabric Fork

在原版 Icarus 基础上做了大量 fork：hooks.py 在 pre_llm_call 时做四路召回（Fabric + Qdrant + Sessions + Facts），在 post_llm_call 和 on_session_end 时触发自动提取。16 个工具：fabric_recall / fabric_write / fabric_brief / fabric_compare / fabric_summarize 等。

Docker 基础设施

三个容器协同（docker-compose.yml）：

  • Qdrant v1.17.1：向量数据库，仅监听 127.0.0.1（不对外暴露）
  • Redis 7 Alpine：ARQ 异步任务队列，密码保护，LRU 驱逐策略
  • ARQ Worker：embedding 管道（ingestion / file_ingestion / reflection），依赖 Qdrant + Redis 健康检查

所有配置通过 .env 注入，MEMORY_OS_WIKI_PATH / FABRIC_DIR / HERMES_HOME 通过 volume mount 映射到宿主机文件系统。

定时任务体系

7 个 cronjob 协同：

  • wiki-continuous-ingest（每小时）：SHA-256 diff 检测新 wiki 文件 → embed → Qdrant
  • vault-curator-weekly（每周）：frontmatter enrichment + 语义链接 + INDEX.md 生成
  • decay-scanner（每周）：归档低价值 AI 内容
  • wiki-raw-ingest-monitor（每周 2 次）：raw/ 文件抽取概念/实体/比较
  • dlq-auto-report（每 6h）：死信队列监控
  • holographic-memory-backup（每周）：workspace 文件 + 数据库备份
为什么是 Hermes 专属：Memory OS 大量依赖 Hermes 的 hook 系统（pre_llm_call / post_llm_call / on_session_end）和工具注册机制（fact_store / qdrant_search / fabric_recall）。这不是通用的 memory 解决方案，而是专门给 Hermes 用户解决"记忆注入了但 agent 不使用"这个问题的。Layer 7 的 Ground Truth 补丁，理论上可以迁移到任何支持 SOUL.md / rulebook.md 的 agent。

对 coding agent 生态的意义

Memory OS 解决了"记忆注入"这条链路上最被忽视的最后一公里：存储和检索只是前半公里，agent 愿意使用记忆才是后半公里。它示范了"Layer 7 Ground Truth 补丁"这个模式——任何在 prompt 里注入记忆的系统，都可以借鉴这个四层权威层级，把"注入的记忆"明确标记为权威层，而不是靠模型自己推断要不要用。Layer 7 是 2026-05-31 才被发现和修复的，说明整个 agent memory 领域都还在摸索这个问题的正确答案。对于 Hermes 用户来说，它是目前最完整的本地记忆基础设施；对于整个 agent 生态来说，Layer 7 的 insight 值得移植。
