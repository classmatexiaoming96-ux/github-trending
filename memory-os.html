Layer 7 Ground Truth SOUL.md — The Authority Hierarchy Problem
Core insight (2026-05-31): Memory OS was injecting context into every prompt, but the agent's identity documents (SOUL.md & rulebook.md) never told the agent to trust it. Without an explicit rank, injected memory was implicitly optional — below terminal output and official docs. The agent kept re-discovering facts that were already in the prompt.

The Problem in One Diagram

Before Layer 7, the Ground Truth hierarchy had only three levels:

  1. 1. Terminal output → Ground Truth (runtime system state)
  2. 2. Official documentation → Authoritative (APIs, configs, version specifics)
  3. 3. Training knowledge → Reference only (always verify)

The four injected sources — [qdrant], [fabric], [sessions], [facts] — were not listed at all. No status = no authority.

Symptoms the team observed:

  • Agent runs search_files, read_file, session_search to re-find information that [qdrant] already provided
  • Every question treated as novel even when the answer was literally in the prompt
  • Projects, decisions, and constraints rediscovered from scratch each session
  • Cross-session context silently ignored despite appearing in the system preamble

The 4-Level Ground Truth Hierarchy (Post-Fix)

The fix expanded SOUL.md to four levels, inserting injected memory as Level 2:

  1. 1. Terminal output → Ground Truth for system state (runtime)
  2. 2. Injected memory [qdrant], [fabric], [sessions], [facts] → Ground Truth for documented knowledge and prior decisions
  3. 3. Official documentation → Authoritative for APIs, configs, version-specifics
  4. 4. Training knowledge → Reference only; always verify against 1–3

Conflict Resolution Table

Sources in Conflict Resolution Rule Winner

Injected memory vs. Agent assumptions Injected memory wins always. Never treat a question as novel when the answer is in the prompt. Injected memory
Injected memory vs. Official docs Official docs win for version-sensitive specifics. Injected memory wins for project context. Docs / Injected

Key Instruction Added to SOUL.md

"When injected memory contradicts your assumptions, injected memory wins. Never treat a question as novel when the answer is already in your prompt."

Why This Matters

Without Layer 7, the infrastructure layers (01–06) capture and inject memory, but the injected memory is ignored:

  • Qdrant points are injected but the agent curls the Qdrant API to verify them
  • Fabric entries are injected but the agent calls fabric_recall to re-find them
  • Session history is injected but the agent runs session_search to re-discover it
  • Facts are injected but the agent probes fact_store to confirm them

Each re-discovery burns tokens, time, and model context. Layer 07 is what stops the waste.

Bayesian Trust Score Calculation

The trust score is not a simple ratio — it uses a Bayesian prior to avoid overfitting to small sample sizes. All facts start at 0.50 (neutral):

trust_score = (helpful_count + α * prior) / (retrieval_count + α)

Where:
  α = 2          (strength of the prior, i.e. "virtual observations")
  prior = 0.50  (initial belief before any evidence)

For example:

  • New fact (0 retrievals, 0 helpful): trust = (0 + 2×0.5) / (0 + 2) = 0.50
  • 1 retrieval, 1 helpful: trust = (1 + 2×0.5) / (1 + 2) = 0.67
  • 10 retrievals, 3 helpful: trust = (3 + 2×0.5) / (10 + 2) = 0.33 (useful but sparse)
  • 100 retrievals, 80 helpful: trust = (80 + 2×0.5) / (100 + 2) = 0.79 (high confidence)
Critical rule: When you retrieve a fact via probe, search, or reason and reference it in your response, you must call fact_feedback(helpful=True/False) in the same turn. Without feedback, trust_score is ornamental — every fact decays to 0.50 and fact quality degrades silently.

HRR — Holographic Reduced Representations

Layer 3 uses HRR for entity resolution — binding related facts across different surface forms. For example, "Docker", "docker daemon", "containerd" might resolve to the same internal entity ID via vector superposition. This powers probe() and reason() without requiring exact string matches.

HRR is not exposed to the agent directly. The agent sees keyword search + entity linking via the fact_store tool — not the holographic vectors themselves.

Layer 5 Qdrant Vector Database — 4-Level Fallback Chain

Layer 5 provides semantic search over all knowledge that benefits from vector embeddings — wiki pages, session transcripts, raw documents, technical references.

Stack

Qdrant 1.17+ (Docker) Collection: knowledge_base 4096d Cosine + BM25 sparse Qwen3-Embedding-8B via OpenRouter Endpoint: http://localhost:6333

Why Qwen3-Embedding-8B

  • Multilingual — strong performance across 50+ languages (Portuguese, Spanish, etc.)
  • Quality — 4096-dimensional, high semantic fidelity, near top of MTEB leaderboard
  • Speed — fast inference at 8B params; suitable for hourly ingestion without bottlenecking the ARQ worker
  • Cost — $0.025/1M tokens via OpenRouter; full wiki re-index costs cents

Social Closer Gate

Trivial messages skip Qdrant search entirely — no point embedding small talk:

_SOCIAL_CLOSERS = frozenset({
    "ok", "obrigado", "valeu", "beleza", "blz", "tks", "thanks",
    "👍", "👌", "✅", "feito", "certo", "confirmo", "entendido",
    "sim", "não", "claro", "perfeito", "ótimo"
})

def _is_social_close(text):
    stripped = text.strip().lower()
    if stripped in _SOCIAL_CLOSERS: return True
    # Very short ASCII-only without technical markers
    if len(stripped) < 6 and stripped.isascii() and not any(
        c in stripped for c in "://.@#$_?"): return True
    return False
✦ hooks.py — Lifecycle Hooks & the Memory Pipeline

The icarus/hooks.py module implements four lifecycle hooks that wrap every session turn. Together they form a complete capture → inject → extract pipeline.

on_session_start — Context Bootstrap

Called when a new session begins. Clears per-session dedup state, increments creative cycle, then assembles context from four sources:

pre_llm_call — Multi-Source Recall + Injection

The core memory injection hook. Searches all four sources and deduplicates per-session to avoid repeating identical context turn after turn:

def pre_llm_call(session_id="", user_message="", is_first_turn=False, **kwargs):
    # ── Overlap gate ──
    # Only suppress injection on NEAR-LITERAL repetition (>0.85 token overlap).
    # The old 0.6 gate killed injection in long single-topic sessions.
    tokens = _tokenize(user_message)   # alphanumeric tokens ≥4 chars, stopwords removed
    if _last_query_tokens:
        overlap = len(tokens & _last_query_tokens) / max(len(tokens), 1)
        if overlap > 0.85: return None   # suppress — near-identical turn

    _last_query_tokens = tokens
    is_social = _is_social_close(user_message)

    # ── 4 independent searches ──
    results          = state.recall(user_message, max_results=5, agent=agent)  # Fabric
    qdrant_results   = _search_qdrant(user_message, top_k=2, threshold=0.55)  # Qdrant
    session_results  = _search_sessions(user_message, session_id, top_k=2)   # Sessions FTS5
    fact_results     = _search_facts(user_message, top_k=3) if is_first_turn else []  # Facts

    # ── Per-source dedup (within session) ──
    # Fabric:   dedup by entry id (str) — _injected_fabric set
    # Qdrant:   dedup by point id — _injected_qdrant set
    # Sessions: dedup by session_id — _injected_sessions set
    # Facts:    no dedup needed (first-turn only)

    # → Returns {"context": "[fabric]...\n\n[qdrant]...\n\n[sessions]...\n\n[facts]..."}

post_llm_call — Decision Capture & Creative Tracking

def post_llm_call(session_id="", user_message="", assistant_response="", platform="", **kwargs):
    state.exchanges.append({"user": user_message[:200], "assistant": assistant_response[:500]})

    # ── Decision capture ──
    # Requires: decision keyword + outcome keyword + substantial response (>200 chars)
    #           + substantial user request (>50 chars)
    if (DECISION_RE.search(assistant_response)
        and OUTCOME_RE.search(assistant_response)
        and len(assistant_response) > 200
        and len(user_text) > 50):
        body = f"Task: {user_text[:300]}\n\nResult: {assistant_response[:500]}"
        state.write_entry("decision", body, summary[:80],
                          platform=plat, status=entry_status, training_value="high")

    # ── Creative tracking (broader _THEME_RE — no writes) ──
    if _THEME_RE.search(assistant_response):
        theme = _extract_theme(assistant_response)      # top-3 non-stopword words, ≥4 chars
        if theme not in creative["themes"]: creative["themes"].append(theme)

    if _EVAL_RE.search(assistant_response):
        learning = _extract_sentence(assistant_response, _EVAL_RE)  # first matching sentence
        if learning and learning not in creative["learnings"]: creative["learnings"].append(learning)

    if _QUESTION_RE.search(assistant_response):
        question = _extract_sentence(assistant_response, _QUESTION_RE)
        if question and question not in creative["questions"]: creative["questions"].append(question)

    state.save_creative(creative)

on_session_end — LLM Extraction + Legacy Fallback

def on_session_end(session_id="", platform="", completed=False, **kwargs):
    state.write_memory_file(creative)    # persist creative state to disk
    if not state.exchanges: return

    scores = state.score_session()
    if scores["total"] < 0.2: return    # too trivial — skip

    # ── LLM extraction (primary) ──
    transcript = _build_transcript(state.exchanges)   # compact [Turn N — User/Agent] format
    entries = _llm_extract_entries(transcript)        # LLM analyzes → structured entries

    if entries:
        for entry in entries:
            state.write_entry(entry["type"], entry["content"], entry["summary"],
                              platform=plat, training_value=entry["training_value"],
                              status="completed")
        logger.info("LLM extracted %d entries from session", len(entries))
    else:
        # ── Legacy fallback ──
        _legacy_session_write(platform, scores)  # truncated original behavior

LLM-Powered Session Extraction

The _llm_extract_entries() function sends a compact transcript to a chat LLM (DeepSeek via OpenRouter by default) and asks it to extract significant entries worth preserving across sessions. Returns structured dicts:

{
  "type": "decision" | "resolution" | "note",
  "summary": "one line, max 80 chars, original language",
  "content": "markdown with ## Context, ## Action/Decision, ## Outcome",
  "training_value": "high" | "normal" | "low"
}

The extraction prompt instructs the LLM to skip trivial sessions, greetings, and routine chatter — only preserve what's worth cross-session knowledge. The function uses robust JSON parsing (_parse_json_robust) that handles markdown fences, leading/trailing text, and progressive stripping of trailing characters on parse failure.

def _search_sessions(query, current_session_id="", top_k=2):
    # FTS5 over state.db (Hermes session DB)
    # Builds OR-query from meaningful tokens (≥4 chars, stopwords removed)
    toks = [t for t in _tokenize(query) if len(t) >= 4]
    fts_query = " OR ".join(toks[:8])   # max 8 terms to avoid query complexity

    # FTS5 snippet() + GROUP BY are incompatible in same SELECT
    # → fetch top-20 ranked rows, dedup by session_id in Python
    SELECT m.session_id, s.title, s.started_at,
           snippet(messages_fts, 0, '', '', '…', 12) AS snip
    FROM messages_fts
    JOIN messages m ON m.id = messages_fts.rowid
    LEFT JOIN sessions s ON s.id = m.session_id
    WHERE messages_fts MATCH ?
      AND m.session_id != ?
      AND m.role IN ('user','assistant')
    ORDER BY rank
    LIMIT 20

Memory-OS retrieves text from external sources (Qdrant, vault files, SQLite) and injects it into the agent's context. Before any text enters the prompt, it passes through _sanitize_context_text() — a multi-pattern sanitization pipeline with a heuristic safety catch.

Heuristic Safety Catch

Beyond pattern matching, _validate_safe_content() catches unknown attack vectors via directive density analysis:

def _validate_safe_content(text: str) -> str:
    if not text or len(text) < 20: return text
    directivess = len(re.findall(
        r"(?i)\b(ignore|forget|disregard|override|replace|pretend|"
        r"act\s+as|you\s+(are|must|will|shall))\b", text))
    if directivess >= 3 and directivess / max(len(text), 1) > 0.02:
        return "[SANITIZED]"
    return text

Post-Processing

  • Excessive newlines normalized: 4+ consecutive \n → 3
  • Excessive spaces normalized: 8+ spaces → 1
  • Result truncated to max_len (default 600 chars)
  • Fail-open: original text returned on any exception

Usage Rate Metric

The telemetry system computes a usage rate: the fraction of recalled entries that were subsequently used in a write operation. A low usage rate (e.g., <0.2) indicates the agent is ignoring injected context — pointing to a possible Ground Truth hierarchy issue (Layer 7 not applied).

def _summarize_telemetry_events(events):
    recalls = [e for e in events if e.get("event") == "recall"]
    usages  = [e for e in events if e.get("event") == "usage"]
    recalled_ids = set(id for r in recalls for id in r.get("result_ids", []))
    used_ids    = set(u.get("entry_id", "") for u in usages) - {""}
    used_from_recall = used_ids & recalled_ids
    return {
        "total_recalls": len(recalls),
        "total_usages": sum(1 for u in usages if u.get("entry_id", "") in recalled_ids),
        "unique_entries_recalled": len(recalled_ids),
        "unique_entries_used": len(used_from_recall),
        "usage_rate": round(len(used_from_recall) / max(len(recalled_ids), 1), 2),
    }
