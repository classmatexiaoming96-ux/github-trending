§ 00 · Source-level Observatory

deja-vu agent memory layer

deja-vu 不是另一个向量数据库，而是一个零依赖 Go 二进制：它直接读取 Claude Code、Codex、opencode、Cursor、Gemini CLI、Grok Build 等本地会话日志，构建本地倒排索引，并通过 CLI/MCP/auto-recall 让 Agent 在重新调试前先检索过去的解法。

§ 00 · OVERVIEW

它解决什么，凭什么值得拆

源码的核心分工很清楚：CLI 路由集中在 cmd/deja/main.go:64，多 harness 加载从 cmd/deja/main.go:27 到 cmd/deja/main.go:53 串起 Claude、Codex、opencode、aider、Gemini、Cursor、Antigravity 和 Grok；真正索引入口在 internal/index/index.go:135 与 internal/index/index.go:152，查询再落到 internal/index/index.go:179。这说明 deja-vu 的架构不是把所有逻辑塞进一个 CLI，而是把“发现源、构建缓存、检索排序、输出上下文”分层拆开。

项目最有价值的地方在于它选择了确定性本地索引，而不是先上 embedding。internal/index/index.go:195 到 internal/index/index.go:225 使用 postings 交集、子串 fallback 和 record scan 三段检索路径；internal/search/search.go:41 到 internal/search/search.go:107 负责二次过滤、计数、排序和截断。这让它能在隐私敏感的 agent 日志上保持零网络路径，同时给 MCP recall 提供稳定低成本结果。

架构模式
本地日志解析器 + crash-safe 倒排索引 + CLI/MCP 双入口。
核心抽象
Session、Message、Record、Manifest、SyncRecord 五个结构串起历史、索引和同步。
安全策略
索引写入、share、sync export 都重新跑 redaction。
下游依赖
Claude Code / Codex / opencode / Cursor 等 agent harness 的本地 transcript。

▸为什么不是普通 grep

普通 grep 每次都要扫原始日志，且很难把同一 session 的多条消息合并成可复用上下文；deja-vu 在 internal/index/index.go:356 重建索引时写入 records.bin，在 internal/index/index.go:381 并行产出 token postings，并在 internal/index/index.go:404 到 internal/index/index.go:418 对每条消息做去重、截断、脱敏和 token 推送。这个设计让查询阶段读缓存而不是反复解析所有 harness 文件。

74			return

83		if r.Time.UnixNano() > nextWatermarks[source] {

85		}
86	})

92		if len(recs) == 0 {

94		}
95		name := fmt.Sprintf("deja-sync-%s-%d.jsonl", shortHash(source), time.Now().UnixNano())
96		f, err := os.Create(filepath.Join(outDir, name))
97		if err != nil {

100		enc := json.NewEncoder(f)
101		for _, rec := range recs {
102			if err := enc.Encode(rec); err != nil {
103				_ = f.Close()
104				return total, err
105			}
106			total++
107		}
108		if err := f.Close(); err != nil {
109			return total, err
110		}
111	}
112	for source, wm := range nextWatermarks {
113		m.ExportWatermarks[source] = wm
114	}
115	if err := writeManifest(dir, m); err != nil {
116		return total, err
117	}
118	return total, nil

§ 04 · TESTS & RISKS

测试覆盖与风险边界

▸覆盖面

仓库测试覆盖到 parser、index crash recovery、dedupe、sync persistence、redaction、MCP、auto install 和 SSH sync。比如 internal/sources/util.go:91 的 JSONL offset scanner、internal/sources/util.go:133 的并发 parseFiles、cmd/deja/install_auto.go:15 的 Codex hooks 合并、cmd/deja/sync_ssh.go:48 的 ssh push 都有对应测试文件。

▸风险

  • 纯 lexical 检索对同义表达不敏感，internal/index/index.go:205 的子串 fallback 能缓解“code/opencode”类问题，但不能替代语义检索。
  • 索引只脱敏缓存和导出，不会修改原始 harness 日志；这一点由 README 说明，源码上也能从 internal/redact/redact.go:45 的 opt-out 看出使用者仍需管理原始数据。
  • 同步依赖用户选择的目录或 SSH hop，cmd/deja/sync_ssh.go:70 到 cmd/deja/sync_ssh.go:81 会创建远端临时目录并 scp，运维失败模式需要用户理解。

▸结论

deja-vu 的强项是“低摩擦、零服务、本地优先”。它不是最大而全的 memory platform，而是把 agent 已经写到磁盘上的历史变成一个可靠 recall primitive：cmd/deja/main.go:108 给 MCP，cmd/deja/main.go:148 给 ctx，cmd/deja/main.go:139 给 share，cmd/deja/main.go:145 给 sync。这个边界小但清晰，所以适合作为个人或团队 agent 工作流的第一层记忆。
