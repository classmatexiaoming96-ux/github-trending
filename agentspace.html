AgentSpace · Human + Agents.
One Team. One Workspace.

AgentSpace 是一个 Agent 原生协作工作空间——把人类和 AI Agent 变成同一团队的正式成员，在同一个可治理的工作空间里分工、交接、审批与留存产出。核心创新是 AgentRouter：一条统一执行管线，抹平 Claude Code / Codex / OpenCode / OpenClaw / Hermes 五种运行时的差异。

⭐ 343★ 📅 2026-06-22 📦 monorepo · TypeScript 🏗 AgentRouter · Agent 原生

01问题域：为什么需要 Agent 工作空间

大多数 Agent 框架面向单人 terminal，AgentSpace 要解决的是团队级协作与治理问题。

现有框架的三大断层

① Agent 能力私有化——Agent 藏在个人 terminal 里，团队不可见；② 上下文分散——消息、文档、审批、截图、runtime 文件散落在各处，没有共同 home；③ 治理缺失——凭证、文档权限、工具调用、对外操作几乎无法集中审计。

团队级缺失

AgentSpace 的回答

把 Agent 从个人工具升格为数字员工（Digital Employee）：有角色定义、有 owner、有权限边界、可被借用/转让/审计。人类负责方向与授权，Agent 负责执行与协调——在同一套工作空间里。

组织级抽象

四大核心能力

🗓 调度（Scheduling）——AgentRouter 统一路由；🧑‍💼 能力（Capability）——数字员工看板；🤝 协作（Collaboration）——多 Agent 协调 + 人工审批门；🔐 安全（Security）——完整治理控制面。

四层能力矩阵

技术选型

Next.js 14 App Router（apps/web）+ Node.js CLI（apps/cli）+ TypeScript monorepo（npm workspaces）+ PostgreSQL + Docker Compose。远程 Daemon 独立部署，通过 HTTPS + token 与 Web 实例通信。

Next.js + PostgreSQL

03核心创新：AgentRouter

AgentRouter 是 AgentSpace 最关键的技术设计——一条统一执行管线，把 Claude Code / Codex / OpenCode / OpenClaw / Hermes 五种异构运行时压成统一接口。

设计动机：每种 Agent CLI 都有各自的 CLI 参数格式、会话模型、事件流结构和诊断输出。换 runtime 必须重建完整上下文。AgentRouter 把这些差异封装在 harness 层之后，对上层暴露完全一致的 JSON 事件流、会话 ID 和诊断结构。

支持的运行时

Provider Execution Path Diagnostics Session
Claude Code AgentRouter stream-json events, session fallback, tool approval bridge ✅
Codex CLI AgentRouter JSON events, session fallback, runtime tool capability diagnostics ✅
OpenCode AgentRouter JSON events, session propagation, timeout/nonzero/empty diagnostics ✅
OpenClaw AgentRouter health/preflight, auth/profile/model/tool/protocol diagnostics ⚠️ fallback
Hermes Agent AgentRouter text output, executable compatibility checks, timeout/empty diagnostics ✅
Gemini CLI legacy provider-runtime one-shot CLI ❌

04数字员工看板

数字员工看板（Digital Employee Board）是 AgentSpace 的资源管理层——把私有 Agent 变成全组织可见、可申请、可复用的共享资产。

👤

Agent 身份档案

每个 Agent 有 role / summary / owner / readiness / status / 绑定的 runtime 和 harness / 已分配的 skills 和 knowledge / 常用频道和可用性状态。

🔄

Agent Fork / Copy

通过 AgentAccessRequest 申请借用或复制一个 Agent。Owner 审批通过后，Agent 的完整上下文（skills、knowledge、instructions）被 fork 到目标 workspace。

👥

Channel 协作

Agent 参与飞书风格的频道协作：@agentMention 触发执行，运行时输出文件、执行事件和任务历史附着在频道上下文中，不丢失在 terminal 里。

📋

Agent 模板

三种开箱即用模板：finance-analyst（财务分析）、product-manager（产品经理）、product-designer（产品设计）。每个模板定义了 role、instructions、skill recommendations 和适用场景。

AgentTemplate 核心字段

AgentAccessRequest 流程：request_type 分为 fork_copy（复制完整上下文）和 channel_use（仅在频道中使用）。requester 发起请求 → Owner/Admin 审批 → 创建 AgentForkInvitation → 目标 workspace 获得 Agent 副本。

05Remote Daemon 架构

Remote Daemon 是 AgentSpace 的执行引擎，独立部署在远程机器上，通过 HTTPS 心跳轮询与 Web 实例通信。

┌─────────────────────────────────────────────────────────────────┐
│              RemoteDaemon 主循环 (packages/daemon)               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. registerDaemon() ──► POST /daemon/register ──► Web Server  │
│     获取 daemonToken（后续认证用）                              │
│                                                                  │
│  2. 主循环: while(true) {                                        │
│       heartbeat() ──► POST /daemon/heartbeat                    │
│       claimTask()  ──► GET  /daemon/tasks/claim                │
│                                                                  │
│       if (task) {                                                │
│         runProviderTask(task)  ──► AgentRouter / LegacyRT       │
│         uploadOutput()   ──► POST /daemon/output               │
│       }                                                          │
│                                                                  │
│       sleep(heartbeatIntervalMs)                                 │
│  }                                                               │
│                                                                  │
│  心跳间隔: DEFAULT_HEARTBEAT_INTERVAL_MS = 10s                   │
│  任务轮询: DEFAULT_TASK_POLL_INTERVAL_MS = 5s                    │
│  任务超时: configurable via --task-timeout (default: 43.2s)     │
└─────────────────────────────────────────────────────────────────┘

06治理控制面

AgentSpace 的权限模型围绕资源（Resource）× 参与者（Actor）× 能力（Capability）× 外部委托（Delegation）四个维度展开。

Workspace 成员

owner / admin / member 三级角色。邀请链接、加入码、邀请历史追踪。

owner / admin / member

Channel Access

加入权限、频道邀请、访问请求、读写断言。Agent 也需要 channel 成员资格才能参与协作。

channel ACL

Runtime Grants

用户级运行时授权、运行时共享、绑定/解绑、runtime provider 健康状态追踪。

runtime 授权

Document Permissions

owner / editor / viewer 三级角色。Agent 访问需要单独授权。文档版本回滚。

文档权限

Google Workspace

OAuth 凭证 owner、Agent 粒度的 Google Workspace 委托（Scoped Delegation）、外部文档请求。

Google OAuth 2.0

Daemon Security

API token 创建/撤销、远程 Daemon 注册、runtime 显示名管理。

daemon token

Provider 错误分类

// packages/domain/src/daemon-api.ts
export type ProviderErrorCategory =
  | "provider"      // Agent CLI 本身问题
  | "runtime"       // 执行环境问题
  | "configuration" // 配置缺失
  | "auth"          // 认证失败
  | "profile"       // Profile 不存在/无效
  | "model"         // 模型不可用
  | "tool"          // 工具缺失/无权限
  | "protocol";      // 协议解析失败

08快速启动

# 1. 克隆安装
git clone https://github.com/HKUDS/AgentSpace.git
cd AgentSpace

# 2. 安装依赖（Web + CLI + DB + Services + Daemon）
npm run setup

# 3. 配置环境变量
cp .env.example .env

# 4. 启动 PostgreSQL
docker compose -f deploy/postgres/docker-compose.yml up -d

# 5. 初始化数据库
npm run db:pg:init

# 6. 启动 Web
npm run dev:web
