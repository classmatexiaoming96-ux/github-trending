Registry、Merkle 与 HTTP 边界 深度解析

这一页看 Machine Genome 如何把 signed records 从 HTTP 请求变成 canonical bytes、bbolt 索引、append-only log、audit chain 与可验证的 inclusion/consistency proof。

§ 02 · KEY FLOW

关键流程

POST /v1/records -> content-type + 1 MiB limit -> Store.Submit -> Canonicalize -> Validate / Verify by recordType -> namespace grant check -> insert object + metadata + log leaf -> append audit event -> expose /v1/log/inclusion and /v1/log/consistency

这条 admission flow 可以从 registry/http.go:129、registry/http.go:182、registry/http.go:187、registry/http.go:192、registry/store.go:158、registry/store.go:165、registry/store.go:190、registry/store.go:333、registry/store.go:358、registry/store.go:361 贯通。测试层在 registry/store_test.go:25、registry/store_test.go:32、registry/store_test.go:47 和 registry/store_test.go:51 验证了入库、幂等和 inclusion proof。

§ 03 · EDGE CASES

边界 / 失败模式

  • registry/http.go:161 到 registry/http.go:179 的 middleware 加了 request id、安全响应头和 IP rate limit，说明 public registry 默认暴露在不可信网络上。
  • registry/store.go:286 到 registry/store.go:309 记录 amendment equivocation，测试 registry/store_test.go:97 到 registry/store_test.go:103 确认 fork 不会覆盖既有链。
  • registry/store.go:472 到 registry/store.go:492 提供 tombstone，但 registry/store_test.go:127 到 registry/store_test.go:131 验证 includeGone 仍能读取不可变对象。
  • registry/merkle.go:126 到 registry/merkle.go:189 验证 consistency proof，registry/store_test.go:204 到 registry/store_test.go:215 会篡改 second root 来确认失败。
  • scripts/check-repository.py:100 到 scripts/check-repository.py:128 检查 JSON $ref，scripts/check-repository.py:130 到 scripts/check-repository.py:139 检查 Markdown 本地链接，补足代码测试无法覆盖的发布资产完整性。
适合复用的部分

Store.Submit 的 admission pattern、append audit、Merkle proof、tombstone/includeGone 分层都可以迁移到内部 Agent registry。

需要谨慎的部分

public registry 的 DNS namespace challenge、checkpoint gossip、备份权限和 admin token 生命周期需要实际运维制度配套。
