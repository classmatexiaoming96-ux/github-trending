§ 00 · OVERVIEW

它解决什么，凭什么值得拆

这个仓库的价值在于它把两个相反角色放到同一个工程框架里：买家侧 shopping agent 处理搜索、详情、购物车和订单，商家侧 merchant agent 处理库存、活动和上架草稿。公共层先在 sources/commerce-agents/commerce-common/commerce_common/turn.py:67、sources/commerce-agents/commerce-common/commerce_common/turn.py:124、sources/commerce-agents/commerce-common/commerce_common/prompt_assembly.py:60、sources/commerce-agents/commerce-common/commerce_common/execution.py:184 抽掉对话历史、提示块、工具契约与执行入口，领域层再把这些能力收敛到明确的商业动作。

源码最值得看的是防线分布，而不是单个 prompt。输入先经过 fencing 与 prompt assembly，工具调用再经过 executor 的 schema/状态注入，最后由 gates 判断是否必须澄清、补证据或等待人工确认。这条链在 sources/commerce-agents/commerce-common/commerce_common/fencing.py:83、sources/commerce-agents/commerce-common/commerce_common/grounding.py:55、sources/commerce-agents/shopping-agent/core/shopping_agent/gates.py:102、sources/commerce-agents/merchant-agent/core/merchant_agent/gates.py:163、sources/commerce-agents/commerce-common/tests/test_turn.py:147 都有测试或显式实现，因此它更像一份可复制的 agent 安全蓝图。

§ 01 · ARCHITECTURE

双 Agent 蓝图与公共运行时

架构上它没有把购物和商家流程塞进一个巨大的 agent，而是先定义公共 turn、prompt、memory、fencing、grounding 和 executor，再由 shopping / merchant 两套子包注册领域工具。从 sources/commerce-agents/commerce-common/commerce_common/types.py:17、sources/commerce-agents/commerce-common/commerce_common/skills.py:17、sources/commerce-agents/shopping-agent/core/shopping_agent/prompt.py:145、sources/commerce-agents/merchant-agent/core/merchant_agent/prompt.py:188 可以看到这套分层让提示词规则、工具契约和可持久化事实分别演进。

→

▸模块清单

公共包里的 turn 负责把 stream 转成可恢复的 round，execution 负责把工具名映射到处理器，fencing 和 grounding 负责让外部文本进 prompt 前先降权，memory 负责写入前过滤隐私与会话性事实。这些边界分别落在 sources/commerce-agents/commerce-common/commerce_common/turn.py:270、sources/commerce-agents/commerce-common/commerce_common/execution.py:106、sources/commerce-agents/commerce-common/commerce_common/fencing.py:99、sources/commerce-agents/commerce-common/commerce_common/grounding.py:72、sources/commerce-agents/commerce-common/commerce_common/memory.py:130、sources/commerce-agents/commerce-common/commerce_common/prompt_assembly.py:43，而 shopping 与 merchant 只需要实现自己领域里的工具 handler 和 gate。

commerce_common.turn
维护最新用户输入、history compact、streamed tool calls、salvage 与 turn close。
commerce_common.execution
统一校验工具参数，把 session/context/cache/status 注入 handler。
shopping_agent / merchant_agent

 225     async def dispatch(self, name: str, tool_input: dict[str, Any]) -> ToolOutcome:
 226         """:meth:`execute` without the failure ladder: what the tool raised propagates,
 227         so a host prefetching a read can tell a failed tool from a result the tool wrote
 228         (a not-found line, a held call). The ``status`` line is dropped here, before any
 229         argument is validated or any handler runs; a tool the deployment's config leaves
 230         out of the tool list is unknown here too, whichever path calls it."""
 231         tool_input, _status = self.split_status(name, tool_input)
 232         if name in self._absent:
 233             return ToolOutcome.error(self.absent_text.format(name=name))
 234         if name == LOAD_SKILL:
 235             return self._load_skill(tool_input)
 236         if (spec := self.components.get(name) or self._extensions.get(name)) is not None:
 237             return await self._present(spec, tool_input)
 238         if (delegate := self._delegates.get(name)) is not None:
 239             return await self._run_delegate(delegate, tool_input)
 240         handler = self._handlers.get(name)
 241         if handler is None:
 242             return ToolOutcome.error(f"Unknown tool: {name}")
 243         return await handler(tool_input)

§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

这个项目是参考蓝图，不是完整生产平台；它清楚展示了 agent 安全边界，但仍需要接入真实身份、支付、库存一致性、审计存储和队列重试策略。源码里能看到 sources/commerce-agents/shopping-agent/core/shopping_agent/executor.py:199、sources/commerce-agents/merchant-agent/core/merchant_agent/executor.py:211、sources/commerce-agents/commerce-common/commerce_common/memory.py:101、sources/commerce-agents/commerce-common/commerce_common/prompt_assembly.py:103 这些实现点还偏 demo/runtime 层，落地前需要按业务风险继续加厚。

缺少端到端外部一致性
