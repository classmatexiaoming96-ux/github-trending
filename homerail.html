§ 00 · Source-level Observatory

homerail 可审计的本地 DAG Agent 运行时

HomeRail 把语音入口、DAG 编排、容器化 Agent Worker 与本地审计串成一个可观察的运行时。它不把“多 Agent”停留在 prompt 层，而是把节点状态、交接端口、重试预算、会话与证据都写成可验证契约。

▸成功路径：显式端口驱动下游

▸已知边界 / 失败模式

  • 条件边未命中时节点必须 SKIPPED，而不是因 after_dep 满足被误唤醒。
  • Agent 正常结束但没有 handoff 会触发 correction；次数受 max_corrections_per_node 限制。
  • 瞬时派发错误最多重试一次；能力不匹配等确定性失败不重试。
  • Manager 冷重启会重放 handoff 历史，但孤儿 RUNNING 节点会被降级为失败。
§ 05 · HIGHLIGHTS

值得借鉴的工程亮点

显式状态机
节点可达性、条件分支、循环唤醒和终止条件均由代码推进，不把控制权交给模型措辞。
预算化容错
dispatch、handoff、edge traversal、correction 都有上限，避免自治循环无限扩张。
双轨证据
transcript 和 tool-events 分离写入，结束时为 transcript 写校验和，可检查证据是否完整。
可替换模型后端
Worker 在统一事件协议下适配 Claude、Codex App Server、Kimi 等运行时。
§ 06 · RISKS & GAPS

HomeRail 仍是 2026 年 7 月刚创建的早期项目。sources/worker/src/audit/index.ts:57、sources/worker/src/audit/index.ts:63、sources/worker/src/audit/index.ts:70、sources/worker/src/audit/index.ts:77、sources/worker/src/audit/index.ts:79、sources/worker/src/audit/index.ts:85 能检查审计文件、校验和 sidecar 与工具事件，但 PromptRunner 的审计创建在 sources/worker/src/prompt-runner.ts:174、sources/worker/src/prompt-runner.ts:177、sources/worker/src/prompt-runner.ts:178、sources/worker/src/prompt-runner.ts:179 被明确设计为 best-effort：审计器初始化失败不会阻断任务。这有利于可用性，却意味着“任务完成”不自动等于“证据完整”，生产环境必须额外把 completeness 结果纳入发布门禁。

早期 API 变化
协议标记 v0.1.x，模块数量大且变化快，集成方应锁定提交与 schema。
本地密钥与挂载
多 Provider、容器和外部模型意味着密钥、workspace mount 与网络策略需要独立审计。
Best-effort 审计
审计写入失败不阻止 Agent 继续；强合规场景要把证据缺失升级为硬失败。
恢复语义
冷恢复会把孤儿 RUNNING 节点判失败；长任务需明确是否允许自动补偿或人工接管。
