§ 00 · OVERVIEW

它解决什么，凭什么值得拆

Deltafin 值得拆，是因为它没有把“Kimi K3 本地运行”简化成一个包装脚本。项目在 README 里声明的核心事实是本地 workstation、2.8T MoE、自动选择 MPS/CUDA/CPU，以及 M1 Max 上 0.0687 token/s 的参考速度；源码侧真正承接这些承诺的是 sources/deltafin/tools/kimi_run.py:39、sources/deltafin/tools/kimi_run.py:45、sources/deltafin/tools/kimi_run.py:72、sources/deltafin/tools/kimi_run.py:121，它们把配置、专家 top-k、设备解析和主设备落到可执行状态。

更重要的是，它把超大 MoE 的瓶颈拆成三个可治理平面：resident spine 每 token 循环读，routed experts 按需拉取/缓存，最后通过 fast MoE backend 执行。sources/deltafin/tools/kimi_run.py:1557、sources/deltafin/tools/kimi_run.py:1578、sources/deltafin/tools/kimi_run.py:1119、sources/deltafin/tools/kimi_run.py:1161 对应这三段实际路径，说明页面看到的性能叙述不是营销语，而是源码里可追踪的分支。

§ 03 · EXPERT CACHE

专家缓存：按需读取但不能阻塞前台

1"""Self-tuning, pressure-aware RAM cache for the int8 spine.
2
3WHY THE OLD ONE WAS OFF BY DEFAULT
4----------------------------------
5kimi_run.py's first attempt sized a spine RAM cache from "free + inactive" and
6took 29.7 GB on this 64 GB box.  A decode token went from 14 s to 122 s: the
7inactive pages it counted as spare were the page cache that was already serving
8the spine and the expert blobs, so claiming them as anonymous heap did not add
9capacity, it MOVED capacity from a class the kernel can drop for free (clean
10file pages) into a class it can only reclaim by compressing or swapping.  It
11then compressed, and every token paid for it.  Two things follow, and this
12module implements both:
13
14  1. THE HEADROOM SIGNAL MUST BE `free`, NOT `free + inactive`.  `free` is the
15     only class that can be taken without displacing something that is already
16     doing useful work.  We additionally hold a reserve (K3_SPINE_CACHE_FLOOR_GB,
17     default 8 GB) below which we stop growing, because the page cache still has
18     to hold the expert payloads.
19
20  2. GROWTH MUST BE WATCHED, NOT PREDICTED.  No static budget can know what else
21     the machine will do while we run. Every admission re-reads the kernel's own
22     accounting (Mach host_statistics64 on macOS; /proc on Linux); if the
23     compressor or swapper starts moving, we stop growing and give memory back
24     layer by layer. That is the difference between the 8x cliff and a cache
25     that just quietly becomes smaller.
26
27WHAT THE CACHE IS WORTH, MEASURED ON THIS MACHINE
28-------------------------------------------------
29Reading a layer's blobs cold off the NVMe:            ~7.0 GB/s
30Reading the same blobs back out of the page cache:   ~27-38 GB/s
31So an in-RAM layer is ~5x cheaper, and the 53 GB spine's ~7.5 s/token of read
32collapses toward ~1.5 s for whatever fraction is resident.  The fraction is what
33matters: access is a strict 0..91 cycle, so under LRU a working set larger than
34RAM gets a ~0% hit rate (each layer is evicted just before it is needed again).
35Caching a FIXED SUBSET instead converts that into a hit rate equal to the
36fraction that fits, which is why a partial cache is still worth having -- but
37only if the layers outside the subset can be prevented from evicting it, which
38is what K3_SPINE_STREAM_NOCACHE (see spine_io) is for.
39
40FLAGS (defaults reproduce today's behaviour exactly: no cache at all)
41    K3_SPINE_CACHE_GB=<n>       hard ceiling on the cache, 0 = disabled
42    K3_SPINE_CACHE_AUTO=1       grow toward the ceiling only while the kernel
43                                says there is room; without _GB, cap growth by
44                                queried physical/recommended working-set limits
45    K3_SPINE_CACHE_FLOOR_GB=<n> stop growing with less than this much `free`
46                                (default 8)
47    K3_SPINE_CACHE_TOL_GB=<n>   how much new compressor traffic to tolerate
48                                before shrinking (default 0.5)
49    K3_SPINE_CACHE_SHRINK=<n>   layers to drop per shrink event (default 4)
50
51ON A 128 GB MAC set K3_SPINE_CACHE_AUTO=1 and leave the ceiling alone (or
52K3_SPINE_CACHE_GB=44 K3_SPINE_CACHE_AUTO=1 to be explicit): 53 GB of spine plus
53~12 GB of hot expert page cache plus the model's own working set fits with room
54to spare, and the watchdog will still claw it back if something else on the box
55wants memory.  On 64 GB, K3_SPINE_CACHE_GB=6 K3_SPINE_CACHE_AUTO=1 is the
