§ 00 · OVERVIEW

它解决什么，凭什么值得拆

这个项目的架构取舍很直接：不跑 Appium、不装 WebDriverAgent、不越狱，而是把 Apple 已经提供的 iPhone Mirroring 当成视频与输入通道。src/phone_harness/helpers.py:31、src/phone_harness/helpers.py:45、src/phone_harness/mirror.py:91、src/phone_harness/ocr.py:19 分别对应状态闸门、用户连接边界、窗口截图和 OCR 坐标换算，说明作者把“能操作手机”和“不能替用户完成物理连接”分得很清楚。

源码规模只有约 793 行，但完整闭环存在：CLI 在 src/phone_harness/run.py:16、src/phone_harness/run.py:30、src/phone_harness/run.py:36 读取 stdin 并注入 helper；镜像层在 src/phone_harness/mirror.py:24、src/phone_harness/mirror.py:91、src/phone_harness/mirror.py:133 负责窗口、截图和点击；滚动与等待逻辑在 src/phone_harness/helpers.py:174、src/phone_harness/helpers.py:316、src/phone_harness/helpers.py:332 处理移动判断、稳定等待和 agent helper 注入。

▸核心数据

架构模式
无 daemon 的本地 CLI harness：每次命令重新发现窗口、截图、OCR、发事件，失败时通过异常把控制权交回用户。
核心抽象
全局屏幕点坐标 + Vision OCR 文本框 + Quartz HID 事件 + agent-workspace 可编辑 helper。
性能/精度数据
没有 benchmark；关键经验写在源码注释里，例如滚动重叠阈值 0.6、稳定等待 2.5s、window capture 失败后回退区域截图。
下游依赖
适合 iOS-only app、手机号/2FA、本机 App 视觉测试；不适合可通过网页/API 完成的任务。

45def ensure_mirroring():
46    """Return the mirroring window if the phone is connected and ready.
47
48    Never launches the app, taps Connect/Continue, or polls to reconnect —
49    resuming mirroring is physical and only the user can do it. If the session
50    isn't ready, raises with instructions for the user. STOP and relay that
51    message; do not try to tap through the connect screen yourself.
52    """
53    state = connection_state()
54    if state == "ready":
55        mirror.activate()
56        return mirror.find_window()
57    if state == "not-running":
58        raise RuntimeError(
59            "iPhone Mirroring isn't running. Please open the iPhone Mirroring "
60            "app and connect your phone, then retry — reconnecting is physical, "
61            "so I can't do it for you.")
62    if state == "no-window":
63        raise RuntimeError(
64            "iPhone Mirroring is open but no phone is connected. Please connect "
65            "your phone in the app, then retry.")
66    raise RuntimeError(
67        "iPhone Mirroring is not connected — it's showing a connect / 'iPhone "
68        "in Use' screen. This needs you: open iPhone Mirroring and connect the "
69        "phone, and if it says 'iPhone in Use', LOCK your iPhone so mirroring "
70        "can resume. Then retry. I will not tap Connect for you.")

src/phone_harness/ocr.py · L19-56Python
19def recognize(path, window):
20    """OCR a capture of `window` ({x, y, w, h} screen points).
21
22    Returns [{text, confidence, x, y, w, h}] where (x, y) is the box center in
23    screen points — pass straight to tap(). Vision's normalized boxes have a
24    bottom-left origin; screen points have a top-left origin, hence the flip.
25    """
26    handler = Vision.VNImageRequestHandler.alloc().initWithURL_options_(
27        NSURL.fileURLWithPath_(path), {})
28    request = Vision.VNRecognizeTextRequest.alloc().init()
29    request.setRecognitionLevel_(Vision.VNRequestTextRecognitionLevelAccurate)
30    ok, err = handler.performRequests_error_([request], None)
31    if not ok:
32        raise RuntimeError(f"Vision OCR failed: {err}")
33
34    img_w, img_h = image_size(path)
35    sx = window["w"] / img_w  # image px -> screen points
36    sy = window["h"] / img_h
37
38    out = []
39    for obs in request.results() or []:
40        cand = obs.topCandidates_(1)
41        if not cand:
42            continue
43        bb = obs.boundingBox()
44        px = bb.origin.x * img_w
45        py_top = (1.0 - bb.origin.y - bb.size.height) * img_h
46        pw = bb.size.width * img_w
47        ph = bb.size.height * img_h
48        out.append({
49            "text": str(cand[0].string()),
50            "confidence": round(float(cand[0].confidence()), 3),
51            "x": round(window["x"] + (px + pw / 2) * sx, 1),
52            "y": round(window["y"] + (py_top + ph / 2) * sy, 1),
53            "w": round(pw * sx, 1),
54            "h": round(ph * sy, 1),
55        })
56    return out

▸已知边界 / 失败模式

  • 连接暂停或 iPhone in Use 时，src/phone_harness/helpers.py:66 直接要求用户锁屏/连接，不让 agent 乱点。

§ 05 · HIGHLIGHTS

为什么这个小项目值得拆

亮点一：不替用户连接手机
最关键的安全设计在 src/phone_harness/helpers.py:45、src/phone_harness/helpers.py:57、src/phone_harness/helpers.py:66：未运行、无窗口、连接暂停都会抛出给用户看的错误，而不是让 agent 去点 Connect。
亮点二：用 OCR 当作贫血 DOM
src/phone_harness/ocr.py:26、src/phone_harness/ocr.py:39、src/phone_harness/ocr.py:51 让每个可见文本带置信度与中心点，足以支撑 tap_text、find_text 和滚动解析。

§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

这个项目的边界同样清楚：它没有尝试绕过系统权限，也没有把视频流伪装成完整 DOM。src/phone_harness/helpers.py:48、src/phone_harness/mirror.py:5、src/phone_harness/ocr.py:3、src/phone_harness/mirror.py:216 说明它接受 iPhone Mirroring 的限制，然后用截图、OCR、HID keycode 和用户确认建立可审计的最小闭环。

物理连接仍是瓶颈
src/phone_harness/helpers.py:24、src/phone_harness/helpers.py:67、src/phone_harness/mirror.py:60 已经写明 mirroring 断开后只能让用户介入；这不是 bug，而是产品边界。
OCR 不是语义树
src/phone_harness/helpers.py:89、src/phone_harness/helpers.py:105、src/phone_harness/ocr.py:48 支持按文字点击，但无标签图标、复杂布局和个人内容仍需要截图确认与人工约束。
输入覆盖有限
src/phone_harness/mirror.py:198、src/phone_harness/mirror.py:242、src/phone_harness/mirror.py:251 使用 US keycode 逐字符输入，不支持的字符会抛错，emoji、多语言输入和系统键盘状态都要额外处理。
没有测试目录
仓库更像一个小型系统工具，验证主要依赖 src/phone_harness/admin.py:12、src/phone_harness/admin.py:65、src/phone_harness/mirror.py:84 的 doctor 与运行时截图，不是常规 pytest 覆盖。
