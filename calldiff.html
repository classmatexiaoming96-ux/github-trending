§ 00 · Source-level Observatory

calldiff 给 Agentic Review 看调用流变化

calldiff 把 git diff 的文本变化提升成 who-calls-whom 的调用栈差异，适合审查 AI agent 改动后的控制流重排。它不是语言服务器，而是用 Tree-sitter 做跨语言 AST 提取，再把函数体中的调用、分支和 JSX 组件组织成可 diff 的树。

§ 01 · ARCHITECTURE

从 CLI 到调用树的六段管线

入口层在 src/cli.ts:119 定义 incur CLI，并把 diff/tree/reach 三个命令都收束到 src/run.ts:143、src/run.ts:228 和 src/run.ts:271。这个分层让命令参数、输出格式、CTA 和 token slicing 保持在 CLI 层，而真正的源码读取、索引构建和树渲染留给 run 层。

▸系统拓扑

CLI args ├─ diff → resolve git snapshots → load before/after indexes → infer entries → diff trees ├─ tree → resolve one snapshot → load index → expand entry tree └─ reach → resolve one snapshot → load index → collect paths to target

▸模块清单

src/git.ts:181 和 src/git.ts:199 负责枚举工作区与 commit 文件；src/extract.ts:30 用语言 registry 加载 extractor；src/calltree.ts:107 展开递归调用树；src/diff.ts:62 用 LCS 对齐子节点；src/render.ts:47 把树变成 CLI 可读的 ASCII。

▸类型契约

src/types.ts:12 把展开后的节点固定为 CallNode，src/types.ts:29 则把函数体中的原始动作表达成 CallStep。这个二段模型很重要：extractor 只负责“函数内发生了哪些调用或分支”，calltree 层再决定如何沿 FunctionIndex 继续展开。

▸diff.ts 用 LCS 保持 after 树顺序

src/diff.ts:62 对 before/after children 做最长公共子序列对齐，而不是简单按 key map 合并；这让新增、删除和移动后的输出尽量贴近“after”调用顺序，适合代码 review 时顺着新控制流阅读。

62function diffChildren(before: CallNode[], after: CallNode[]): DiffNode[] {
63  const n = before.length;
64  const m = after.length;
65  const dp: number[][] = Array.from({ length: n + 1 }, () =>
66    Array.from({ length: m + 1 }, () => 0),
67  );
68
69  for (let i = n - 1; i >= 0; i--) {
70    for (let j = m - 1; j >= 0; j--) {
71      if (before[i]!.key === after[j]!.key) {
72        dp[i]![j] = dp[i + 1]![j + 1]! + 1;
73      } else {
74        dp[i]![j] = Math.max(dp[i + 1]![j]!, dp[i]![j + 1]!);
75      }
76    }
77  }
78
79  const result: DiffNode[] = [];
80  let i = 0;
81  let j = 0;
82  while (i < n && j < m) {
83    if (before[i]!.key === after[j]!.key) {
84      result.push(diffNode(before[i]!, after[j]!));
85      i += 1;
86      j += 1;
87    } else if (dp[i + 1]![j]! >= dp[i]![j + 1]!) {
88      result.push(diffNode(before[i]!, null));
89      i += 1;
90    } else {
91      result.push(diffNode(null, after[j]!));
92      j += 1;
93    }
94  }
95  while (i < n) {
96    result.push(diffNode(before[i]!, null));
97    i += 1;
98  }
99  while (j < m) {
100    result.push(diffNode(null, after[j]!));
101    j += 1;
102  }
103  return result;
104}

§ 05 · RISKS

技术亮点之外，仍要看清边界

▸AST 不是类型系统

src/languages/typescript.ts:76 的 calleeKey 主要基于 identifier/member expression 推断调用 key；这能覆盖大量静态调用，但动态属性、依赖注入和运行时多态不会像 LSP 或类型检查器那样精确。README 也明确这是 syntactic AST-based 工具。

具体到 TypeScript，src/languages/typescript.ts:84 放弃 subscript expression，src/languages/typescript.ts:96 才把 this.method 归到 class，src/languages/typescript.ts:99 处理 object.property，src/languages/typescript.ts:102 又在 className 存在时做保守回退。这个策略稳，但不能恢复真正的运行时接收者。

▸语言数量带来维护压力

src/languages/registry.ts:28 一次注册 22 种 extractor，优势是覆盖广；代价是每种语言的语法边界都要靠测试守住。src/languages/grammars.ts:92 还需要为个别 grammar pin 安装规格，说明 native grammar 生态本身也会带来兼容成本。

运行时依赖同样不轻：src/languages/grammars.ts:104 会加载 grammar 包，src/languages/grammars.ts:128 决定 cache 目录，src/languages/grammars.ts:132 可能触发 npm install，src/languages/grammars.ts:151 再从 cache package.json 创建 require。离线环境要提前预热这些 grammar。

▸适合 review 辅助，不适合当唯一真相

calldiff 的强项是让 agentic review 快速看到调用流变化。最终判断仍要结合真实类型信息、测试和运行行为；尤其是 src/git.ts:156 的 isSourceFile 只按扩展名纳入文件，生成代码、配置驱动和框架魔法不会完整进入调用图。

快照层也有边界：src/git.ts:181 读取工作区 tracked 和 untracked 文件，src/git.ts:199 读取 commit 树，src/git.ts:230 做路径过滤，src/git.ts:242 返回 SnapshotFile 列表。它看的是 Git 视角下的源文件，不会自动理解构建产物或框架生成的隐式调用。
