§ 00 · DETAIL

导入链与契约

land 的入口约束

land 是唯一被授权落到 integrationBranch 的路径。src/land.ts:39 进入函数后先加载配置，src/land.ts:46 读取当前 branch，src/land.ts:47 直接拒绝从 integrationBranch、protectedBranches 或 detached HEAD 运行。这个约束避免 agent 在主 checkout 上直接 land，确保 lane 语义成立。

它还承认 build tool 会重写文件。src/land.ts:64 读取 regenerableFiles，src/land.ts:65 的 discardRegenerableDirt 只会丢弃白名单文件；src/land.ts:71 把其他 dirty file 当成真实 WIP，不替用户猜。

39export async function land(): Promise<void> {
40  if (!hasConfig()) {
41    console.error("claude-code-merge-queue land: no claude-code-merge-queue.config found at the repo root. Run `claude-code-merge-queue init` first.");
42    process.exit(1);
43  }
44  const cfg = await loadConfig();
45
46  const branch = execSync("git rev-parse --abbrev-ref HEAD", { encoding: "utf8" }).trim();
47  if (branch === cfg.integrationBranch || cfg.protectedBranches.includes(branch) || branch === "HEAD") {
48    console.error(`claude-code-merge-queue land: refusing to run from '${branch}' — land is for lane branches only.`);
49    process.exit(1);
50  }
51
52  // A rebase refuses to run at all with a dirty tree. Build-tool-regenerated
53  // noise shouldn't block landing — discard ONLY the configured
54  // regenerableFiles, exactly like sync does for the fast-forward on the
55  // other end. Any other dirty file is real work-in-progress: leave it alone
56  // and let the rebase fail loud.
57  //
58  // Checked here AND again right before the rebase itself (not just once):
59  // a build tool can regenerate one of these files at any point, including
60  // during the (possibly long) wait for the landing queue lock below. A
61  // single check up front leaves that whole wait as a window where the
62  // exact same harmless noise reappears and gets misreported as a real
63  // rebase conflict instead of silently discarded like it should be.
64  const regenerable = new Set(cfg.regenerableFiles);
65  function discardRegenerableDirt(): void {
66    const status = execSync("git status --porcelain", { encoding: "utf8" });
67    const dirty = status
68      .split("\n")
69      .filter(Boolean)
70      .map((line) => line.slice(3).trim());
71    const blocking = dirty.filter((f) => !regenerable.has(f));
72    if (dirty.length > 0 && blocking.length === 0) {
73      execSync(`git checkout -- ${dirty.map((f) => `"${f}"`).join(" ")}`);
74    }
75  }
76  discardRegenerableDirt();
77
78  const lock = createQueueLock("land");

串行落地主线

落地锁在 src/land.ts:78 获取，等待日志由 src/land.ts:81 的 onWait 提供，agent 或人能看到前面还有几个 landing。拿锁后 src/land.ts:93 再清一次 regenerable dirt，因为等待队列期间文件可能又被构建工具重写；这个二次检查来自真实 bug。

关键流程

同步主 checkout

push 成功不是结束。src/land.ts:126 直接调用 sync(cfg)，把主 checkout 快进。sync 的保护在 src/sync.ts:151 读取当前 branch，src/sync.ts:163 如果不是 integrationBranch 就拒绝行动；src/sync.ts:177 只做 merge --ff-only，避免自动生成 merge commit。

依赖同步是更细的工程判断。src/sync.ts:75 检查 lockfile 是否变化，src/sync.ts:81 如果 package.json 删除了依赖就不自动 install，避免共享 node_modules 把旧 lane 需要的 binary 删除；安全的版本 bump 才在 src/sync.ts:91 自动 install。
