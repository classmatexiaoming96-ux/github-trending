481def copy_public_task_dir(src: Path, dst: Path) -> None:
482    """Copy the agent-visible task content, never exposing verifier-only data.
483
484    New layout (allowlist): the agent sees ONLY ``workspace/`` (its inputs) plus
485    the task statement ``task.md``. Everything verifier-only — ``grader/``,
486    ``services/`` (mock source), ``private/``, ``rubric.json``, ``task.toml`` —
487    lives outside ``workspace/`` and is structurally excluded by not copying it.
488    This replaces the old blocklist, where a mock/verifier filename missing from
489    the ignore tuple would leak answers to the agent.
490
491    Old layout (frozen v2, no ``grader/``/``workspace/``): fall back to the
492    historical blocklist over the whole task dir. Removed once v2 migrates (Phase 2).
493    """
494    workspace = src / "workspace"
495    # Detect the new layout by grader/ or workspace/ so browse-only tasks (no
496    # agent inputs → no workspace/) still take the allowlist path instead of
497    # falling through to the old blocklist (which would leak grader/ + services/).
498    is_new_layout = (src / "grader").is_dir() or workspace.is_dir()
499    if is_new_layout:
500        dst.mkdir(parents=True, exist_ok=True)
501        if workspace.is_dir():
502            shutil.copytree(
503                workspace,
504                dst / "workspace",
505                ignore=shutil.ignore_patterns(".DS_Store", "__pycache__", "*.pyc"),
506            )
507        task_md = src / "task.md"
508        if task_md.is_file():
509            shutil.copy2(task_md, dst / "task.md")
510        return
511    ignore = shutil.ignore_patterns(
512        ".DS_Store",
513        "fixtures",
514        "attachments",
515        "node_modules",
516        "private",
517        "__pycache__",
518        "*.pyc",
519        "rubric.json",
520        "test.sh",
521        "task.toml",
522        "source_metadata.json",
523        "REFERENCE_SOLUTION.py",
524        "_grader.py",
525        "host_deps.txt",
526        "package.json",
527        "package-lock.json",
528        "start_mock_services.sh",
529        "mock*.py",
530        "mock*.js",
531        "*server.py",
532        "*server.js",
533        "*.mjs",
534        "verify*.py",
535        "INPUTS_TO_BUILD.md",
536        "ASSET_INVENTORY.md",
537        "EXPECTED_BEHAVIOR.md",
538    )
539    shutil.copytree(src, dst, ignore=ignore)

§ 02 · KEY FLOW

关键流程

task config → contract object → runtime materialization → agent execution → verifier/report

从这些源码行可以看到，RealReplicaBench 的流程不是把 Agent 输出丢给一个脚本评分，而是先构造可复现任务世界，再让 harness 运行，最后把 verifier、trajectory 和 report 合并成证据链。

读这条链路时还要把入口和物化点连起来看：src/real_replica_bench/cli.py:342 负责把磁盘任务转成对象，src/real_replica_bench/cli.py:371 读取 harness 声明，src/real_replica_bench/cli.py:428 固定 provider 参数，src/real_replica_bench/cli.py:508 过滤私有资源，src/real_replica_bench/cli.py:522 保留公开 fixture，src/real_replica_bench/cli.py:631 再把 runtime mock 写进副本目录。

§ 03 · EDGE CASES

边界 / 失败模式

▸失败在哪里会被放大

  • 如果任务声明不完整，src/real_replica_bench/cli.py:358 附近的解析会提前中断，而不是让 Agent 在缺环境时跑出伪结果。
  • 如果 mock 或 provider 配置漂移，src/real_replica_bench/cli.py:415 附近的检查会让问题在发布前暴露。
  • 如果 Agent 只完成部分业务动作，最终分数会被 verifier 端硬门禁压成失败，需要回看 trajectory。
