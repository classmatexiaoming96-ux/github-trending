§ 00 · OVERVIEW

它解决什么，凭什么值得拆

这个仓库值得拆，是因为它把“科研 Agent”从口号落到本地应用骨架：CLI 入口在 backend/cli/src/index.ts:55 建出完整命令树，默认 web 命令在 backend/cli/src/cli/cmd/web.ts:60 接管裸 `openscience`，server 再服务浏览器工作台。它的关键不是模型调用，而是把模型、工具、权限、配置和 UI 都放在同一个可审计闭环里。

源码里最有价值的设计是“本地优先但可扩展”：Host/Origin guard 在 backend/cli/src/server/host-guard.ts:19 限定 loopback host，又在 backend/cli/src/server/host-guard.ts:54 单独判断 origin；配置系统从远程 well-known、global、project、`.openscience` 和 synced config 分层合并，见 backend/cli/src/config/config.ts:75 到 backend/cli/src/config/config.ts:207。这让它既像桌面软件，又保留 agent 工具链的可组合性。 入口 middleware 还会设置运行时标记 backend/cli/src/index.ts:83。 credential 注入发生在命令执行前 backend/cli/src/index.ts:101。 compute keys 也在同一层应用 backend/cli/src/index.ts:105。 命令注册覆盖 serve/web/session/project backend/cli/src/index.ts:121。 错误格式化集中在 fatal catch backend/cli/src/index.ts:189。

§ 01 · ARCHITECTURE

本地科研工作台的三层结构

从源码看，OpenScience 的边界先由 CLI 入口建立，再由 web 命令启动 server 和浏览器，最后由 server guard 把访问面约束在本机。backend/cli/src/index.ts:55 的 yargs 命令树、backend/cli/src/cli/cmd/web.ts:147 的 server listen、backend/cli/src/server/host-guard.ts:46 的 host 检查形成第一条主链。

▸系统拓扑

openscience CLI → yargs command registry → web command / network options → local Hono server on loopback → SolidJS workspace → agent runtime / providers / science connectors / plugins

91  // the session thk_ token. These SDKs read `<PROVIDER>_API_KEY` straight from
92  // env, so a shell `export OPENAI_API_KEY=sk-...` would otherwise shadow the
93  // managed token and 401 the proxy ("thk_* token not found"). Returns {} unless
94  // both managed spend is on AND the baseURL is the Atlas proxy — genuine BYOK

96  async function managedProxyKey(providerID: string, baseURL: unknown): Promise<{ apiKey?: string }> {
97    const managed =
98      isAtlasProxyBaseURL(baseURL) && (await Config.get().catch(() => undefined))?.billing?.llm === "managed"
99    if (!managed) return {}
100    // Managed wallet routes through OpenRouter ONLY: never attach the wallet's
101    // thk_ token to a first-party proxy (anthropic / openai / google). Those
102    // providers are also dropped from availability (see isProviderAllowed), so
103    // this is belt-and-suspenders — a managed token can only ever reach the
104    // sanctioned OpenRouter (or hosted synsci) route.

54export function isAllowedOrigin(origin: string, extraWhitelist: string[] = []): boolean {
55  if (origin.startsWith("http://localhost:") || origin === "http://localhost") return true
56  if (origin.startsWith("http://127.0.0.1:") || origin === "http://127.0.0.1") return true
57  if (origin === "tauri://localhost" || origin === "http://tauri.localhost") return true
58  // Trusted hosted-UI subdomains (default syntheticsciences.ai, extended via
59  // OPENSCIENCE_CORS_DOMAINS). See matchesAllowedSubdomain.
60  if (matchesAllowedSubdomain(origin)) return true
61  return extraWhitelist.includes(origin)
62}
63
64// Decide whether a NETWORK request is cross-origin and must be rejected. An
65// Origin header (always present on cross-origin fetch and WebSocket upgrades)
66// is checked against the allow-list; when it is absent (same-origin requests
67// and same-/cross-site GET navigations omit it) we fall back to Sec-Fetch-Site
68// and reject only explicit cross-site contexts. Non-browser clients send
69// neither header and are allowed (the loopback bind already gates them).
70export function isCrossOrigin(
71  origin: string | undefined,
72  secFetchSite: string | undefined,
73  extraWhitelist: string[] = [],
74): boolean {
75  if (origin !== undefined) return !isAllowedOrigin(origin, extraWhitelist)
76  return secFetchSite === "cross-site"
77}

176  function pinByokToPublicEndpoint(provider: Info, options: Record<string, any>, publicURL: string) {
177    const effectiveKey =
178      (typeof options["apiKey"] === "string" ? (options["apiKey"] as string) : undefined) ??
179      provider.key ??
180      provider.env.map((key) => Env.get(key)).find((value): value is string => !!value)

187      })

▸已知边界 / 失败模式

  • YouTube 式远端服务不可控时，OpenScience 的 remote well-known config 已经用 backend/cli/src/config/config.ts:88 到 backend/cli/src/config/config.ts:105 做了降级；但每个具体 science connector 的失败策略还需要逐个审。
  • Agent 权限默认很宽：defaults 里 backend/cli/src/agent/agent.ts:55 设置 `* allow`，再叠加用户规则；部署给高风险科研环境时应把项目策略收紧。
  • README 明确说 agent 不是 sandbox；源码里 Host/Origin guard 保护的是本地 server 暴露面，不等于 shell/code execution 隔离。

§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

源码显示 OpenScience 有清楚的本地边界和扩展点，但它也把很多能力集中在一个本地 agent runtime 内。backend/cli/src/index.ts:98 会把凭证注入进程，backend/cli/src/config/config.ts:272 会为配置目录安装 plugin 依赖，backend/cli/src/agent/agent.ts:55 默认权限偏开放；这些都适合个人工作台，但企业环境需要额外策略。

不是执行 sandbox
README 已提示 agent 不隔离；backend/cli/src/server/host-guard.ts:19 保护网络入口，不保护子进程副作用。
插件依赖安装面
backend/cli/src/config/config.ts:261 到 backend/cli/src/config/config.ts:281 会创建 package 并 bun install，本地插件目录需要可信来源。
Provider 配置复杂
backend/cli/src/provider/provider.ts:90 到 backend/cli/src/provider/provider.ts:125 的 managed proxy 逻辑很细，测试缺口会直接影响账单和凭证路径。
连接器可靠性不均
统一 registry 在 backend/cli/src/science/connectors/index.ts:30 注册多个数据库，但每个外部 API 的限流和失败语义仍需单独观察。
