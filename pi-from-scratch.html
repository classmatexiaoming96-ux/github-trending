§ 00 · OVERVIEW

它解决什么，凭什么值得拆

pi-from-scratch 的目标不是做一个功能最全的 agent，而是把生产级 coding agent 的最小骨架摊开：src/agent.ts:89 用一个无限循环表达 agent 的生命线，src/agent.ts:98 把模型流事件接进循环，src/agent.ts:122 把 assistant message 写回 context，src/agent.ts:172 再把工具结果变成下一轮模型输入。这个闭环足够小，但已经包含 tool use、streaming、abort、compaction、session persistence 和测试。

它的教学价值在于每个模块都很薄。src/llm.ts:57 只负责消息格式转换，src/llm.ts:107 只解析一行 SSE，src/tools.ts:24 只做输出截断，src/cli.ts:97 只做 append-only JSONL 持久化。读者可以看到 agent 不是魔法，而是一组状态转换和协议适配。

▸核心数据

▸为什么不是 README 摘要

源码里真正值得看的点出现在边界处理：src/agent.ts:107 在 abort 时丢弃未完成 tool_calls，src/agent.ts:125 遇到 max_tokens 时把错误写回 context，src/tools.ts:88 对 edit 做 0 匹配错误，src/tools.ts:89 对多匹配错误硬失败。这些细节决定一个教学 agent 是否会把 session 搞坏。

▸Context 到 OpenAI messages

57export function contextToOpenAIMessages(context: Context): object[] {
58  const messages: object[] = []
59  if (context.systemPrompt) messages.push({ role: 'system', content: context.systemPrompt })
60
61  for (const msg of context.messages) {
62    if (typeof msg.content === 'string') {
63      messages.push({ role: msg.role, content: msg.content })
64      continue
65    }
66
67    const blocks = msg.content
68    if (msg.role === 'assistant') {
69      const toolCalls: object[] = []
70      let text = ''
71      for (const b of blocks) {
72        if (b.type === 'text') text += b.text
73        else if (b.type === 'tool_use') {

81    } else {

83      for (const b of blocks) {
84        if (b.type === 'tool_result') {
85          messages.push({ role: 'tool', tool_call_id: b.tool_use_id, content: b.content })
86        } else if (b.type === 'text') {
87          messages.push({ role: 'user', content: b.text })
88        }
89      }

▸SSE 增量和 tool_call buffer

流式解析的复杂度集中在 src/llm.ts:107 和 src/llm.ts:144。模型可能把 function arguments 分多次吐出，所以 src/llm.ts:127 先按 index 建 buffer，src/llm.ts:132 追加 JSON 字符串，最后 src/llm.ts:151 尝试 JSON.parse。这个设计解释了为什么 tool_call 事件要等流结束后统一 flush。

107function handleSSELine(
108  data: string,
109  toolCallBuffers: Map<number, { id: string; name: string; argsBuf: string }>,
110): { textDelta: string | null; stopReason: 'end_turn' | 'tool_use' | 'max_tokens' | null } {
111  let chunk: OpenAIChunk
112  try { chunk = JSON.parse(data) as OpenAIChunk } catch { return { textDelta: null, stopReason: null } }
113
114  const choice = chunk.choices[0]
115  if (!choice) return { textDelta: null, stopReason: null }
116
117  let textDelta: string | null = null
118  let stopReason: 'end_turn' | 'tool_use' | 'max_tokens' | null = null
119
120  if (choice.delta?.content) textDelta = choice.delta.content
121
122  // tool_call 增量：按 index 累积 name + arguments 的 partial JSON
123  if (choice.delta?.tool_calls) {
124    for (const tc of choice.delta.tool_calls) {
125      const idx = tc.index ?? 0
126      if (!toolCallBuffers.has(idx)) {
127        toolCallBuffers.set(idx, { id: tc.id ?? `call_${idx}`, name: '', argsBuf: '' })
128      }
129      const entry = toolCallBuffers.get(idx)!
130      if (tc.id) entry.id = tc.id
131      if (tc.function?.name) entry.name = tc.function.name
132      if (tc.function?.arguments) entry.argsBuf += tc.function.arguments
133    }
134  }
135
136  // finish_reason 映射：tool_calls → tool_use，length → max_tokens，stop → end_turn（默认值）
137  if (choice.finish_reason === 'tool_calls') stopReason = 'tool_use'
138  else if (choice.finish_reason === 'length') stopReason = 'max_tokens'
139
140  return { textDelta, stopReason }
141}

§ 05 · RISKS

技术亮点之外，别忽略这些

▸参数验证被有意省略

仓库自己在 src/agent.ts:146 和 src/tools.ts:4 标明教学版不验证 args。生产化时必须在 src/agent.ts:155 之前按 parameters 做 schema validation，否则模型可以把任意结构传给 src/tools.ts:109 的 run_bash。

▸run_bash 权限边界很粗

src/tools.ts:111 直接 exec shell command，只设了 maxBuffer 和 timeout。对于教学足够；对于真实 agent，需要工作目录沙箱、命令 allowlist、环境变量过滤和文件系统权限限制。

▸Context compaction 是条数近似

src/agent.ts:28 和 src/agent.ts:30 用消息数量触发压缩，而不是 token 估算；src/agent.ts:57 还会调用同一个 stream。这个实现讲清概念，但生产版要处理 token cut point、工具回合不可拆分和摘要质量验证。

结论 — pi-from-scratch 适合作为 agent 内核教材，不应直接把 run_bash 和无验证 args 暴露到未隔离生产环境。
