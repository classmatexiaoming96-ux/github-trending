§ 02 · KEY FLOW

关键流程

load_swarm_profile │ env vars + overrides ▼ workflow runtime metadata │ sandbox_mode / paths / reporter backend ▼ main coordinator prompt ├─ create_subagent(role label) ├─ assign_task(output manifest optional) └─ collect_reports(status blocks)

▸配置先合并，再进入提示词

这个顺序让 profile 成为可测试的工程对象：sources/frontieragent/workflows/agent_team/profile.py:173 先解析环境变量占位符，sources/frontieragent/workflows/agent_team/profile.py:175 再应用 overrides，最后由 sources/frontieragent/workflows/agent_team/subagent_runtime.py:151 把可发布路径写进模型可见说明。

这个流程说明 Agent Team 的“团队感”来自运行时约束而不是 prompt 幻觉。sources/frontieragent/workflows/agent_team/profile.py:173 先解析 env placeholders，sources/frontieragent/workflows/agent_team/profile.py:175 再应用 overrides，sources/frontieragent/workflows/agent_team/subagent_runtime.py:145 则给主 Agent 加上 output manifest namespace 提醒。

§ 03 · EDGE CASES

边界 / 失败模式

  • Inline profile 可以绕过文件查找，但仍会走 env-var resolution：sources/frontieragent/workflows/agent_team/profile.py:164。
  • 未知 reporter backend 不会直接炸掉，而是 warning 后回到 fast backend：sources/frontieragent/workflows/agent_team/profile.py:80。
  • container/native 共享 workspace，bwrap 私有 workspace；差异在 sources/frontieragent/workflows/agent_team/subagent_runtime.py:79 和 sources/frontieragent/workflows/agent_team/subagent_runtime.py:119。
  • outputs physical path 和 virtual manifest path 被明确区分：sources/frontieragent/workflows/agent_team/subagent_runtime.py:145 到 sources/frontieragent/workflows/agent_team/subagent_runtime.py:151。
