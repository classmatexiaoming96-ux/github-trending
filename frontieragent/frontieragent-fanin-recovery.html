135    *during* a turn, but agents still running at the start of a new turn

144         * agents created but never assigned → ``[status] no_work_queued``,

146         * all submitted work already collected → ``[status] all_collected``,

148         * at least one session running → wait up to ``timeout`` seconds
149           for the FIRST completion, then drain any others that
150           completed during the wait.
151
152    Reports come back as

154    reason="...">…</report>`` — treat ``incomplete`` / ``failed`` as
155    partial evidence, not a final answer.
156
157    Args:
158        timeout: Max seconds to wait for the first completion when
159                 something is genuinely running. Default 1800 (30 min).
160                 Sub-agents on hard BrowseComp-style questions routinely
161                 take 3-10 minutes — short timeouts are a poll, not a
162                 wait. Pass a smaller value only when you specifically
163                 want a cheap poll.
164
165    Returns:
166        One or more ``<report>`` blocks plus a status line. Status-only
167        outcomes (nothing to wait for / timeout) come back as a single

▸状态短路防止 collect_reports 轮询风暴

collect_reports 有专门的 churn counter。sources/frontieragent/plugins/tools/collect_reports.py:69 记录连续同状态次数，sources/frontieragent/plugins/tools/collect_reports.py:86 渲染 status-only return，sources/frontieragent/plugins/tools/collect_reports.py:111 超过阈值后直接告诉 Agent 停止轮询并 finalize 或派发具体 follow-up。

69def _bump_status_churn(scope: Any, state: str) -> int:
70    """Increment and return the consecutive count for ``state``."""
71    md = getattr(scope, "metadata", None)
72    if md is None:
73        return 1
74    prev_state, count = md.get(_STATUS_CHURN_KEY) or ("", 0)
75    count = count + 1 if prev_state == state else 1
76    md[_STATUS_CHURN_KEY] = (state, count)
77    return count

80def _reset_status_churn(scope: Any) -> None:
81    md = getattr(scope, "metadata", None)
82    if md:
83        md.pop(_STATUS_CHURN_KEY, None)

86def _status_notice(
87    scope: Any,
88    state: str,
89    body: str,
90    *,
91    extra_status: str | None = None,
92    track_churn: bool = True,
93) -> str:
94    """Render a status-only return: ``<report>`` block + ``[status]`` line.
95
96    Every short-circuit return goes through here so SDK consumers
97    parsing ``tool_finished.result_preview`` always find a well-formed
98    ``<report>`` block (see
99    :func:`workflows.agent_team._report_format.format_status_report_block`)
100    — bare free-form status text used to be pasted back to end users
101    verbatim with a parse-failure marker.
102
103    With ``track_churn`` (idle states only), the same state returned
104    more than :data:`_STATUS_CHURN_LIMIT` times in a row swaps the body
105    for a hard stop-polling directive and tags
106    ``reason="<state>_stop_polling"`` so trace consumers can spot the
107    churn at a glance.
108    """
109    reason = state
110    if track_churn:
111        count = _bump_status_churn(scope, state)
112        if count > _STATUS_CHURN_LIMIT:
113            reason = f"{state}_stop_polling"
114            body = (
115                f"This is consecutive '{state}' notice #{count}. STOP "
116                "calling collect_reports — repeating it cannot return "
117                "anything new. Call finalize_answer NOW with your best "
118                "synthesis of the reports already collected, or "
119                "assign_task with a concrete follow-up question if (and "
120                "only if) one is genuinely needed."
121            )
122    else:
123        _reset_status_churn(scope)
124    out = f"{format_status_report_block(reason, body)}\n\n[status] {state}"
125    if extra_status:
126        out += f"\n{extra_status}"
127    return out
