▸领取时写租约，而不是先读再抢

apps/agent/agent/lib/tasks.ts:41 使用 UPDATE...FROM 子查询，把 dueAt、leasedUntil、attempts 和 kind 过滤都放在数据库侧；apps/agent/agent/lib/tasks.ts:55 的 SKIP LOCKED 是多 dispatcher 安全的关键。

28export async function claimDue(
29	limit: number,
30	kinds: { only: readonly string[] } | { except: readonly string[] },
31	leaseMs = LEASE_MS,
32): Promise<LeasedTask[]> {
33	const now = new Date();
34	const until = new Date(now.getTime() + leaseMs);
35
36	const list = "only" in kinds ? kinds.only : kinds.except;
37	if ("only" in kinds && list.length === 0) return [];
38
39	const match = Prisma.sql`t2.kind ${"only" in kinds ? Prisma.sql`IN` : Prisma.sql`NOT IN`} (${Prisma.join(list)})`;
40
41	const claimed = await db.$queryRaw<LeasedTask[]>`
42		UPDATE "agentTask" AS t
43		SET "leasedUntil" = ${until},
44			"startedAt" = COALESCE(t."startedAt", ${now}),
45			"attempts" = t."attempts" + 1
46		FROM (
47			SELECT t2.id FROM "agentTask" AS t2
48			WHERE t2."finishedAt" IS NULL
49				AND t2."dueAt" <= ${now}
50				AND (t2."leasedUntil" IS NULL OR t2."leasedUntil" < ${now})
51				AND t2."attempts" < ${MAX_ATTEMPTS}
52				AND ${match}
53			ORDER BY t2."priority" DESC, t2."dueAt" ASC
54			LIMIT ${limit}
55			FOR UPDATE SKIP LOCKED
56		) AS due
57		WHERE t.id = due.id
58		RETURNING t.id, t."contactId", t."companyId", t.kind, t.reason,
59			t.budget, t.attempts, t.priority, t."dueAt";
60	`;
61
62	return claimed.sort(
63		(a, b) => b.priority - a.priority || a.dueAt.getTime() - b.dueAt.getTime(),
64	);
65}

边界 / 失败模式

  • apps/agent/agent/lib/tasks.ts:67 退休耗尽任务，避免坏任务永远循环。
  • apps/api/src/agent/agent-trigger.service.ts:195 poke 失败只 debug，cron 仍会兜底。
  • apps/agent/test/tasks.integration.spec.ts:97 验证租约未过期不会重复领取。

共享数据库包给这条队列补上了跨 app 的类型锚点：packages/db/src/agent-tasks.ts:1 是 AgentTask 类型入口，packages/db/src/agent-tasks.ts:14 把 direct lane 任务固定成 brand 和 portrait，避免 API 层与调度器各自维护一套字符串约定。读源码时这能解释为什么 visible lane 可以批量处理，而研究 lane 必须进入会话。

Subject 建模也在共享包里收口，packages/db/src/agent-tasks.ts:18 到 packages/db/src/agent-tasks.ts:22 将任务对象限制在 company、contact、workspace 三类实体。这个限制对 CRM 很关键，因为重试、租约和 completion token 都必须知道结果应该写回哪类业务对象。

真正的运行时恢复能力来自任务表和客户端的组合：packages/db/src/agent-tasks.ts:31 提供类型导出，packages/db/src/client.ts:55 则是各进程共享 Prisma 访问的入口。只要任务状态已经落库，dispatcher 重启后仍然能通过 dueAt、leasedUntil 和 attempts 重新判断下一步，而不是依赖内存队列。
