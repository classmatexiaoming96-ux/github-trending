  84     * Tail the SSE stream. Uses fetch + a reader (not EventSource) so we control the
  85     * lifecycle — the server self-closes once neither a turn nor the harness is in
  86     * flight, and we don't auto-reconnect while idle.

  88    const startStream = useCallback(async () => {
  89      if (abortRef.current) return; // already tailing
  90      const ac = new AbortController();
  91      abortRef.current = ac;
  92      try {
  93        const res = await fetch(`/api/projects/${projectId}/chat/stream`, {
  94          signal: ac.signal,
  95          headers: { Accept: 'text/event-stream' },
  96        });
  97        if (!res.ok || !res.body) return;
  98        const reader = res.body.getReader();
  99        const decoder = new TextDecoder();
 100        let buffer = '';
 101        for (;;) {
 102          const { value, done } = await reader.read();
 103          if (done) break;
 104          buffer += decoder.decode(value, { stream: true });
 105          const events = buffer.split('\n\n');
 106          buffer = events.pop() ?? '';
 107          for (const evt of events) {
 108            const line = evt.split('\n').find((l) => l.startsWith('data:'));
 109            if (!line) continue;
 110            try {
 111              const payload = JSON.parse(line.slice(5).trim());
 112              if (payload.messages) setRows(payload.messages);
 113              if (payload.project) setProject(payload.project);
 114              if (payload.harness) setHarness(payload.harness);
 115            } catch {
 116              /* ignore partial/non-json */
 117            }
 118          }
 119        }
 120      } catch {
 121        /* aborted or network — ignore */
 122      } finally {
 123        if (abortRef.current === ac) abortRef.current = null;
 124        // Settle after the stream closes; if the harness kicked off (or is still
 125        // running) the effect below reopens the stream.
 126        refetch();
 127      }
 128    }, [projectId, refetch]);
§ 02 · KEY FLOW

mount → GET seeds → pending/running → fetch SSE

§ 03 · EDGE CASES

边界 / 失败模式

  • 解析失败被忽略，下一帧完整快照会自然修复。
  • 连接超时后依靠 refetch 和运行态 effect 重新进入。
  • 400ms 多表查询在高并发下可能成为数据库压力源。
