 21function write(root, fingerprints, note) {

§ 02 · KEY FLOW

关键流程

addedLines + detectors + fingerprint + baseline filter + ledger trend

Ratchet 的噪音控制来自三处：sources/ratchet/hooks/lib/detect.js:177 支持本地 suppress，sources/ratchet/hooks/lib/baseline.js:33 支持 repo 级 accepted 集合，sources/ratchet/hooks/ratchet-guard.js:125 支持 session 内 reported 去重。三层合起来让工具能长期打开，而不是每次都重复提醒历史问题。

▸规则层的扩展入口

如果要扩展 Ratchet，应该先看 sources/ratchet/hooks/lib/detect.js:200 的 pattern scanner 和 sources/ratchet/hooks/lib/detect.js:209 的 wrapper scanner，再看 sources/ratchet/hooks/lib/detect.js:231 的 abstraction scanner。它们共享 sources/ratchet/hooks/lib/detect.js:194 的 finding 构造函数和 sources/ratchet/hooks/lib/detect.js:275 的 fingerprint 规则；新增检测若不能稳定 fingerprint，就会让 baseline 与 session 去重失效。

§ 03 · EDGE CASES

边界 / 失败模式

  • sources/ratchet/hooks/lib/changes.js:35 到 sources/ratchet/hooks/lib/changes.js:41 解析 JSON 失败会返回空依赖，manifest 语法坏掉时不会给误报。
  • sources/ratchet/hooks/lib/detect.js:231 的 YAGNI 依赖 countImplementations，语言不匹配时可能漏报，适合做建议而非硬阻断。
  • sources/ratchet/hooks/lib/state.js:75 依赖 git ls-files；未跟踪的大量生成文件不会进入 snapshot，这符合“看项目真实提交面”的定位。
