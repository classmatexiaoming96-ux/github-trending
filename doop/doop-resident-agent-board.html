Doop Resident Agent：从设计卡片到后台执行

拆解 Doop 如何把 Board、角色 pipeline、反馈队列和 resident worker 串成可恢复的 agent 流程。

01

后台 agent 的调度边界

不是无限自动执行

resident agent 的第一道边界是配置和并发。server/resident.ts:42 在缺少 OpenAI key 时跳过运行，server/resident.ts:56 使用 runningCanvases 防止同一 canvas 并发，server/resident.ts:69 的 sweep 只处理等待中的 work，server/resident.ts:75 从 pendingWorkAgents 取任务。这让后台自动化更像队列 worker，而不是浏览器里突然出现的自由 agent。

server/resident.ts:69后台 sweep 限制每个 canvas 的运行
69/** Work every agent that has something waiting, one at a time. Re-checking the
70 *  queue between runs is what carries a card into its next pipeline stage. */
71async function sweep(canvasId: string) {
72  running.add(canvasId)
73  try {
74    for (let i = 0; i < MAX_SWEEP_RUNS; i++) {
75      const next = actions.pendingWorkAgents(canvasId)[0]
76      if (!next) break
77      await runAgent(canvasId, next)
78    }
79  } finally {
80    running.delete(canvasId)
81    if (queued.delete(canvasId)) onFeedback(canvasId)
82  }
83}

02

任务卡片进入队列

Board 是 agent pipeline 的产品入口

用户从 Board 创建卡片，src/components/Board.tsx:119 收集 brief，src/components/Board.tsx:125 通过 API 入队；服务端的 server/actions.ts:569 创建 queued card，server/actions.ts:605 写成 task event，server/actions.ts:616 广播。这个路径让设计需求先成为产品状态，再交给 agent，而不是直接塞进一次模型调用。

server/actions.ts:569用户卡片变成 agent queued work

570  canvasId: string,
571  title: string,
572  from: string,
573  agents?: unknown,
574  attachments?: unknown,
575): AgentTask | undefined {
576  const clean = title.trim().slice(0, 200)
577  if (!clean || !store.getCanvas(canvasId)) return undefined
578  const pipeline = normalizePipeline(agents)
579  /* reference-image frame ids: only frames that actually live on this canvas */
580  const refs = (Array.isArray(attachments) ? attachments : [])
581    .filter((a): a is string => typeof a === 'string')
582    .filter((id, i, arr) => arr.indexOf(id) === i && store.getFrame(id)?.canvasId === canvasId)
583    .slice(0, 4)
584  const list = taskLog.get(canvasId) ?? []
585  const duplicate = list.find(
586    (t) =>
587      t.queuedBy === from &&
588      !t.endedAt &&
589      t.status === clean &&
590      pipelineOf(t).join(',') === pipeline.join(',') &&
591      (t.attachments ?? []).join(',') === refs.join(','),
592  )
593  if (duplicate) return duplicate

595    id: nanoid(8),
596    agentName: '',
597    color: colorFor(from),
598    status: clean,
599    startedAt: Date.now(),
600    queuedBy: from,
601    pipeline,
602    stage: 0,
603    ...(refs.length > 0 ? { attachments: refs } : {}),
604  }
605  list.unshift(card)
606  if (list.length > 100) list.length = 100
607  taskLog.set(canvasId, list)

609  broadcast(canvasId, { type: 'task', task: card })

613    `queued a card for ${pipeline.map(roleName).join(' → ')}: “${clean}”`,

615  /* the resident agents pick queued cards up instantly (no-op without a key) */

03

反馈和评论汇入同一轮

Agent 看到的是合并后的工作包

runAgent 开始后，server/resident.ts:176 领取任务反馈，server/resident.ts:179 领取元素评论，server/resident.ts:181 领取卡片任务，随后 server/resident.ts:186 写入 heartbeat。它把三种输入合并到同一轮推理里，避免“反馈系统”和“卡片系统”变成两个互相抢状态的执行器。

server/resident.ts:170runAgent 合并反馈、评论和卡片任务
170async function runAgent(canvasId: string, agentName: string) {
171  const anthropic = getClient()
172  if (!anthropic) return
173  const role = roleByAgentName(agentName) ?? roleById(DEFAULT_ROLE_ID)!
174  const actor = actions.resolveActor({ name: role.name, kind: 'agent' })
175
176  /* claim this agent's open work — the UI flips to "picked up" instantly.
177     Claiming happens before the try so an agent with nothing to do never
178     shows up in presence. */
179  const claimed = actions.takeFeedbackFor(canvasId, role.name)
180  const comments = actions.takeAgentCommentsFor(canvasId, role.name)
181  const cards = actions.takeQueuedCardsFor(canvasId, role.name)
182  if (claimed.length === 0 && comments.length === 0 && cards.length === 0) return
183
184  /* presence otherwise only refreshes on tool activity, and the sweep's TTL
185     is shorter than a big generation turn */
186  const heartbeat = setInterval(() => actions.heartbeatAgent(canvasId, actor), 15_000)

角色模型

预设角色让队列更像设计团队

虽然角色定义在共享类型里，但实际消费发生在服务端和 Board：server/resident.ts:142 根据角色选择策略，server/resident.ts:226 把路由结果写入上下文，src/components/Board.tsx:209 让用户选择 pipeline。结合 server/actions.ts:546 的 endAgentTasks，这套设计支持“某个角色完成某段工作”的可见过程。
