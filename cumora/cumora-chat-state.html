§ 02 · KEY FLOW

关键流程

REST list conversations → WebSocket ticket auth → tenant-filtered Redis bridge → message / reaction / poll / doc events → zustand stores render one team inbox

doc 协作路径展示了同一 WS 如何服务非聊天状态：server/src/ws.ts:163 的 handleDocFrame 处理 subscribe/update/awareness，server/src/ws.ts:213 到 server/src/ws.ts:235 把 Yjs update 和 awareness 分开广播。

§ 03 · EDGE CASES

边界 / 失败模式

  • server/src/ws.ts:49 的 WS_MAX_BUFFERED_BYTES 与 TERMINATE cap 防止慢客户端造成 OOM。
  • server/src/ws.ts:65 的 resetHumanPresenceOnBoot 清理 stale avail，人类 presence 不依赖旧进程状态。
  • server/src/ws.ts:143 的 docCompanyFor 返回 opaque null，避免泄露不可见文档是否存在。
