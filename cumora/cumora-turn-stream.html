▸流式读取有 idle 与 wall 双 timeout

server/src/agents/turn-stream.ts:110 到 server/src/agents/turn-stream.ts:138 通过 nextWithTimeout 控制每次 iterator.next，既防止长时间没有 event，也防止流一直滴答但永远不结束。这对 agent turn 很关键，因为每个 turn 都占用运行时并可能阻塞后续 wake。

§ 02 · KEY FLOW

关键流程

runAgentTurn → loadInbox / loadMemory / loadContext → Responses stream → pendingTools → executePodTool or cumora CLI → side effect + status + cost ledger

这一链路的关键边界分别在 server/src/agents/turn.ts:141 的 loadInbox wrapper、server/src/agents/runtime/inproc-client.ts:105 的 unread tail SQL、server/src/agents/tools.ts:147 的 pull_group 动作和 server/src/agents/tools.ts:180 的 react 动作。
