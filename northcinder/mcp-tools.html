本地 MCP 与远端只读桥 深度解析

这一页拆 NorthCinder 的工具面：本地 server 可以进入授权和 checkout，remote bridge 只允许 search 与 trust。关键不是工具数量，而是权限按进程边界拆开。

§ 00 · IMPORT CHAIN

导入链与契约

本地 server 的依赖注入在 client/src/server.ts:113 暴露 authorizations、checkout、audit、profile、watches 与 orders；remote bridge 的文件头在 remote/src/mcp-server.ts:1 直接说明无授权与 checkout，remote/src/mcp-server.ts:25 还强调 stateless。搜索结果被本地缓存于 client/src/server.ts:371，用于后续 authorization 绑定真实 offer。

76/**
77 * Sanitize an upstream-service error before it reaches an authenticated
78 * third-party MCP client on this PUBLIC bridge.
79 *
80 * `service-client.ts` (mirrored from the trusted local stdio client, where
81 * this detail is fine) builds `service_unreachable` messages containing the
82 * real `NORTHCINDER_SERVICE_URL` + path, and `service_error`/HTTP-error messages
83 * that can echo up to 200 chars of the upstream response body. Neither
84 * infra topology nor upstream internals should ever reach an arbitrary
85 * API-key holder — do not log the detail either, because production log
86 * access is broader than the upstream credential boundary; return a generic,
87 * bounded message. Every other error code (invalid_query, invalid_merchant,
88 * invalid_service_response, …) is already safe to pass through verbatim —
89 * those messages describe the caller's OWN input or a schema mismatch, not
90 * upstream infra.
91 */
92function sanitizeServiceError(error: ToolFailure): ToolFailure {
93  const isUnreachable = error.code === "service_unreachable";
94  const isUpstreamHttpError = error.message.startsWith("service HTTP ");
95  if (!isUnreachable && !isUpstreamHttpError) return error;
96  console.error(`[northcinder-remote] upstream error suppressed from client response (${error.code})`);
97  return {
98    code: error.code,
99    message: isUnreachable ? "configured engine unavailable" : "configured engine error",
100  };
101}

107/**
108 * Verify that the service accounted for every adapter it says is registered.
109 * Keep this consumer-local rather than trusting the local client package: the
110 * self-hosted bridge is independently deployable and must not silently bless an
111 * omitted (or duplicated) store status.
112 */
113function verifyStoreCoverage(registeredStores: readonly string[] | undefined, statuses: readonly { store: string }[]) {
114  if (registeredStores === undefined) return { verified: "not_applicable" as const, missing: [], unexpected: [] };
115  const registered = new Set(registeredStores);
116  const counts = new Map<string, number>();
117  for (const status of statuses) counts.set(status.store, (counts.get(status.store) ?? 0) + 1);
118  const missing = [...registered].filter((store) => !counts.has(store)).sort();
119  const unexpected = [...counts.keys()].filter((store) => !registered.has(store) || (counts.get(store) ?? 0) !== 1).sort();
120  return { verified: missing.length === 0 && unexpected.length === 0, missing, unexpected };
121}
§ 02 · KEY FLOW

关键流程

client search -> verify ranking -> audit remote search -> sanitize upstream error -> verify ranking -> return read-only result remote never registers request_purchase_authorization / approve_purchase / complete_checkout

本地工具链从 client/src/server.ts:507 注册 search_products，client/src/server.ts:648 开始 profile 工具，client/src/server.ts:904 开始 watches；remote 只在 remote/src/mcp-server.ts:123 创建 server。这种差异是安全边界本身，而不是部署形态的偶然结果。

§ 03 · EDGE CASES

边界 / 失败模式

  • client/src/server.ts:572 接受 browser observations，但后续购买前仍会因 native revalidation 被拒。
  • remote/src/mcp-server.ts:95 对任意错误消息做截断，避免把内部异常原样暴露给 API key 持有人。
  • client/src/server.ts:285 的 local trust evidence 只展示，不影响排序，防止本地历史污染 ranking。
