§ 02 · TYPESCRIPT

TypeScript extractor 的语义取舍

▸calleeKey 决定调用身份

src/languages/typescript.ts:76 的 calleeKey 是调用图质量的核心：identifier 直接返回函数名，this.method 会被归到当前 class，object.property 会生成 object.property。src/languages/typescript.ts:84 明确跳过 subscript expression，这避免把动态 key 误判成稳定调用。

src/languages/typescript.ts · L76-107TypeScript
76function calleeKey(node: SyntaxNode, className: string | null): string | null {
77  if (node.type === "identifier") return node.text;
78  if (node.type === "this") return className;
79
80  if (
81    node.type === "member_expression" ||
82    node.type === "subscript_expression"
83  ) {
84    if (node.type === "subscript_expression") return null;
85
86    const object = node.namedChild(0);
87    const property =
88      namedChildren(node).find(
89        (c) =>
90          c.type === "property_identifier" ||
91          c.type === "private_property_identifier",
92      ) ?? null;
93    if (!object || !property) return null;
94
95    const propName = property.text;
96    if (object.type === "this" && className) {
97      return `${className}.${propName}`;
98    }
99    if (object.type === "identifier") {
100      return `${object.text}.${propName}`;
101    }
102    if (className) return `${className}.${propName}`;
103    return propName;
104  }
105
106  return null;
107}

§ 05 · RISKS

▸动态调用仍是盲区

src/languages/typescript.ts:84 跳过 subscript expression 是正确的保守选择，但也意味着 registry[ name ]()、依赖注入容器和框架装饰器不会被完整展开。这个工具适合 review call flow，不适合替代类型系统。
