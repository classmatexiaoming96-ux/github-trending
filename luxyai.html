§ 00 · OVERVIEW

它解决什么，凭什么值得拆

LuxyAI 的公开仓库在 README 里已经改名为 Flawless，源码目标是 Kubernetes/cloud 场景下的 AgenticOps 控制面。它不是只把告警丢给 LLM，而是把动作目录、证据评分、MCP 只读探针、审批和执行后验证拆开：agents/remediation_engine.py:16、agents/remediation_engine.py:147、agents/remediation_engine.py:220、agents/remediation_engine.py:258、agents/remediation_engine.py:415 这些入口说明模型只做规划，稳定动作、证据权重和执行边界仍由平台代码维护。

真正值得拆的是它把 SRE workflow 写成可审计闭环。agents/sre_graph.py:69 定义状态，agents/sre_graph.py:158 建 trace，backend/app/application.py:7623 在失败后根据新证据重规划；这意味着“修复失败”不会只返回一句抱歉，而会进入新的证据分支。

▸核心数据

架构模式
SRE Graph + EvidenceRunbookEngine + Kubernetes MCP server + FastAPI 控制面。
核心抽象

性能/精度数据
项目未给 benchmark；测试覆盖更强调故障分类、权限、patch 合法性和重规划去重。

§ 01 · ARCHITECTURE

控制面拓扑：证据先行，动作后置

主路径可以概括为 Alert 进入 agents/sre_graph.py:69 的状态机，scope 由 agents/sre_graph.py:88 归一化，Pod 证据由 agents/sre_graph.py:103 和 agents/sre_graph.py:114 筛选，然后进入 runbook scoring 与 remediation plan。这个路径的设计避免了“模型看到一段日志就直接执行”的常见风险。

▸系统拓扑

Prometheus/Rancher Alert\n → SRE Graph state\n → MCP evidence probes\n → EvidenceRunbookEngine scoring\n → guarded remediation preview\n → approval / dry-run / execute\n → verify symptom and persist lineage

▸模块清单

模块边界比较清楚：agents/remediation_engine.py:415 负责证据到 runbook 的排序，mcp_servers/k8s_mcp_server.py:620 负责 Kubernetes 读写工具暴露，backend/app/application.py:7623 负责运行时失败后的重规划，tests/test_remediation_engine.py:37 则把分类和执行约束变成回归测试。

EvidenceRunbookEngine
从 alert、diagnosis、pod_status、events、logs 五类来源加权，输出 runbook_id、confidence、diagnostics 和 success criteria。
K8s MCP Server
在集群内优先 ServiceAccount，开发机回退 kubeconfig，所有写操作都有 dry_run 和局部 schema 校验。
Runtime Replan
执行失败后把 runtime evidence、失败指纹和动作目录重新喂给 planner，禁止重复同一失败动作。

▸动作目录是安全边界

动作目录在 agents/remediation_engine.py:16 开始，给每个动作绑定 risk、auto_allowed、rollback 和 description；后面的 backend/app/application.py:7708 又根据已证明根因收窄 allowed actions。两层约束让 LLM 即使提出动作，也必须落在平台能解释和审计的 vocabulary 内。

§ 06 · RISKS

技术亮点之外，别忽略这些

第一，mcp_servers/k8s_mcp_server.py:63 允许 insecure-skip-tls-verify 的 kubeconfig 路径，开发便利但生产需要配置企业 CA。第二，backend/app/application.py:7672 的 LLM prompt 很长，复杂故障下仍可能受模型上下文和结构化 JSON 稳定性影响。第三，agents/remediation_engine.py:387 暴露完整 action catalog 给 planner，后续要持续维护动作语义和 rollback 说明。

亮点

风险
仓库初始提交体量很大，生产成熟度还要看真实集群接入、RBAC 最小权限和长期运行记录。
