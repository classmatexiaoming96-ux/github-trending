核心判断

Resident Agent 队列

后台 resident agent 的关键不是“自动跑”，而是它先限制每个 canvas 只有一个运行实例。server/resident.ts:56 到 server/resident.ts:67 用 set 去重，server/resident.ts:69 的 sweep 会捞取等待中的任务，server/resident.ts:75 只为 pendingWorkAgents 建任务。真正执行时，server/resident.ts:176、server/resident.ts:179 和 server/resident.ts:181 会把反馈、评论、卡片任务合并到同一轮 prompt。

70 *  queue between runs is what carries a card into its next pipeline stage. */
71async function sweep(canvasId: string) {
72  running.add(canvasId)
73  try {
74    for (let i = 0; i < MAX_SWEEP_RUNS; i++) {

深度阅读入口

MCP 工具面从工具注册、上下文绑定、截图校验到 iframe HTML 修改。 Resident Agent 队列任务卡片、角色 pipeline、反馈队列和后台调度如何衔接。 实时与访问控制REST、WebSocket、presence、访问权限和测试覆盖的组合。

值得借鉴

Doop 最可复用的设计是把 agent 协作变成产品内状态机：server/actions.ts:569 接住用户发起的卡片任务，server/resident.ts:75 把任务转给后台 agent，server/mcp.ts:907 让 agent 修改 frame，src/lib/ws.ts:51 再把结果推回浏览器。对任何“AI + 可编辑画布”产品来说，这比单纯嵌入模型调用更接近生产系统。

风险边界

当前值得继续审计的是权限和 HTML 执行边界：server/index.ts:440 的 auth middleware 足够集中，但 server/mcp.ts:922 这类 HTML 追加工具需要配合 CSP、sandbox 和 asset 策略；src/components/FrameView.tsx:147 的元素检查桥也应继续确认 postMessage 来源。已有 tests/access.test.ts:126 的未授权 MCP 测试，但 frame 内容安全还可以补更专门的用例。
