§ 00 · Source-level Observatory

claude-code-merge-queue 本地合并队列

这个项目解决的是 parallel Claude Code agents 的最后一公里：Claude 原生 worktree 已经把多个 agent 隔离开，但 build、test、rebase、push、dev checkout 仍然共享本机资源。它用零运行时依赖的 TypeScript CLI，把 land/build/sync/preview/hook/pre-push 串成一套本地交通灯。

§ 00 · OVERVIEW

它解决什么，凭什么值得拆

项目的核心判断很朴素：Claude Code 的 --worktree 让每个 agent 有自己的目录，但没有解决多个 agent 同时抢同一个 integration branch、同一个 build/test 资源、同一个 dev checkout 的问题。源码入口 src/bin/claude-code-merge-queue.ts:31 把 init、hook、land、sync、promote、preview、build-lock、check-push 都收在一个 CLI 里；配置层 src/lib/config.ts:19 又把 branchPrefix、worktreeSuffix、integrationBranch、checkCommand 等差异外置，所以它不是单仓库脚本，而是可迁移的本地 agent 交通系统。

最值得拆的地方，是它没有用“让 agent 遵守说明”当可靠性基础。landing 队列在 src/land.ts:78 获取跨 worktree FIFO lock，pre-push 在 src/lib/check-push.ts:52 阻断绕过队列的直推，WorktreeCreate hook 在 src/hooks/worktree-create.ts:76 把 Claude 原生 worktree 创建接管成 numbered lanes，sync 在 src/sync.ts:139 负责把主 checkout 快进到刚落地的 commit。它把人类流程约定变成了文件锁、git hook、环境变量和测试门禁。

▸核心数据

架构模式
Node CLI + Git worktree + FIFO lock + Husky pre-push hook。关键状态放在 git、tmpdir 和配置文件里，没有服务端。
核心抽象

§ 01 · ARCHITECTURE

本地 Agent 交通灯：三把锁和两个钩子

架构可以分成四层。第一层是 CLI 调度，src/bin/claude-code-merge-queue.ts:196 用一个 switch 分派所有子命令，并且在 src/bin/claude-code-merge-queue.ts:259 直接把 check-push 暴露给 git hook。第二层是配置，src/lib/config.ts:87 定义默认 branchPrefix、worktreeSuffix、symlinks 和 buildOutputDirs，src/lib/config.ts:196 加载用户 repo 的 config 并做校验。第三层是队列锁，src/lib/queue-lock.ts:73 创建 per-repo/per-queue 的 FIFO mutex。第四层是 hook 和同步，src/hooks/worktree-create.ts:179 响应 Claude 的 WorktreeCreate 事件，src/sync.ts:175 fetch 之后只做 ff-only。

▸系统拓扑

claude --worktree → WorktreeCreate hook (src/hooks/worktree-create.ts:179) → lane/N + symlinked env/node_modules (src/hooks/worktree-create.ts:119) → build-lock queue (src/build-lock.ts:1) → land FIFO queue (src/land.ts:78) → pre-push gate (src/lib/check-push.ts:76) → sync main checkout (src/sync.ts:203)

▸CLI 是薄调度，状态在底层模块

CLI 自身不保存队列状态，而是把每个命令委托给模块：src/bin/claude-code-merge-queue.ts:222 跑 land，src/bin/claude-code-merge-queue.ts:224 跑 sync，src/bin/claude-code-merge-queue.ts:253 跑 preview，src/bin/claude-code-merge-queue.ts:255 跑 build-lock。这让可测试性更好，因为 lock、hook、sync 都能在 test 目录里独立构造 scratch repo。

▸QueueLock：用硬链接原子抢锁

src/lib/queue-lock.ts:73 先用 git common dir 计算 repoKey，确保同一个 repo 的所有 worktree 命中同一个队列目录；src/lib/queue-lock.ts:103 每轮 prune dead tickets；src/lib/queue-lock.ts:140 用 linkSync 把临时文件硬链接成 lock 文件，借文件系统原子性避免两个进程同时持锁。它不是 timeout 锁，而是用 src/lib/queue-lock.ts:88 的 PID liveness 判断 holder 是否还活着。

73export function createQueueLock(queueName: string): QueueLock {
74  const QUEUE_DIR = join(
75    tmpdir(),
76    `claude-code-merge-queue-${queueName}-queue-${createHash("sha1").update(repoKey()).digest("hex").slice(0, 12)}`,
77  );
78  const TICKETS_DIR = join(QUEUE_DIR, "tickets");
79  const LOCK_FILE = join(QUEUE_DIR, "lock");
80  mkdirSync(TICKETS_DIR, { recursive: true });
81
82  const lane = basename(process.cwd());
83  const ME = process.pid;
84  const TICKET_TS = Date.now();
85  const TICKET_NAME = `${TICKET_TS}-${ME}`;
86  const TICKET_FILE = join(TICKETS_DIR, TICKET_NAME);
87
88  function alive(pid: number): boolean {
89    if (!pid || pid === ME) return pid === ME;
90    try {
91      process.kill(pid, 0);
92      return true;
93    } catch (e) {
94      return (e as NodeJS.ErrnoException).code === "EPERM"; // exists but owned by someone else
95    }
96  }
97
98  function pidOf(name: string): number {
99    const dash = name.lastIndexOf("-");
100    return dash === -1 ? 0 : Number(name.slice(dash + 1));
101  }
102
103  function pruneDeadTickets(): string[] {
104    let names: string[];
105    try {
106      names = readdirSync(TICKETS_DIR);
107    } catch {
108      return [];
109    }
110    const live: string[] = [];
111    for (const name of names) {
112      if (alive(pidOf(name))) {
113        live.push(name);
114      } else {
115        try {
116          unlinkSync(join(TICKETS_DIR, name));
117        } catch {
118          /* someone else cleaned it */
119        }
120      }
121    }
122    live.sort((a, b) => {
123      const [ta, pa] = a.split("-").map(Number) as [number, number];
124      const [tb, pb] = b.split("-").map(Number) as [number, number];
125      return ta - tb || pa - pb;
126    });
127    return live;

▸WorktreeCreate hook：把 Claude 的原生隔离接入 lane 规范

77  // Clean up administrative entries for worktrees whose directories are
78  // already gone (e.g. someone `rm -rf`'d one instead of `git worktree
79  // remove`) so reusing that lane number's branch name doesn't fail with
80  // "already checked out elsewhere."
81  tryGit(["worktree", "prune"], mainTop);
82
83  const repoName = basename(mainTop);
84  let lane = 0;
85  for (;;) {
86    lane += 1;
87    if (lane > MAX_LANE_ATTEMPTS) {
88      throw new Error(`could not claim a lane after ${MAX_LANE_ATTEMPTS} attempts — is mainTop ('${mainTop}') actually the repo root?`);
89    }
90    const wt = join(dirname(mainTop), `${repoName}${cfg.worktreeSuffix}${lane}`);
91    if (existsSync(wt)) continue; // still claimed — try the next lane
92
93    const branch = `${cfg.branchPrefix}${lane}`;
94    const branchExists = tryGit(["show-ref", "--verify", "--quiet", `refs/heads/${branch}`], mainTop).ok;
95
96    // Base every new lane on the main checkout's own current HEAD — never on
97    // origin/integrationBranch. The main checkout is kept fast-forwarded by
98    // `sync` precisely so its local HEAD IS the trusted, up-to-date view;
99    // reading origin directly instead can be *behind* local HEAD (a commit
100    // made here but not yet pushed) and silently drop it from every new
101    // lane. That's not a hypothetical: it breaks the literal Quickstart —
102    // `init` writes claude-code-merge-queue.config.mjs/CLAUDE.md/.claude locally, and the
103    // very first lane created before that commit is pushed anywhere would
104    // otherwise come up with none of it.
105    let add;
106    if (branchExists) {
107      add = tryGit(["worktree", "add", wt, branch], mainTop);
108    } else {
109      add = tryGit(["worktree", "add", wt, "-b", branch], mainTop);
110    }
111
112    if (!add.ok) {
113      // Someone else claimed this exact lane between our existsSync check
114      // and `git worktree add` — the same race a `mkdir` guards against.
115      // Try the next one.
116      continue;
117    }
118
119    for (const rel of cfg.symlinks) {
120      const src = join(mainTop, rel);
121      const dest = join(wt, rel);
122      if (!existsSync(src) || existsSync(dest)) continue;
123      try {
124        mkdirSync(dirname(dest), { recursive: true });
125        symlinkSync(src, dest);
126      } catch {
127        /* best-effort — a missing symlink degrades to "run npm install," not a hard failure */
128      }
129    }
130
131    return { wt, branch, lane };
132  }

§ 03 · KEY FLOW

关键流程：从 lane 创建到主 checkout 更新

完整路径是：Claude 触发 WorktreeCreate hook，hook 创建 lane worktree；agent 在 lane 中提交；agent 执行 land；land 拿 FIFO 锁、fetch、rebase、push；pre-push hook 运行 checkCommand；push 成功后 land 调 sync，让主 checkout ff-only 到最新。这里每一步都能在源码里找到硬边界：src/hooks/worktree-create.ts:197 输出 worktree path，src/land.ts:79 等队列，src/lib/check-command.ts:60 执行 checkCommand，src/sync.ts:177 只允许 ff-only merge。

▸Landing path

lane branch → discard regenerable dirt (src/land.ts:65) → createQueueLock("land") (src/land.ts:78) → git fetch + rebase (src/land.ts:95, src/land.ts:99) → git push with landing env (src/land.ts:107) → sync main checkout (src/land.ts:126)

▸Sync path

main checkout → verify current branch == integrationBranch (src/sync.ts:163) → fetch origin (src/sync.ts:175) → merge --ff-only (src/sync.ts:177) → refresh dependencies if lockfile changed (src/sync.ts:75)

▸亮点：同一套 liveness 模式复用三次

queue lock 在 src/lib/queue-lock.ts:88 用 PID 判断 ticket/holder；ephemeral resource 在 src/lib/ephemeral.ts:56 用 ClaimRegistry 保存 claim，并在 src/lib/ephemeral.ts:110 先清理 orphan 再创建新资源；WorktreeCreate hook 则用 “worktree path 是否存在 + git worktree add 原子性” 代替 PID。三个地方的共同点是：不靠 magic timeout。

56export class ClaimRegistry {
57  private readonly dir: string;
58
59  constructor(registryDir: string) {
60    this.dir = registryDir;
61    mkdirSync(this.dir, { recursive: true });
62  }
63
64  record(claim: Claim): void {
65    writeFileSync(join(this.dir, claim.id), JSON.stringify(claim));
66  }
67
68  release(id: string): void {
69    try {
70      unlinkSync(join(this.dir, id));
71    } catch {
72      /* already gone */
73    }
74  }
75
76  /** Every claim whose owning PID is no longer alive — safe to destroy. */
77  orphans(): Claim[] {
78    let names: string[];
79    try {
80      names = readdirSync(this.dir);
81    } catch {
82      return [];
83    }
84    const found: Claim[] = [];
85    for (const name of names) {
86      try {
87        const claim = JSON.parse(readFileSync(join(this.dir, name), "utf8")) as Claim;
88        if (!alive(claim.pid)) found.push(claim);
89      } catch {
90        /* unreadable claim file — leave it, don't guess */
91      }
92    }
93    return found;
94  }

97/**
98 * Run `fn` against a freshly created resource, prune any orphans left by a
99 * previous crashed run first, and always release the claim — including on
100 * a thrown error. If THIS process is killed before the `finally` runs, the
101 * resource isn't leaked forever: the next call to `withEphemeralResource`
102 * (in the next test run, from any lane) prunes it via `orphans()` before
103 * creating its own.
104 */
105export async function withEphemeralResource<T>(
106  provider: EphemeralResourceProvider<T>,
107  registry: ClaimRegistry,
108  fn: (resource: T) => Promise<void>,
109): Promise<void> {
110  for (const orphan of registry.orphans()) {
111    await provider.destroyOrphan(orphan);
112    registry.release(orphan.id);
113  }
114
115  const id = `${Date.now()}-${process.pid}`;
116  const claim: Claim = { id, pid: process.pid, createdAt: Date.now() };
117  registry.record(claim);
118
119  const resource = await provider.create();
120  try {
121    await fn(resource);
122  } finally {
123    await provider.destroy(resource);
124    registry.release(id);
125  }
126}

▸风险：本地工具不是安全边界

pre-push gate 能挡误操作，但 src/lib/check-push.ts:48 暴露 emergency env var，README 也承认它不是 adversarial security boundary。sync 的 src/sync.ts:91 会在 lockfile changed 时跑 package manager install，这对共享 node_modules 是必要的，但 src/sync.ts:81 也特意检查 dependency removal，避免把旧 lane 依赖删掉。

强项
把并发 agent 的冲突点缩成本地可验证机制：FIFO lock、pre-push、ff-only sync、worktree hook。
限制
只协调一台机器；两台机器同时推仍回到 git 非 fast-forward 语义。
强项
大量测试使用真实 git repo、真实 child process、真实 hook wiring，覆盖工程事故而非只测 happy path。
限制
如果 checkCommand 是空壳，队列只能保证“跑过检查”，不能保证检查真的有价值。
