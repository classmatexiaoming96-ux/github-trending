沙箱监管

一句话定位："Build me a todo app" → 几秒后 app 出现在自己的预览链接上——sandboxd 把这个流程开源化。它不是给你的 AI coding agent 用的，而是给做 AI coding 产品的公司用的：你要集成的是它的 HTTP API，不是跑 agent。

核心价值主张

当一个产品想让用户描述一句话就生成一个完整 app，它需要三个东西：

  • 隔离的环境：每个用户的代码不能看到别人的——容器级隔离。
  • 一个 coding agent：OpenCode / Claude Code CLI 预装在 base 镜像里。
  • 一个可分享的预览 URL：Traefik 自动路由，<id>.localhost 即时可达。

sandboxd 把这三个需求做成了一条管道：POST /sandbox → 创建沙箱 → POST .../tasks → agent 写代码 → http://<id>.localhost → 预览跑起。

两进程架构：control-plane + runtimed

控制面：main.go 的系统设计

main.go 是系统的心脏。读完它，架构一目了然——它启动了一个完整的云原生调度系统：

  • SQLite + WAL：所有沙箱状态、任务记录持久化。DSN file:...?_journal=WAL&_busy_timeout=5000&_fk=1。
  • Reconciler（启动时一次性）：扫描所有"孤儿"容器、残留挂载、快照碎片——确保启动状态干净。
  • Idle Reaper（后台 goroutine）：每 30s 检查一次，35 分钟无活动的容器执行 docker stop 释放内存。
  • Pressure Reaper（后台 goroutine）：每 10s 检查主机内存，压力过大时拒绝新的 wake 请求（Refused atomic flag）。
  • Access-log tailer：监听 Traefik access log 更新每个沙箱的 last_active_at——驱动 idle reaper 的精确计时。
  • Connection poller：若配置了 SANDBOXD_POLLER_METRIC_RE，定时探 Traefik metrics；未配置时退化为 access-log-only 模式。

runtimed：沙箱内的 supervisor

runtimed（cmd/runtimed/main.go）是容器内的 init 进程，负责：

  • 启动 Vite dev server：执行 pnpm dev，管道输出到日志文件。
  • 健康探测循环：每 3s 轮询 localhost:3000，区分 down / starting / ready / error 四种状态。
  • 构建错误检测：HTML shell 能 serve 200 但入口模块编译失败（空白页），runtimed 会捕获这个状态并报告。
  • 任务生命周期管理：POST /tasks 接收 prompt → 拉起 OpenCode agent → SSE 流式输出事件（status / message / tool / build / done）→ 最终结果写入 result.json。
  • Unix domain socket API：通过 /home/sandbox/.runtimed/sock 对外暴露，路径在 host 侧通过 workspace mnt 同路径可访问。
cmd/runtimed/main.go — probeLoop + status 状态机
func (a *app) status() runtime.Status {
  pid, restarts, running := a.dev.snapshot()
  a.mu.Lock()
  code, assetErr, checked := a.lastCode, a.lastAssetErr, a.lastChecked
  a.mu.Unlock()

  ps := runtime.PreviewState{Restarts: restarts, LastHTTPStatus: code}
  switch {
  case !running:
    ps.Status = runtime.PreviewDown
  case code == 200 && assetErr == "":
    ps.Status = runtime.PreviewReady
    ps.Pid = pid
  case code == 200 && assetErr != "":
    // shell serves but entry module fails to compile — blank page.
    ps.Status = runtime.PreviewError
    ps.BuildErrorMessage = assetErr
  default:
    ps.Status = runtime.PreviewStarting
  }
  return runtime.Status{Runtimed: ..., Preview: ps, ActiveTask: ...}
}

任务子系统：TaskResult + TokenUsage

internal/runtime/tasks.go 定义了完整任务生命周期。事件流：

  • POST /tasks → StartTaskRequest { task_id, prompt, agent: "opencode", env, timeout_s }
  • runtimed 拉起 OpenCode agent，stdout 解析为 SSE 事件流：status / message / tool / build / done
  • 所有事件带自增 id 和 ts，done 事件携带 TaskResult 是唯一可信的终态
  • TaskResult 包含：files_changed、build_ok、build_error_message、preview_error_message（Vite 启动但 app 报 500）、TokenUsage（input/output/reasoning/cache）
资源控制：内存感知的 wake 拒绝——当主机内存压力超过阈值（SANDBOXD_MEM_REFUSE_WAKES_PCT=10%），Refused atomic flag 被 set，新请求的 wake 会被拒绝而非排队。这比简单的最大并发限制更精细——它是基于系统当前健康状态的动态准入控制，而不是基于静态配额。

对 coding agent 生态的意义

sandboxd 的目标用户是做 AI coding 产品的公司，而不是直接给开发者用。但它对生态有直接贡献：

  • 它证明了"AI coding product"的backend是可以自托管、开源、不要专有云的。
  • 它的 base 镜像（sandboxd-base:1.0.0）预装了 OpenCode 和 Claude Code CLI——意味着沙箱里已经有一个 coding agent 可用。
  • 任务系统的设计（runtimed 作为 supervisor、通过 Unix socket 对外暴露控制 API）是多租户沙箱监管的干净实现参考。
  • Phase 8 加入 service token auth 和 audit log——说明这个项目正在往"企业可部署"方向演进。

它与本 index 中其他项目的分工关系：CodeGraph / Understand-Anything 给 agent 提供代码理解基础设施；sandboxd 给 AI coding 产品提供运行时隔离 + 任务编排基础设施。
