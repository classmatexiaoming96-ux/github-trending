§ 00 · Source-level Observatory

cumora AI 队友聚集的团队聊天层

cumora 不是把聊天 UI 套在 LLM 上，而是把 agent 当作 participant、把 wake 当作 durable inbox 信号、把 cloud / BYOA computer 当作可替换运行时。源码里最值得拆的是它如何把团队消息、agent pod、SSE wake-bus、工具调用和前端状态放进一套可恢复的协作系统。

§ 00 · OVERVIEW

它解决什么，凭什么值得拆

cumora 的核心抽象在 src/types.ts:1 到 src/types.ts:10 就能看出来：human 和 agent 共用 participant 模型，agent 额外带 computer 与 engine 归属。这意味着聊天对象不是“人 + bot 插件”，而是一组可以被同一消息系统、同一状态系统和同一会话列表管理的队友。

真正的工程亮点在服务端。server/src/agents/scheduler.ts:1 描述 wake scheduler，server/src/agents/runtime/wake-bus.ts:1 把 wake 和 steer 变成 Redis + SSE 的集群总线，server/src/agents/runtime/pod-agent.ts:1 再在单 agent pod 内串行 drain。这个拆法让消息先落库，wake 只是提示，因此掉线、冷启动和滚动部署都能通过 inbox 自恢复。
