读懂一个 agent 的内核

pi-agent-core 是一个带工具执行与事件流的有状态 agent。它把「调用 LLM → 执行工具 → 再调用 LLM」这个循环，抽象成一条可订阅、可干预、可持久化的事件流。

# npm install @earendil-works/pi-agent-core · Node ≥ 22.19

▸ 播放事件流 从心智模型开始
向下探索
01
心智模型 · the mental model

两种消息，一条管线

理解 pi-agent-core 的第一步：分清 AgentMessage 与 LLM Message。这是整个库设计的支点。

// 你的世界

AgentMessage

一个灵活的类型。既包含标准 LLM 消息（user / assistant / toolResult），也能通过声明合并加入 app 自定义消息（通知、状态、UI 卡片……）。这是 transcript 真正存的东西。

// 模型的世界

LLM Message

LLM 只认识三种角色：user、assistant、toolResult。任何自定义类型在发给模型前，都必须被过滤或转换掉。这就是 convertToLlm 存在的理由。

图 01 · 每次 LLM 调用前的转换管线
AgentMessage[]
原始 transcript
transformContext (可选)
AgentMessage[]
已裁剪 / 已注入
convertToLlm (必需)
Message[]
纯 LLM 消息
LLM
provider 请求
transformContext 工作在 AgentMessage 层：裁剪旧消息、做 context window 管理、从外部注入上下文。convertToLlm 负责最后一步「翻译」：过滤掉 UI-only 消息，把自定义类型映射成 LLM 能懂的格式。两者都约定不得抛错——失败要返回安全的回退值。

事件流 · the heartbeat

把一次 prompt() 拆给你看

这是理解 pi-agent-core 最关键的一节。每次运行都是一串有序事件——UI、日志、持久化全都挂在它上面。按下播放，看它逐帧发生。

agent 生命周期 turn 回合 message 消息 tool 工具
turn = 一回合

什么是 turn？

一个 turn = 一次 LLM 调用 + 它触发的所有工具执行。assistant 要了工具，循环就继续到下一个 turn，直到不再有工具调用。

message_update

流式增量

只有 assistant 消息会发 message_update，携带 assistantMessageEvent.delta。这是你做打字机效果的入口。

continue()

从现场续跑

不加新消息、直接从当前 context 继续——出错后重试的利器。要求最后一条是 user 或 toolResult。

04
工具 · tools

给 agent 装上手

工具就是 agent 能调用的函数。用 typebox 定义参数 schema，execute 里做事——成功返回 content，失败直接 throw。

read-file-tool.ts
import { Type } from "typebox";

const readFileTool: AgentTool = {
  name: "read_file",
  label: "Read File",        // 给 UI 显示
  description: "Read a file's contents",
  parameters: Type.Object({
    path: Type.String({ description: "File path" }),
  }),
  // 可选：强制整批顺序执行
  executionMode: "sequential",
  execute: async (toolCallId, params, signal, onUpdate) => {
    const content = await fs.readFile(params.path, "utf-8");
    onUpdate?.({ content: [{ type: "text", text: "Reading…" }], details: {} });
    return {
      content: [{ type: "text", text: content }],
      details: { path: params.path, size: content.length },
    };
  },
};

agent.state.tools = [readFileTool];

AgentTool 解剖

字段作用
name模型可见的工具名（唯一）
labelUI 展示用的人类可读名
parameterstypebox schema，自动校验入参
execute干活；带 signal 与流式 onUpdate
executionMode覆盖全局并发模式
错误处理：工具失败要 throw，不要把错误塞进 content。抛出的错误会被捕获，作为 isError: true 的 tool result 回给 LLM。
terminate：execute 或 afterToolCall 返回 terminate: true 可提示「这批工具跑完就停」。仅当本批每一个结果都 terminate 时才真正提前结束。
表 01 · 工具执行模式与拦截钩子
能力说明
parallel (默认)顺序 preflight，所有放行的工具并发执行；tool_execution_end 按完成顺序发，但持久化的 toolResult 消息仍按 assistant 源顺序。
sequential逐个执行，匹配历史行为。任一工具标了 executionMode:"sequential"，整批都退化为顺序。
beforeToolCall入参校验后、执行前触发。返回 { block: true } 可拦截，循环改发一条 error result。
afterToolCall执行完、事件发出前触发。可逐字段覆盖 content / details / isError / terminate。
05
转向与跟进 · steering & follow-up

在运行中插话

三种把消息「塞进」一次运行的方式，区别只在注入时机。这是做可打断、可排队 agent UI 的核心。

一次运行的时间线 →
↓
steer()
工具还在跑时打断；当前这批工具跑完后立刻注入
↑
nextTurn()
排到下一次「用户发起」的 turn，插在新 user 消息之前
↓
followUp()
等 agent 本该停下时再注入，让它多跑一轮
QueueMode

一次注入多少？

one-at-a-time（默认）每个 drain 点只注入最旧的一条；all 一次性全注入。steering 与 follow-up 各有独立模式。

清空队列

随时丢弃

clearSteeringQueue() · clearFollowUpQueue() · clearAllQueues() 丢掉还没注入的排队消息。注意 abort() 不会清掉 nextTurn 的消息。

检测顺序：一个 turn 结束后，先看 steering 队列（此时当前 assistant 的工具都已跑完）→ 注入并让 LLM 下一轮回应。只有当没有工具调用、也没有 steering 时，才检查 follow-up 队列。
06
编排层 · AgentHarness

循环之上的指挥台

当你需要会话持久化、resources（skills / prompt 模板）、hooks、压缩、分支导航时，就上 AgentHarness——它直接驱动低层循环，自己掌管整个运行生命周期。

状态被切成四块

理解 harness，先理解它如何隔离「现在的配置」与「这一回合正在用的快照」——这是它能在 turn 进行中安全改配置的根本。

① Harness config

app / 扩展随时设置的最新运行配置（model、thinking、tools、resources、stream options、system prompt）。Getter 返回它，不是正在跑的快照。

② Turn snapshot

一回合 LLM 调用用的具体状态，由 createTurnState() 生成。整回合逻辑都用同一份快照，provider 请求中途不会被改动。

③ Session

仅含已持久化的条目（append-only 树）。读 session 返回持久化状态，不含排队中的写入。

④ Pending writes

运行中产生的 session 写入先排队，在 save point、结算、失败清理时按确定顺序 flush，绝不丢失。

显式的运行阶段（phase）

结构性操作（prompt / skill / compact / navigateTree）要求 idle 才能开始，否则报 "busy"。

就绪idle
回合中turn
压缩中compaction
分支摘要branch_summary
重试retry
save point：一回合的 assistant 与其 tool result 完成后到达。此时 harness flush 待写入、生成新快照——让你在一次运行中途改的 model / thinking / tools / system prompt，从下一回合起生效，而绝不污染正在进行的 provider 请求。
env

ExecutionEnv

FileSystem + Shell 能力抽象。所有文件/进程操作返回 Result<T,E> 而非抛错——可移植到 Node 以外的运行时。

resources

Skills & 模板

通过 setResources() 注入 skills 与 prompt templates；快照在 turn 开始时拍下。app 自己负责从磁盘加载/热重载。

streamOptions

provider 请求

transport、timeout、retry、headers、metadata、cache——由 harness 托管并逐回合快照；凭证每次请求重新解析（支持过期 token 刷新）。

错误约定：低层能力用 Result<TValue, TError>（预期失败不抛）；高层编排 API（Session、AgentHarness）则直接 reject/throw，公开失败统一规整为 AgentHarnessError，原始错误保留在 cause。
07
扩展机制 · hooks

在每个关节切一刀

Hooks 是 harness 的扩展点。设计极简：事件自带它的结果类型（type-only phantom），没有结果映射表、没有 spec 表。harness 只做一件事——emit(event)。

observe()

纯观察

看到所有事件，只读，返回值被忽略。适合日志、指标、UI 同步。

on(type, handler)

参与语义

针对某个事件类型，参与它的结果归约——能改写、能拦截、能取消。结果类型决定 handler 能返回什么。

表 02 · 关键 hook 事件及其语义
事件语义返回
before_agent_start注入消息、链式改写 system promptmessages / systemPrompt
context顺序 transform 发给 LLM 的 messages{ messages }
before_provider_requestpatch stream options（headers 可删键）streamOptions 补丁
before_provider_payload顺序改写 provider payload{ payload }
tool_call执行前拦截，命中 block 立即退出{ block, reason }
tool_result顺序累积 patch，后者看得到前者改动content / details / isError
session_before_compact取消或自定义压缩{ cancel, compaction }
session_before_tree取消或自定义分支摘要{ cancel, summary, label }
message_end · model_update · …观察类：state / 生命周期变更—
归约策略各异：context / payload 是顺序 transform（每个 handler 看到上一个的输出）；tool_call 是命中即退；tool_result 是逐字段累积；session_before_* 是遇 cancel 即退、否则取最后一个结果。harness 不存 handler、不串联、不懂扩展策略——全在 hooks 实现里。
08
持久化 · sessions & compaction

一棵 append-only 的对话树

Session 是全部持久化的 agent 状态——不只是消息，还有 model 变更、thinking 变更、active tools、压缩、分支摘要、leaf 指针。它是一棵可分叉的树。

SessionTreeEntry 条目类型

type记录什么
message一条 AgentMessage
model_change切换模型
thinking_level_change切换思考档位
active_tools_change分支级的启用工具集
compaction压缩摘要 + 起保留点
branch_summary分支摘要
leaf当前树叶指针（持久化游标）
label · custom · …标签、自定义条目/消息

存储与压缩

storage

两种内置实现

jsonl（落盘、可重开恢复 leaf）与 memory（测试/临时）。都实现 SessionStorage / SessionRepo 接口——可换后端。

compaction

上下文压缩

shouldCompact() 判断是否该压；compact() 把旧消息总结成 summary，保留最近 keepRecentTokens、预留 reserveTokens。helper 全部导出，可单独用。

fork()

分叉

从任意 entry 处分叉出新分支——探索不同走向而不丢历史。

navigateTree()

树导航

切换 leaf；途中可自动生成 branch summary，把被离开的分支浓缩成一段摘要。

durable

半持久

session 是唯一持久日志，恢复时由 app 重建工具/模型/hooks 等运行时依赖，从持久边界重启而非 provider 流中点。

09
可观测性 · observability

不绑定任何 APM 的遥测

pi 只发出稳定、结构化的生命周期事件。要不要变成 OpenTelemetry span、Sentry、日志、指标——由外部监听器决定。核心包不依赖 OTel、Sentry 或 Node-only API。

trace.ts
// 把任意 context 关联到一次 turn
await runWithPiContext(
  { userId: "u123", orgId: "acme" },
  () => harness.prompt("fix this"),
);

// 订阅事件，自己决定送去哪
const off = subscribePiObservability((e) => {
  if (e.type === "end")
    console.log(e.name, e.durationMs, e.context);
});

一条 trace = 一棵因果树

每个操作发 start / end / error，带 traceId + spanId + parentSpanId。

  • pi.agent.prompt一次 prompt
  • pi.agent.turn一回合
  • pi.agent.tool_call一次工具
  • pi.ai.provider.request一次 LLM 请求
  • pi.session.append_entry一次落盘
默认安全：provider / model / token 数 / 时延等可安全上报；prompt、补全、工具入参/结果、文件内容、API key、headers 默认不上报。监听器是被动的，绝不影响 pi 执行。
10
快速开始 · quick start

三十秒跑起第一个 agent

最小可用例子：建 Agent、订阅流式 delta、发一句 prompt。这就是 README 的起手式。

quickstart.ts · Agent 类
import { Agent } from "@earendil-works/pi-agent-core";
import { getModel } from "@earendil-works/pi-ai";

const agent = new Agent({
  initialState: {
    systemPrompt: "You are a helpful assistant.",
    model: getModel("anthropic", "claude-sonnet-4-20250514"),
  },
});

// 订阅流式增量，做打字机效果
agent.subscribe((event) => {
  if (
    event.type === "message_update" &&
    event.assistantMessageEvent.type === "text_delta"
  ) {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});

await agent.prompt("Hello!");
low-level.ts · agentLoop()
import { agentLoop } from "@earendil-works/pi-agent-core";

const context: AgentContext = {
  systemPrompt: "You are helpful.",
  messages: [],
  tools: [],
};

const config: AgentLoopConfig = {
  model: getModel("openai", "gpt-4o"),
  convertToLlm: (msgs) =>
    msgs.filter((m) =>
      ["user", "assistant", "toolResult"].includes(m.role)),
};

const userMessage = { role: "user", content: "Hi", timestamp: Date.now() };

for await (const ev of agentLoop([userMessage], context, config)) {
  console.log(ev.type);
}
浏览器代理：需要经后端转发时，传 streamFn: streamProxy(...)，带上 authToken 与 proxyUrl 即可。
