本地优先

一句话定位：与其在每个聊天工具里各装一个 AI 助手，不如装一个跨所有平台的 OpenClaw——它用同一套记忆、同一套 agent 逻辑、同一个技能系统，在你已有的 20+ 消息渠道上提供一致的 AI 服务。Channel 插件即插即用，无需重新配置凭证。

TypeScript Monorepo 架构

项目是 pnpm monorepo，核心在 src/，包在 packages/，插件在 extensions/：

核心：ACP 协议 — Agent Communication Protocol

OpenClaw 的核心创新之一是 ACP（Agent Communication Protocol）——一套用于 agent 之间跨会话、跨实例通信的协议。它定义在 packages/gateway-protocol/ 里，处理 session 建立、消息路由、身份鉴权。一个 agent 可以派生出多个子 agent（src/agents/subagent-*），每个子 agent 有独立上下文，通过 ACP 消息和主 agent 协调工作。

多 Channel 适配：20+ 消息平台

每个消息平台是一个独立的 channel 插件（extensions/channels/），通过统一的 ChannelAdapter 接口接入 OpenClaw。核心在 src/channels/——入站消息统一成 InboundMessage，出站走 OutboundDispatcher，中间件负责 typing indicator、@mention 解析、消息去重等跨平台通用逻辑。

Subagent 系统与 MCP 集成

src/agents/ 实现了完整的 subagent 生命周期管理。主 agent 接受用户请求，通过 delegate_tool 派生出专门处理子任务的 subagent（每个有自己独立的工具集和上下文窗口）。subagent 通过 MCP（Model Context Protocol）接入外部工具，MCP server/client 支持完整。

安全设计：OpenClaw 默认启用 exec approval flow——所有 bash 工具调用需要用户显式批准。它还有 workspace path guards（防止 agent 访问敏感目录）、SSRF 保护（限制 HTTP 请求目的地）。这不是"默认开放然后靠用户纠错"的模式，而是默认锁定再按需放宽。

技能系统：59 个内置 Skill

Skills（skills/）是 OpenClaw 的"技能包"——以 markdown 文件定义，包含触发条件、步骤说明、工具列表。每个 skill 相当于一个可被 agent 自动触发的工作流模版。内置 59 个技能覆盖：coding-agent、github、canvas、discord、meme-maker、gh-issues、blogwatcher 等。

记忆插件：LanceDB / Wiki / Active Memory

OpenClaw 的记忆系统通过可插拔的记忆后端实现——memory-lancedb（向量嵌入检索）、memory-wiki（Markdown vault）、active-memory（会话间活跃上下文）。三种记忆层满足不同需求：语义搜索、结构化vault、即时会话状态。

对 coding agent 生态的意义

OpenClaw 的核心价值在于把"个人 AI"从"某个平台的 AI 工具"里解放出来。你的 AI 助手不需要存在于每个消息平台——它只需要存在一次，通过 channel 适配器连接到所有平台。这和"一个 agent，多个界面"的哲学与 coding agent 生态里"一个 agent，多个工具"的趋势完全一致。OpenClaw 的 subagent 系统和 ACP 协议，也为 multi-agent 协作提供了可复用的基础设施。
