Gateway 入口与主循环

源码：src/entry.ts（Node.js CLI 入口点）

整个系统从 entry.ts 的 runMainOrRootHelp() 开始：

// entry.ts:92-94
const entryFile = fileURLToPath(import.meta.url);
const installRoot = resolveEntryInstallRoot(entryFile);

// entry.ts:285
async function runMainOrRootHelp(argv: string[]): Promise {
    const { runCli } = await gatewayEntryStartupTrace.measure("cli", async () => {
        const parsed = parseCliProfileArgs(parsedContainer.argv);
        // ...profile env applied
        await runCli({ argv: parsed.argv });
    });
}

启动链路：entry.ts → resolveEntryInstallRoot() → respawnWithoutOpenClawCompileCacheIfNeeded()（编译缓存优化）→ parseCliProfileArgs()（加载 profile 环境变量）→ runCli()。Gateway 模式下实际跑的是 runCli 内部的 gateway 子命令。

编译缓存通过 entry.compile-cache.ts 管理，用 OPENCLAW_COMPILE_CACHE_DIR 环境变量定位缓存目录，重 spawn 时不带缓存标志以避免递归。

ACP 会话生成（acp-spawn.ts）

源码：src/agents/acp-spawn.ts（1708 行，核心文件）

ACP（Agent Client Protocol）的会话生成逻辑在此文件：

// acp-spawn.ts 导入链
import { getAcpSessionManager } from "../acp/control-plane/manager.js";
import {
  cleanupFailedAcpSpawn,
  type AcpSpawnRuntimeCloseHandle,
} from "../acp/control-plane/spawn.js";
import { isAcpEnabledByPolicy, resolveAcpAgentPolicyError } from "../acp/policy.js";
import { readAcpSessionMeta } from "../acp/runtime/session-meta.js";
import { resolveAcpSessionCwd, resolveAcpThreadSessionDetailLines }
  from "@openclaw/acp-core/runtime/session-identifiers";
import type { AcpRuntimeSessionMode } from "@openclaw/acp-core/runtime/types";

ACP Core 是一个独立 package（@openclaw/acp-core），包含 session 标识符解析、运行时类型定义（AcpRuntimeSessionMode）以及会话元数据读写（session-meta.js）。

会话生成流程：acp-spawn.ts 调用 getAcpSessionManager() 获取会话管理器 → 通过 spawn.js 中的 cleanupFailedAcpSpawn() 处理失败清理 → 由 policy.js 的 isAcpEnabledByPolicy() 做策略检查。父进程通过 acp-spawn-parent-stream.ts 做 stdout/parent-stream relay，把 ACP harness 的输出打回到 OpenClaw 的会话流中。

会话限制由 config/agent-limits.ts 控制：

// src/config/agent-limits.ts
DEFAULT_SUBAGENT_MAX_CHILDREN_PER_AGENT  // 每个 agent 最大子会话数
DEFAULT_SUBAGENT_MAX_SPAWN_DEPTH         // 最大 spawn 深度（防止嵌套失控）

AgentHarness 类型系统

源码：src/agents/harness/types.ts

OpenClaw 的外部编程接口通过 AgentHarness 接口抽象。这是 ACP harness（Claude Code / Codex 等）接入的核心协议：

// src/agents/harness/types.ts
export type AgentHarness = AgentHarnessRunCapability &
  AgentHarnessSideQuestionCapability &
  AgentHarnessClassificationCapability &
  AgentHarnessCompactionCapability &
  AgentHarnessSessionLifecycleCapability;

// 核心能力：
export type AgentHarnessRunCapability = {
  run(params: AgentHarnessAttemptParams): Promise<AgentHarnessAttemptResult>;
};

export type AgentHarnessSideQuestionCapability = {
  sideQuestion(params: AgentHarnessSideQuestionParams): Promise<AgentHarnessSideQuestionResult>;
};

export type AgentHarnessClassificationCapability = {
  classify?(input: unknown): Promise<AgentHarnessResultClassification>;
};

export type AgentHarnessCompactionCapability = {
  compact(params: AgentHarnessCompactParams): Promise<AgentHarnessCompactResult>;
};

export type AgentHarnessSessionLifecycleCapability = {
  reset?(params: AgentHarnessResetParams): Promise<void>;
};

关键点：run() 是必须方法，sideQuestion()（侧提问）、classify()（结果分类）、compact()（压缩会话）、reset() 都是可选扩展。OpenClaw 通过这个统一接口驱动 Claude Code、Cursor、Gemini CLI 等外部 harness。

插件系统公共接口（types.ts）

源码：src/plugins/types.ts（定义了 OpenClawPluginApi 所有公共注册方法）

插件通过 buildPluginApi()（api-builder.ts）构建的 API 对象注册自己的能力：

// api-builder.ts — BuildPluginApiParams 定义了所有可注册项
export type BuildPluginApiParams = {
  id: string;
  name: string;
  version?: string;
  source: string;
  registrationMode: OpenClawPluginApi["registrationMode"];
  config: OpenClawConfig;
  runtime: PluginRuntime;
  logger: PluginLogger;
  handlers?: Partial<Pick<OpenClawPluginApi,
    | "registerTool"          // 注册工具
    | "registerHook"          // 注册生命周期钩子
    | "registerHttpRoute"      // 注册 HTTP 路由
    | "registerChannel"       // 注册消息渠道
    | "registerGatewayMethod" // 注册 Gateway 方法
    | "registerCli"            // 注册 CLI 命令
    | "registerProvider"       // 注册 Provider（模型/语音/图像等）
    | "registerAgentHarness"  // 注册外部 Agent Harness（ACP）
    | "registerMcpServer"      // 注册 MCP 服务器
    | ...（共 30+ 项）
  >>;
};

每个注册方法对应一个具体的功能领域。例如 registerTool 让插件声明自己的工具，registerHook 注入生命周期回调（start/stop/enable/disable 等），registerAgentHarness 是 ACP 外部 harness 接入的正式入口。

源码：src/plugins/manifest.ts

插件的元数据描述文件是 openclaw.plugin.json（PLUGIN_MANIFEST_FILENAME 常量），解析在此文件：

// manifest.ts
export const PLUGIN_MANIFEST_FILENAME = "openclaw.plugin.json";
export const MAX_PLUGIN_MANIFEST_BYTES = 256 * 1024;

// manifest 解析缓存（SLRU，512 条目）
const pluginManifestLoadCache = new PluginLruCache<PluginManifestLoadCacheEntry>(
  MAX_PLUGIN_MANIFEST_LOAD_CACHE_ENTRIES,
);

// 缓存 key 生成
export function createPluginCacheKey(...): PluginCacheKey;

// 清除缓存（测试用）

Manifest 中包含插件版本、入口点、config schema、commands、providers、hooks 等元数据。解析后缓存 512 条，缓存条目包含 mtimeMs/ctimeMs 以跟踪文件变化。Secret provider exec 参数长度限制等安全策略也在此文件校验。

Plugin 运行时协调器（runtime.ts）

源码：src/plugins/runtime.ts

Plugin 运行时协调器管理全局 plugin registry 状态：

// runtime.ts — 全局 RegistryState 保存在 globalThis 上
const state: RegistryState = (() => {
  const globalState = globalThis as typeof globalThis & {
    [PLUGIN_REGISTRY_STATE]?: RegistryState;
  };
  let registryState = globalState[PLUGIN_REGISTRY_STATE];
  if (!registryState) {
    registryState = {
      activeRegistry: null,
      activeVersion: 0,
      httpRoute: { registry: null, pinned: false, version: 0 },
      channel: { registry: null, pinned: false, version: 0 },
      importedPluginIds: new Set<string>(),
      runtimeSubagentMode: "default",
    };
    globalState[PLUGIN_REGISTRY_STATE] = registryState;
  }
  return registryState;
})();

// 关键函数：
function asPluginRegistry(registry: RegistryState["activeRegistry"]): PluginRegistry | null;
async function cleanupPreviousPluginHostRegistry(params: {...}): Promise<void>;
function isRegistryLive(registry: PluginRegistry): boolean;
function isRegistryPinned(registry: PluginRegistry): boolean;

运行时状态设计：每个进程只有一个全局 registry（存在 globalThis 上），通过 activeRegistry / httpRoute / channel 三个视角观察同一份 registry。pinned 标记用于防止正在使用的 registry 被意外清理。

沙箱隔离模型（sandbox/runtime-status.ts）

源码：src/agents/sandbox/runtime-status.ts

沙箱模式由 sandbox.mode 配置控制：

// sandbox/runtime-status.ts
function shouldSandboxSession(
  cfg: SandboxConfig,
  sessionKey: string,
  mainSessionKey: string,
) {
  if (cfg.mode === "off") return false;   // 关闭沙箱
  if (cfg.mode === "all") return true;    // 所有 session 都沙箱
  // 默认：main session 不沙箱，其他沙箱
  return sessionKey.trim() !== mainSessionKey.trim();
}

export function resolveSandboxRuntimeStatus(params: {
  cfg?: OpenClawConfig;
  sessionKey?: string;
  agentId: string;
}): SandboxRuntimeStatus;

沙箱策略通过 tool-policy.ts 的 classifyToolAgainstSandboxToolPolicy() 对每个工具调用做检查。sandbox.mode 可选值："off"（不隔离）、"all"（全部隔离）、"non-main"（默认，只对非主 session 隔离）。实际 Docker/SSH 隔离在 sandbox/config.ts 中配置。
