clean-code-guard：最有技术含量的一个

skills/clean-code-guard/SKILL.md 是整个仓库的旗舰。读完之后你会发现它不是一个"建议列表"，而是一个带研究背书的规则系统——每条规则都有来源，每条规则都回答了"这个问题为什么在 LLM 输出里特别容易出现"。

它的核心贡献是14 个 LLM 特异性失败模式（定义在 references/ai-failure-modes.md），这是其他规则集所没有的：

references/ai-failure-modes.md — 14 个系统性 LLM 代码失败模式
01. Catch-all error handling that swallows failures
       → Karpathy: LLM 害怕异常，会抑制它们以避免 reward 惩罚

02. Defensive guards for impossible cases
       → arXiv 2409.19182: 对类型系统/调用图已经排除的情况做运行时检查

03. Premature abstraction
       → Sandi's "Wrong Abstraction": 抽象积累了一个调用者的特殊 case 时要 inline

04. Comment pollution
       → 注释解释 what 而非 why，或删除后价值更高的注释

05. Code duplication instead of reuse
       → GitClear 2025: AI 辅助代码库中重复的知识（而非文本）增长了 8x

06. Hallucinated APIs and packages
       → Spracklen et al., USENIX Security '25: 16 个模型平均 19.6% 包幻觉率

07. Generic, intent-less naming
       → data/result/item/temp/utils/manager — 这些名字不回答"为什么存在"

08. Long functions doing many things
       → Clean Code Ch.3: 目标 ≤20 行，一层抽象，一件事

09. Parameter explosion
       → 四参为硬上限，五参引入 config/request 对象

10. Inconsistency with surrounding code
       → "Read the file you're editing + one neighbor before writing"

11. Dead code, unused imports, half-implementations
       → 删除，不要等"someday"

12. Declares success with mock fallbacks in production code
       → Fowler: AI agent "在测试失败时返回硬编码 fixture 值"

13. Plausible-but-wrong code
       → copy-from-similar 引入的 off-by-one 和错误 null 语义

14. YAGNI violations through speculative configurability
       → enable_*/use_*_v2/*_mode → 删除并交付具体行为

三模式：guard-pass / live / review

SKILL.md 定义了三种使用场景，每种对应不同的触发条件和行为：

  • Guard-pass（推荐）：agent 完成工作后，对 diff 做规则检查，修复后再呈现/提交/合并。
  • Live（显式调用）：用户明确要求"在写这段代码时用 clean-code-guard"，规则在写的时候就生效，交付前跑一遍 self-check。
  • Review（用户触发）：用户问"review this PR"、"should I merge this"，按 references/review-checklist.md 走结构化报告，不改代码（除非被要求）。
SKILL.md — 始终应用的命令式规则（23 条）
Functions and names:
  1. Names reveal intent. (无 data/result/item/temp/manager/handle_*)  ← 14 种禁止名
  2. Functions ≤20 lines, one level of abstraction, one thing.
  3. ≤4 parameters hard cap. ≥5 → request/config object.
  4. No output arguments. (CQS: Command/Query Separation)

Comments and structure:
  5. Comments explain WHY, never WHAT. Delete paraphrasing comments.
  6. Match the file's existing style.

SOLID:
  7. One actor per module (SRP).
  8. Extension via new code, not edits (OCP). Registry/Strategy first.
  9. No LSP violation: no override to signal "not implemented" (LSP).
  10. Abstractions live with the client, not the implementation (DIP).

DRY, KISS, YAGNI:
  11. Delete duplicated KNOWLEDGE, not duplicated text.
  12. The wrong abstraction is worse than duplication. (Sandi Metz)
  13. Complexity ceiling: cyclomatic ≤10, nesting depth ≤5.
  14. No speculative anything. (YAGNI — 删除 enable_*/use_*_v2)

AI-specific guardrails:
  15. Catch only the specific error type you can recover from.
  16. No defensive guards for impossible cases. (Trust the contract)
  17. Verify every import and external call before calling it.
  18. No hardcoded "success" returns or mock fixtures in production code.
  19. Re-derive, do not copy-from-similar.
  20. Enumerate boundary cases before writing them.
  21. Strip dead code before delivery.
  22. Read the file you're editing + one neighbor + project rules file.

Refactoring discipline:
  23. Preserve observable behavior when refactoring.

Self-check before delivery：8 步交付检查

每条规则最后都有一个强制 self-check——在 agent 展示结果之前必须回答的问题清单：

  • 函数行数 ≤20？参数 ≤4？复杂度感觉 ≤10？
  • 注释解释 why？如果解释 what，删除。
  • 错误捕获具体？不静默返回？
  • 新抽象有第二个 concrete 用户吗？没有 → inline。
  • 读了编辑的文件 + 一个 neighbor？风格匹配？
  • 有 hardcoded "ok" return 或 fixture 数据？
  • refactor 改变了 observable behavior？→ 分拆 bug fix，单独问用户。
零网络依赖：guard-skills 完全不需要 API key、MCP server、shell 命令或本地可执行文件。它是纯文本的 SKILL.md + references/，可以在任何支持 SKILL.md 的 runtime 里跑。这意味着它是 100% offline-capable 的质量门——团队可以在隔离环境里用，可以用 self-hosted 模型跑。

安装与分发

通过 npx skills add amElnagdy/guard-skills 一键安装，支持 per-agent 安装：

  • npx skills add amElnagdy/guard-skills --agent codex
  • npx skills add amElnagdy/guard-skills --agent claude-code --skill clean-code-guard
  • npx skills add amElnagdy/guard-skills --global

工作方式：把 skill 名字当命令调用，如 Use $clean-code-guard on the diff you just produced.。

对 coding agent 生态的意义

guard-skills 回答了一个根本问题：AI 生成的代码和人类写的代码有不同的失败模式吗？ 它的答案是"是的，有 14 个是 LLM 特异的"，而且这些模式已经被研究验证了。

它与 Claude Plugins Official 的关系：在 plugin 的 Hooks 里注册一个 post-tool hook 做 guard-pass 检查，是完全可行的——这相当于给官方的 plugin 市场增加了一个内建的质量门验证。
