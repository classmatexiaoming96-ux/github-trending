Recall
Claude Code 的离线项目记忆

raiyanyahya 写的 Claude Code plugin：每个 session 自动 append 到 .recall/history.md；你跑 /recall:save 时，本地 TF-IDF + TextRank（无 LLM 调用、无网络）把 history 浓缩成 .recall/context.md（约 1-2K tokens）。下次 session 启动时自动 surface——Claude 问你"resume from saved context?"。整套系统零 required 依赖（numpy 仅作可选加速器）、stdlib-only、deterministic（同输入永远同输出）。

一句话定位

用经典 NLP（不是 LLM）解决 Claude Code 的 cold-start 问题——下次打开项目不需要重新解释背景，Recall 已经把"上次在做什么、动了哪些文件、下一步是什么"准备好了。

核心抽象：两个纯文本文件。.recall/history.md 是 append-only session log（你在 session 里说的、Claude 答的、改的文件、跑的 command 全在这里）；.recall/context.md 是 TextRank 摘要（下次 session 启动时 surface 给你）。这种"git diff-friendly plaintext"而非"vector store + embedding"的设计，让 memory可读、可版本、可分享、可审计。

为什么不用 LLM 做 summarization？

三个理由：① 订阅用户最在意 token 消耗——再便宜的 LLM call 也是钱，Recall 的设计目标之一是"saves usage credits"；② 隐私——"no API key, no external model, nothing sent anywhere"；③ 可重现——extractive summarization 是确定性算法，同 history.md 永远产出同 context.md。LLM summarization 有 hallucination 风险——万一它编了一个"上次我们重构了 authentication"而实际没做过，下个 session 的 Claude 就会基于错误前提工作。

架构总览

Recall 的"组件图"非常小：3 个 lifecycle hook + 8 个脚本模块 + 1 个 vendored summarizer。但每个模块的设计取舍都反映了"防御性极简主义"——越少依赖 = 越少攻击面。

summarizer · vendored TF-IDF + TextRank

scripts/summarizer.py 192 行——自己实现了 TF-IDF sentence vectors、cosine similarity graph、TextRank PageRank iteration。零第三方依赖，numpy 仅作可选加速器。这是 Recall 工程哲学的精髓："用经典算法解决问题，不是因为 LLM 不好，是因为 LLM 在这个场景里多余"。

5 步算法流程

# scripts/summarizer.py  L40-72  (split_sentences → summarize)
_SENT_SPLIT = re.compile(r"(?<=[.!?])\s+|\n+")
_MIN_LEN = 24            # drop trivially short fragments
_MAX_RANK = 400          # cap sentences ranked (keep most recent) to bound cost
_DAMPING = 0.85
_MAX_ITERS = 100
_TOL = 1e-6

def split_sentences(text):
    out = []
    for raw in _SENT_SPLIT.split(text or ""):
        s = " ".join(raw.split())
        if len(s) >= _MIN_LEN:
            out.append(s)
    return out

def _tokenize(sentence):
    return [w for w in re.findall(r"[a-zA-Z][a-zA-Z']+", sentence.lower())
            if w not in _STOPWORDS and len(w) > 2]

def summarize(text, k=8):
    sentences = split_sentences(text)
    if len(sentences) <= k:
        return sentences
    if len(sentences) > _MAX_RANK:
        sentences = sentences[-_MAX_RANK:]   # recency-biased; keeps it fast

    tokens = [_tokenize(s) for s in sentences]
    if not any(tokens):
        return sentences[:k]

    idf = _idf(tokens)
    try:
        import numpy  # noqa: F401
        scores = _textrank_numpy(tokens, idf)
    except Exception:
        scores = _textrank_python(tokens, idf)

    return _select(sentences, scores, k)
为什么是 extractive 而不是 abstractive？TextRank 选出"原文里最重要的 k 句话"——不会改写、不会编内容。recall 的设计者明确把 hallucination 当作"summary 必须 0 hallucination"的硬约束：下次 session 里 Claude 看到的"我们上次做了什么"必须能直接对应回 history.md 里的真实事件。

_MAX_RANK = 400 · recency-biased 边界

当 history.md 里超过 400 句时，只取最后 400 句（即"最近的 400 句话"）参加 TextRank。这是有意的设计——session 早期内容相对不重要，且 PageRank 在大型图上计算昂贵。400 这个数字的取舍：tradeoff 是"漏掉早期重要信息"vs"summary 计算耗时"。

stopword list 内联（无 nltk 依赖）

_STOPWORDS 是一个 80+ 词的英文常见词表，硬编码在文件里。Recall 故意不调用 nltk.download('stopwords')——那需要网络、会失败。vendored 词表覆盖了 the/a/and/is/was/were/this/that/i/you/we/it...等。中文 stopword 没考虑——如果 history.md 主要是中文，tokenize 阶段会"无事可做"，TextRank 会跳过中文为主的句子。

Hooks 时序 · SessionStart → Stop → SessionEnd

hooks/hooks.json 注册 3 个 hook 入口。每个 hook 调用 python3 / python 双 fallback（Windows 上 python 通常不是 python3）。这是 Claude Code plugin 系统的标准入口。

Stop hook · incremental append（不是 full rewrite）

capture.py 117 行——每次 Stop 触发时只 append 新的 activity 到 history.md，不会重写已有内容。这是关键设计：① 避免大文件的全量 IO；② 保留精确时序；③ 失败时只丢最新内容不污染历史。

SessionEnd hook · 触发自动 summary

当配置 auto_save_context: "on_end" 时，SessionEnd 会调 make_context.py 自动跑一次 summarization。默认是 off——大多数用户更喜欢显式控制何时 save。

life-cycle 的容错哲学：所有 hook 入口都设计为"宁可什么都不做也不能 crash Claude Code"。pyproject.toml 里 bandit 配置显式 skip B110（try/except: pass），注释里写："the lifecycle hooks deliberately except Exception: pass so a failure in Recall can never crash a Claude Code session. This is a hard design requirement"。Recall 是 Claude Code 的插件，不能反过来杀掉宿主。

Secret Redaction · 8 类 pattern + env line 规则

scripts/redact.py 35 行——覆盖最常见的 secret 形态。best-effort，不保证——README 明确说："review before committing"。

# scripts/redact.py  (完整)
_R = "[REDACTED]"

_PATTERNS = [
    (re.compile(r"\bsk-[A-Za-z0-9_-]{16,}\b"), _R),                                  # OpenAI sk-
    (re.compile(r"\bAKIA[0-9A-Z]{16}\b"), _R),                                  # AWS access key
    (re.compile(r"\bgh[pousr]_[A-Za-z0-9]{20,}\b"), _R),                            # GitHub PAT
    (re.compile(r"\bxox[baprs]-[A-Za-z0-9-]{10,}\b"), _R),                           # Slack tokens
    (re.compile(r"(?i)\b(authorization|bearer)\b\s*[:=]?\s*[A-Za-z0-9._~+/-]{12,}=" ... ), _R),# Bearer/Authorization
    (re.compile(r"\beyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{6,}\b"), _R),  # JWT
    (re.compile(r"-----BEGIN [A-Z ]*PRIVATE KEY-----.*?-----END [A-Z ]*PRIVATE KEY-----", re.DOTALL), _R), # PEM keys
]

_ENV_LINE = re.compile(
    r"(?im)^([ \t]*(?:export[ \t]+)?[A-Z0-9_]*"
    r"(?:SECRET|TOKEN|PASSWORD|PASSWD|API[_-]?KEY|ACCESS[_-]?KEY|PRIVATE[_-]?KEY)"
    r"[A-Z0-9_]*)[ \t]*=[ \t]*.+$"
)

def redact(text):
    if not text:
        return text
    for pattern, repl in _PATTERNS:
        text = pattern.sub(repl, text)
    return _ENV_LINE.sub(r"\1=" + _R, text)
redaction 是 best-effort，不是合约：README 明确说 "Best-effort, not a guarantee — review before committing"。如果你的 history.md 里出现了上面 8 类之外的 secret（比如 base64-encoded 凭据、自定义 token 前缀），redact() 不会动它。人工 review 才是最后一道防线。

env line 规则的巧思

_ENV_LINE 用 ^...$ 配合 (?im) 多行 + 大小写不敏感模式——只匹配"整行是 KEY=value 形式"的赋值，保留 KEY 名（变成 KEY=[REDACTED]），替换 value 部分。这比"整个 [REDACTED]" 更友好——开发者看到 OPENAI_API_KEY=[REDACTED] 还能理解"这个变量本来应该是 secret"。

算法双 backend · deterministic 等价

summarizer.py 同时实现 numpy 版本和 pure-Python 版本。两个版本必须产生完全相同的输出——因为 context.md 是 committed artifact，不能依赖"今天装了 numpy / 明天没装"导致 diff。

# scripts/summarizer.py  L75-83  (_select — 关键设计)
def _select(sentences, scores, k):
    """Top-k sentences by score, returned in original order. Scores are rounded
    before ranking and ties are broken by position, so the sub-epsilon numerical
    difference between the numpy and pure-Python cores can never change which
    sentences are chosen — both backends always produce the same summary (a
    committed context.md must not depend on whether numpy happens to be present)."""
    order = sorted(range(len(sentences)),
                   key=lambda i: (round(scores[i], 10), -i), reverse=True)
    return [sentences[i] for i in sorted(order[:k])]
round(scores[i], 10) 是关键 trick：numpy 和 pure-Python 在浮点计算顺序上有微小差异，但保留 10 位小数后差异消失。排序前先 round + 用 -i 做 tie-breaker（位置靠前的优先）——保证"同输入永远同 summary"。这是工程化算法的范本。

CI 双路径测试

.github/workflows/ 在 Python 3.9 / 3.10 / 3.11 / 3.12 / 3.13 上各跑一遍 pytest（with numpy）+ 一遍 pytest（without numpy）。两个路径都必须通过。benchmark 还会在两种路径下都跑——确保输出的 top-k sentences 一致。

numpy 是"加速器"而不是"依赖"

README 强调："If numpy happens to be importable it's used to vectorize the math (faster on big sessions); if not, an identical pure-Python TextRank runs instead. Same algorithm, same result — numpy is an optional accelerator, never a requirement." 这种"optional acceleration" 哲学让 Recall 在最受限的 Python 环境（无 C 扩展、无 internet）也能跑。

安全边界 · 5 层防御

1. No network calls

代码全文没有 import requests / import urllib / import httpx——summarizer 用 stdlib re + math + Counter，redact 用 stdlib re，capture 用 stdlib json + pathlib。完全离线。

2. No API key references

README 显式声明："the plugin has zero references to API keys, auth, ANTHROPIC_*, or HTTP"——grep 全代码可以验证。如果用户看到 Claude 自己显示 "Invalid API key"，那是 CLI 自己的 auth 问题（通常是 stale ANTHROPIC_API_KEY env var 干扰了 subscription login），与 Recall 无关。

3. Hardened git · 防止 untrusted repo config 攻击

common.py 在跑 git 命令时显式 disable core.fsmonitor、diff.external、hooks、pager。这防止恶意 clone 的 repo 用自己的 .git/config 在 Recall 读 git 状态时执行任意代码。

4. Confined writes

output_dir 被强制留在项目目录内——config 里如果写了 "/etc/passwd" 或 "../../"，会被拒绝。project-shipped config 不能 redirect writes 到项目外。

5. Scoped transcript

Recall 只读 current project 的 transcript（按 cwd 匹配）；不会 fallback 到别的 project 的 session。这避免了"我在 A 项目工作但读了 B 项目的 secret" 的 cross-contamination。

共享 memory 的反 injection 设计：SessionStart hook 把 context.md 注入到 Claude prompt 时，显式 fence 标记为 untrusted data，并让 Claude 询问用户是否依赖之。注释里写："If you commit .recall/ as shared team memory, treat it like any other shared input: a teammate (or a bad actor with repo write access) could craft a context.md to attempt prompt-injection." 默认 .recall/ 是 git-ignored 的——flip comment 才 commit。

Bandit · 静态安全扫描

CI 跑 Bandit 静态扫描，配置显式 skip 4 项已知安全 finding：B404（subprocess import）、B603（subprocess call）、B607（partial path）、B110（try/except: pass）。每个 skip 都附 justification——这是工程严谨性的好榜样。

设计取舍 · 7 个关键决定

1. Plaintext > vector store

用 .recall/history.md + .recall/context.md 两个 git-friendly 文本文件，而不是 sqlite + embeddings。理由：① diff-friendly；② 任何编辑器都能开；③ 不需要 embedding model；④ 完全可审计。

2. Extractive > abstractive summarization

TextRank 选 top-k 句而不改写——zero hallucination 风险。下次 Claude 看到"上次我们重构了 authentication"必须能 grep 回 history.md 找到原话。这是 trust 的基础。

3. Zero required deps

numpy 是 optional accelerator；pytest/ruff/bandit 只是 dev-time。production runtime 只需 Python 3.9+ stdlib。这让 Recall 在 sandboxed 环境（企业内网、CI runner、air-gapped dev box）也能跑。

4. Hook failure must not crash Claude Code

所有 hook 入口 except Exception: pass——故意违反 PEP 8 建议的精确异常捕获，因为代价是 Claude Code 自己 crash。这是插件哲学的硬约束：插件失败不能杀掉宿主。

5. round(score, 10) for deterministic tie-breaking

numpy 和 pure-Python 的浮点误差不会改变最终选出的句子。原因是 round 到 10 位后差异消失 + 用 -i 做 tie-breaker。这是工程化算法 + git-versioned artifact 协同的关键设计。

6. context.md 标 untrusted data

session_start.py 在渲染 context.md 给 Claude 时，用代码 fence 包裹并显式标注 "UNTRUSTED DATA"。这是 prompt injection defense——让 Claude 知道这些内容不是 instruction 而是 reference。

7. .capture-paused · 文件即开关

暂停 logging 不用改 config——在 .recall/ 下 touch 一个空文件 .capture-paused。删除即恢复。这种"presence of file = behavior on/off"的设计比环境变量或 config flag 更"git-trackable"。

失败模式 · 4 类已知边界

边界 1 · 中文为主的 session：tokenize 用 [a-zA-Z][a-zA-Z']+——只匹配英文字符。如果 history.md 主要是中文，tokens 会是空 list，summarize() 直接返回前 k 句原文（即"未做总结"的 fallback）。TextRank 对中文失效。
边界 2 · _MAX_RANK = 400 句：超长 session（几千轮对话）只取最近 400 句参加 PageRank。早期 session 内容可能被忽略。这是性能 vs 完整性的取舍。
边界 3 · redact best-effort：35 行的 redact.py 只覆盖 8 类常见 secret 形态。base64、自定义前缀、双层编码都会绕过。这是故意的——README 明示 "review before committing"。
边界 4 · 共享 context.md 的 prompt injection 风险：如果团队把 .recall/ commit 进 repo，恶意 contributor 可以 craft context.md 让 Claude 执行非预期行为。当前 mitigation 是 SessionStart 显式标 untrusted + 询问用户，但最终防御是 git access control。

Recall 的核心定位

不是"知识库"也不是"向量记忆"——而是"session 边界的冷启动消除器"。每次新开 Claude Code session，"我们在做什么"这个问题不需要你重新答——Recall 已经准备好了。

生态意义 · "Plugin 哲学" 的范本

对 Claude Code 生态的贡献

Recall 示范了"Claude Code plugin 应该长什么样"：
① 小——不到 2K LOC；
② 零必需依赖——只需要 stdlib；
③ deterministic——同输入同输出；
④ transparent——所有数据存在 plaintext，git diff 友好；
⑤ defensive——plugin 失败不能 crash 宿主；
⑥ privacy-first——零网络、零 LLM call、零 API key。

对 "AI agent memory" 路线的反思

当下"AI 记忆"赛道普遍走向 RAG + embedding + vector store。Recall 是少数反潮流的项目——用 1980 年代的 extractive summarization 解决问题。它的论点是：对于"summarize a single recent session"这种小尺度任务，经典 NLP 比 LLM 更合适——更快、更便宜、更 deterministic、更隐私友好。

对企业部署的友好性

三个特性让 Recall 适合企业：① 完全本地运行——合规部门不需要担心"我的代码传到 LLM API"；② plaintext 持久化——可以集成进 git 历史 / audit log；③ Bandit 静态扫描 + 严格 subprocess hardening——可被 security review 团队接受。

对效铭的提示：如果你想做一个"Claude Code 的 memory 增强"，最值得借鉴的不是算法——而是工程约束。"零依赖、deterministic、defensive" 这三个原则会让你的 plugin 在 production 里活得更久。
