§ 00 · OVERVIEW

它解决什么，凭什么值得拆

Claude Code 自带的 /goal 让模型自己盯目标，/loop 是间隔调度器——二者都没强迫你把"什么是完成" (authored 为 sources/ksimback-looper/schemas/loop.v1.schema.json:18)写成可检验的形式，也没让你请第二个模型看一眼。 Looper 正好卡在这个 gap 上：scripts/looper.py sources/ksimback-looper/scripts/looper.py:1 是一个 scaffolder，自身不会调用任何模型，只读 YAML、跑验证、写文件；真正跑 loop 的是被它 emit 出去的 templates/run-loop.py sources/ksimback-looper/templates/run-loop.py:1（外部 runner）或 RUN_IN_SESSION.md sources/ksimback-looper/SKILL.md sources/ksimback-looper/SKILL.md:1:79（当前 session prompt）。

从源码看，Looper 把"好 loop"拆成四件必需品：typed verification（programmatic / judge / human 三类）、可替换 council（reviewer 写笔记、judge 出 verdict）、三重终止守卫（max_iterations + gate.max_revisions + no_progress 签名）、跨 vendor 隐私边界（argv 不入 shell、转译前先 redact .env + secrets + .key）。任何一项缺失都会被 normalize_spec() sources/ksimback-looper/scripts/looper.py:254 当 LooperError sources/ksimback-looper/scripts/looper.py:60 抛出。

§ 01 · ARCHITECTURE

三段式拓扑：coach / spec / runner

Looper 把"好 loop" 当成一份配置而不是一段 runtime。三段分别对应三组文件，严格单向数据流：/looper 写 loop.yaml → scripts/looper.py compile 把它压成 loop.resolved.json → 外部用 templates/run-loop.py 跑，或回到当前 session 按 RUN_IN_SESSION.md 跑。两个 runner 共享同一份 resolved spec，因此设计期做的小改动可以无损地换 surface。

▸系统拓扑

[Coach · /looper] Claude Code skill ↓ loop.yaml (authoring) ↓ [Compile · scripts/looper.py] validate + normalize + argv-expand ↓ loop.resolved.json ↓ ┌───────────────┴───────────────┐ ↓ ↓ [Render] [External Runner] LOOP.md + RUN_IN_SESSION.md run-loop.py ↓ pasted into current session (stdlib only, reads JSON) Runner.run logic ↓ host → plan_gate → loop≤N state.json + run-log.md

▸validate_gate — gate 三段约束

每个 gate 必须是 {plan_gate, delivery_gate} 之一；verdict_policy 只允许 revise_until_clean 或 fixed_passes sources/ksimback-looper/scripts/looper.py:233 第二种策略；criteria 必须在 criteria_by_id 已注册的判定之列；members 必须在 council 里。revise_until_clean 还要 verdict_source 是 judge 角色或 human——这条强制区分了 reviewer 与 judge，否则下次循环会让 structured verdict 解析成 unparseable_judge_output。

§ 03 · KEY FLOW

关键流程：compile → resolve → run

最值得拆的是 spec 在三段时间里扮演的不同角色：authoring 时它是带注释的人类可读 YAML；compile 时它是 normalize_spec 的输入；run 时它是被 load_json() 解析的 dict-form。resolved 阶段是 boundary——一次折叠换来两套 runner（外部 Python / 当前 session prompt）共享同一份 truth。

▸no_progress_reached — 同 signature 致死

这是 Looper 的灵魂护栏。每次 gate 失败都把 sorted(failures) 做 signature，与 state.json 里的 previous signature 比对：相同就 +1，否则归零。如果连续达到 max_stalled_iterations sources/ksimback-looper/templates/run-loop.py:193 默认 2 (sources/ksimback-looper/scripts/looper.py:311)（默认 2），按 action 是 stop 还是 human_checkpoint 分叉 (sources/ksimback-looper/templates/run-loop.py:210-218 action ∈ {stop, human_checkpoint})——前者直接标 failed，后者给用户一次 "continue" 的机会。即使 action 是 stop，这里仍给出 blocking_issues 让人工翻看。

 188    def no_progress_reached(self, gate_name: str, failures: list[str]) -> bool:
 189        if not failures:
 190            self.save_state(no_progress={"count": 0, "signature": "", "gate": gate_name})
 191            return False
 192        config = self.spec.get("loop_control", {}).get("no_progress", {})
 193        threshold = int(config.get("max_stalled_iterations", 2))
 194        signature = "\n".join(sorted(failures))
 195        previous = self.state.get("no_progress", {})
 196        same_gate = previous.get("gate") == gate_name
 197        same_signature = previous.get("signature") == signature
 198        count = int(previous.get("count", 0)) + 1 if same_gate and same_signature else 1
 199        progress = {
 200            "gate": gate_name,
 201            "signature": signature,
 202            "count": count,
 203            "threshold": threshold,
 204            "updated_at": utc_now(),
 205        }
 206        self.save_state(no_progress=progress)
 207        if count < threshold:
 208            return False
 209        self.append_log("no_progress_detected", gate=gate_name, count=count, failures=failures)
 210        if config.get("action", "stop") == "human_checkpoint":
 211            answer = input("No-progress detected. Type 'continue' to allow one more revision: ").strip().lower()
 212            if answer == "continue":
 213                progress["count"] = 0
 214                self.save_state(no_progress=progress)
 215                self.append_log("no_progress_override", gate=gate_name)
 216                return False
 217        self.save_state(status="failed", failure="no_progress_detected", blocking_issues=failures)

 234    def redact_prompt_for_member(self, member_id: str, prompt: str) -> str:
 235        redactions = self.redactions_for(member_id)
 236        redacted = prompt
 237        for pattern in redactions:
 238            paths = list(self.base_dir.glob(pattern))
 239            if pattern.endswith("/**"):
 240                root = self.base_dir / pattern[:-3]
 241                if root.exists():
 242                    paths.extend(root.rglob("*"))
 243            for path in paths:
 244                if not path.is_file():
 245                    continue
 246                try:
 247                    secret_text = path.read_text(encoding="utf-8")
 248                except UnicodeDecodeError:
 249                    continue
 250                if not secret_text.strip() or len(secret_text) > 1_000_000:
 251                    continue
 252                marker = f"[redacted:{path.relative_to(self.base_dir).as_posix()}]"
 253                redacted = redacted.replace(secret_text, marker)
 254                for line in secret_text.splitlines():
 255                    stripped = line.strip()
 256                    if len(stripped) >= 8:
 257                        redacted = redacted.replace(stripped, marker)
 258        return redacted

▸已知边界 / 失败模式

  • judge 输出非 JSON 时降级为 REVISE — parse_judge_output sources/ksimback-looper/templates/run-loop.py:112 sources/ksimback-looper/templates/run-loop.py:112 L112-140 把 fence'd JSON 兜底切成原文本，都失败就 verdict=REVISE + blocking_issues=["Judge output was not parseable JSON."]，可能在边界场景死循环。
  • no_progress 仅比 failures 文本签名 — 同样一句 blocking 可能错位匹配；下一轮改写就归零。
  • secret redaction 走文件路径而非内容指纹 — 如果用户把 API_KEY 复制到 notes.md 不会被 redact，只能保证默认 glob。
  • wall_clock 用 time.monotonic() 在外部调用前检查 — host / judge 自身耗时不计入；budget 烧穿的具体耗时是 > wall_clock_min。
  • 外部 runner 必须拿到 PyYAML 才能 compile (sources/ksimback-looper/scripts/looper.py:66-70 在 load_yaml 里强制) — run-loop.py 是 stdlib only，但 compile 阶段仍要 PyYAML；运行期与设计期的依赖面不一致。
§ 05 · HIGHLIGHTS

技术亮点

1 · 把设计期和运行期拆开
Looper 自己不能调用 model (`sources/ksimback-looper/scripts/looper.py:2-6` docstring 自己说 "must not invoke model CLIs")，只产出文件。约束来自 looper-spec.md 的 "Looper's own process never invokes a model to do loop work"，是 hard rule 不是 vibe。
2 · 两套 runner 共享一份 resolved JSON
外部 Python runner (run-loop.py) 与当前 session 跑 RUN_IN_SESSION.md，从同一份 loop.resolved.json sources/ksimback-looper/scripts/looper.py:393 派生；改 YAML 一处，三处产物一致。
3 · typed verification 是 first-class
programmatic / judge / human 三类先入 schema 再入 normalize_spec，LooperError 防止用户写弱 rubric，doc 强制"至少一条不是 vibe-based"。
4 · reviewer ≠ judge 强制分离
reviewer.role 写笔记，judge.role 出 pass/revise + confidence (sources/ksimback-looper/templates/run-loop.py:131) + blocking_issues；validate_gate 强校验 verdict_source 必须是 judge 角色或 human。
5 · argv 数组而非 shell 字符串
每个 model invocation、每条 programmatic check 都用 list[str]；runner 用 subprocess.run(argv, ...) 直调，避免 shell injection 与 quoting 噩梦。
6 · 三重 termination guard
max_iterations 控制总轮；每个 gate 的 max_revisions 控制单条改稿上限；no_progress.signature 控制"同一失败堆积 X 次"；再加 budget USD/tokens/wall_clock 任一超限停。
§ 06 · RISKS & GAPS

技术亮点之外，别忽略这些

源码看下来有意或无意的取舍：

a · Looper 不假装是 orchestrator
作者在 looper-spec.md §2 把"Looper is a scaffolder and session handoff, not an orchestration framework" 作为 hard rule 写进设计文档，loop 真的需要长跑 / checkpointed restart / 并发调度，Looper 应该交出去。
b · MODEL_PROBES 写死 5 个 CLI
注册 model 的 escape hatch 是 register-model 子命令，新 vendor 进来要手动 --invoke 一遍，没有自动发现。Aider、Gemini CLI 等较新的非 Claude/Codex 工具不会出现。
c · no_progress = 文本签名
如果用户把同一 blocking issue 的措辞稍微修改（"Add a check" → "Please add a check"），signature 归零，no_progress 自动重启 (sources/ksimback-looper/templates/run-loop.py:198 同样 signature 才 +1) (sources/ksimback-looper/templates/run-loop.py:198 同一 gate 同样 signature 才 +1)——一种 false negative，可能被无限循环拖死。
d · redact 用 path glob 不做 content 探测
默认 .env + secrets/** + **/*.key (sources/ksimback-looper/scripts/looper.py:23 默认 glob)；如果 secret 被复制到 README、process-notes.md、an inline attachment，runner 不会拦。需要自己加 privacy.egress.redact。
e · budget USD/tokens 靠外部记账
looper-spec sources/ksimback-looper/looper-spec.md:23 把 USD / tokens 列为 operator-acknowledged 的预算，runner 自己不会去解析 CLI 输出统计实际 token 消耗。预算烧穿靠 wall_clock_min 做兜底，精度有限。
f · examples 只有一个
examples/ai-workflow-mapping/ 是唯一现实示例，host=codex exec、council judge=claude -p。其他组合（host=claude + judge=codex，host=llm + council=ollama）只能用户自己翻 SKILL.md 拼。
