▸Phase parser 与 first-failure 语义

解析逻辑在 scripts/verify.sh:60、scripts/verify.sh:63、scripts/verify.sh:67、scripts/verify.sh:71，执行逻辑在 scripts/verify.sh:84、scripts/verify.sh:87、scripts/verify.sh:88、scripts/verify.sh:94。这让每个项目自己定义 build/test/lint，但 runner 保证顺序、过滤和失败语义一致；它对应的规则依据是 core/20-principle-rules.md:35 到 core/20-principle-rules.md:37 的“先跑完整检查，再声明成功”。

58# Parse "Label :: command" lines (skip comments/blanks).
59LABELS=(); CMDS=()
60while IFS= read -r line; do
61  [ -z "${line//[[:space:]]/}" ] && continue
62  case "$line" in \#*) continue ;; esac
63  label="${line%%::*}"; cmd="${line#*::}"
64  label="$(echo "$label" | sed 's/[[:space:]]*$//;s/^[[:space:]]*//')"
65  cmd="$(echo "$cmd" | sed 's/^[[:space:]]*//')"
66  [ -z "$cmd" ] && continue
67  if [ -n "$ONLY" ] && [[ "$label" != *"$ONLY"* ]]; then continue; fi
68  LABELS+=("$label"); CMDS+=("$cmd")
69done < "$CONF"
70
71TOTAL=${#LABELS[@]}
72if [ "$TOTAL" -eq 0 ]; then
73  echo "${YELLOW}No matching phases.${RESET}"; exit 0
74fi
75
76if $LIST_ONLY; then
77  echo "${BOLD}Configured phases:${RESET}"
78  for i in "${!LABELS[@]}"; do printf '  %d. %s :: %s\n' "$((i+1))" "${LABELS[$i]}" "${CMDS[$i]}"; done
79  exit 0
80fi
81
82cd "$ROOT_DIR"
83START=$SECONDS
84for i in "${!LABELS[@]}"; do
85  echo; echo "${BOLD}${CYAN}[$((i+1))/$TOTAL] ${LABELS[$i]}${RESET}"
86  echo "  ${CMDS[$i]}"

88    echo; echo "${BOLD}${RED}verify.sh: phase '${LABELS[$i]}' failed.${RESET}"

91  fi
92done

21- **Within a layer (automated):** build, type-check, lint, unit/integration
22  tests pass. These prove the code is internally correct.
23- **Across layers (exercised):** the changed path was actually run — a real
24  invocation, a request through the running service, a click-through in the UI.

26  concrete value through every layer and every fan-out consumer it reaches
27  (each route, caller, callback, config variant) before claiming done (R3).
28
29"It compiles and the unit test passes" is within-a-layer evidence only. If a
30human could click a button and see it break, you haven't verified it.

33Before calling code done, tick each — "deferred: reason" is allowed, silence is not:

35- [ ] `<your build cmd>` succeeds (no warnings you introduced)
36- [ ] `<your typecheck cmd>` clean

§ 02 · KEY FLOW

关键流程

▸Phase 表如何变成证据

verify.conf → parse labels/commands → optional --only filter → execute phase → fail fast with direct command hint → summary only after all pass

从工程角度看，这个设计的好处是把“怎么证明”外置到配置，把“如何按顺序执行并报告”固定在脚本。core/20-principle-rules.md:13、core/20-principle-rules.md:17、core/20-principle-rules.md:35 给出证据标准，scripts/verify.sh:52、scripts/verify.sh:76、scripts/verify.sh:87、profiles/software-dev.md:46 使 agent 和人类使用同一入口。

§ 03 · EDGE CASES

边界 / 失败模式

  • scripts/verify.sh:87 使用 bash -c，配置文件必须被当作代码审查。
  • scripts/verify.sh:72 在没有匹配 phase 时返回 0，这对 `--only` 调试友好，但 CI 不应只跑窄 tag。
  • profiles/software-dev.md:40 要求真实路径运行，这部分无法完全由 verify.sh 自动推断。
