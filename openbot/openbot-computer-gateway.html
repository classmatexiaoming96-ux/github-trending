§ 02 · KEY FLOW

关键流程

▸统一动作路径

snapshot() → cache refs → govern(tool, subject) → resolve(ref) → build PolicyContext → evaluateActionPolicy() → write audit row → forward or ActionRefusedError

真正的动作方法只是 govern 的薄包装：server/src/computer/gateway.ts:565 包装 navigate，server/src/computer/gateway.ts:581 包装 click，server/src/computer/gateway.ts:596 包装 type，server/src/computer/gateway.ts:611 包装 key。这样所有 action 都走同一套审计和拒绝语义。

§ 03 · EDGE CASES

边界 / 失败模式

▸失败先被命名

  • 未知 ref 仍然进入 policy context，见 server/src/computer/gateway.ts:290，避免“没有 snapshot 所以不能拒绝”。
  • 允许后失败会补写 failure audit，见 server/src/computer/gateway.ts:387，避免只记录成功。
  • file path 和 command 也进入 context，见 server/src/computer/gateway.ts:352 和 server/src/computer/gateway.ts:353，否则 shell/workspace 无法治理。
